# 手机直播交互与美术方案 v1

日期：2026-10-11，C 方向细化更新。**已确定方向：**夜间通过手机观看 Z 的直播；可发弹幕、送礼、自愿参加随机连麦；Z 以近景 Live2D 式形象回应玩家及其他观众是目标，整体保持与像素世界一致的角色和美术锚点。全游戏取消精力，货币改称金币。用户本轮已选择 **C“月光全屏”横屏 PC 方向继续细化**，要求更简洁、更高品质的弹幕、礼物、字体与 UI，并支持中英国际化；这不是最终成品批准。**未确定：**最终视觉成品、SDK、动态资产规格、连麦概率和表现节奏。以下仍是设计提案，不代表真实 Live2D、AI 或观众系统已实现。

本轮入口：[C 方向本地交互设计预览 v2](../ui/live-phone-v2/index.html)；[旧三方案对比页](../ui/live-phone-v1/index.html)保留。当前规格以[总案](游戏设计总案-v2.md)、[核心系统](核心系统与数值草案-v2.md)、[D1—D3 切片](D1-D3-Demo开发与验收规格-v2.md)与[AI 协议](AI与状态规格-v2.md)共同维护。

v2 用干净的白发 Z 近景图（预览目录内 `art/z-moonlight-clean.png`）作视觉底层，文字、图标和控件由真实 HTML/CSS 叠加；中文/English 切换、礼物抽屉和随机连麦状态用于本地交互设计预览。背景中的 Z 不是已绑定的 Live2D 模型，预设回复、弹幕、观众数或连麦状态不是实际 AI 推理、联网观众或真实通话。完成预览不代表游戏规则与工程验收已通过。

## 1. 观看关系

玩家在岛上的住处等允许观看的地点打开手机，看到的是节目摄像机/虚拟摄影机提供的直播流。Z 的上半身、脸部、眼神和手势是画面主体，直播背景属于视频内容。常规观看不需要进入直播厅，也不能藉此获得后台权限。

白天仍为斜俯视像素 RPG。晚上切入手机观看视角，人物靠近镜头，保留银白长发、月牙发饰、象牙色开衫、冰蓝裙与深蓝腰带。美术一致性来自调色板、像素边缘、材质、光线与角色锚点；不把地图中的小精灵直接放大当直播立绘。

这里的“实时”是表演与反馈目标：眨眼、嘴型、视线、呼吸、头部转向、发丝、表情和小手势随互动变化，不意味着游戏内分钟跟随现实时间流逝。AI 生成、排队与玩家输入期间，游戏时间仍冻结。

## 2. 保留的三方案与当前 C 方向

| 方案 | 构图与美术 | 优点 | 需要验证 |
|---|---|---|---|
| A 暖金横屏 · 分栏直播 | 横置手机；左侧大画面，右侧独立聊天室；炭黑、暖铜金边框 | 接近现有 UI 材质，PC 字体与信息最易读，互动位置稳定 | 边框与侧栏不能压过 Z；小屏适配需折叠聊天室 |
| B 海盐竖屏 · 贴近手机 | 竖置手机；Z 占上方大部分画面，弹幕浮层与象牙白操作区；灰绿点缀 | 手机直播感最明确，脸部与表情近，适合后续竖屏适配 | 横屏 PC 会留白；不能为了填满屏幕裁掉上下内容 |
| C 月光全屏 · 角色优先 | 横置手机；直播铺满屏幕，左侧轻弹幕，底部窄操作栏；月蓝与银灰 | 表演和陪伴感强，界面干扰少 | 弹幕、礼物与字幕需要避让脸和手，背景变化时仍须可读 |

三图使用同一时刻的情境：玩家听潮提出“能把码头铃声做成开场节拍吗？”，Z 正在回应，另一个观众阿树送出星星瓶。金币 74 未因他人赠礼改变。在线 1,286、20:10 等为艺术示例；不是联网人数，也不是新增的固定计时节点。候选中的时钟在实现时读取规则时钟，分钟变化仍按节目窗口协议提交。

此前以 A 作为 PC 可读性对照；当前按用户选择，沿 **C 横屏、角色优先**继续。保留夜海与室内暖光、银白长发 Z 的气质，简化实体手机外框、重复入口、金边与逐条卡片；通过构图留白、清楚的文字层级和克制的控件提升品质。弹幕和礼物反馈避开脸与手，中文和英文独立排版而非整张图片等比缩放；完整文字由浏览器渲染，便于检查换行、对齐与交互状态。A/B/C 原图作为比较材料保留，C 的选择不等于批准旧 C 图中的全部控件或装饰。

## 3. 互动必须有可见反馈

| 玩家或观众事件 | 画面反馈 | 状态边界 |
|---|---|---|
| 发弹幕 | 内容进入滚动记录，玩家消息有轻微区分；Z 被选中的回应可引用原文/昵称，视线轻移后开口 | 发出、被挑中、得到双向回应分别成立；并非每条都念出，重复刷屏不累加识别 |
| 送礼 | 打开礼物抽屉，确认数量与金币价格/已持有数量；短动画与赠送记录，Z 可点头或微笑致谢 | 扣金币或已持有礼物，两者不重复扣；赠礼不购买私人同意、连麦名额或亲密结论 |
| 其他观众参与 | 有主题相关弹幕、礼物、被 Z 接住的提问，Z 的回应注明对象 | 观众不是玩家的代言人，其说法不能自动变成玩家经历或已知事实 |
| 随机连麦 | 公告开放→自愿报名→抽选→抽中通知→本人接受后接通；接通时显示昵称、发言状态与结束按钮 | 未报名、未抽中、拒绝接通不记为失约；不默认打开设备麦克风 |
| 连麦中 | Z 倾听、点头、接话；玩家发言与普通弹幕分区，结束后回到普通直播 | Demo 可先输入文字模拟公开连麦对话；真人麦克风/语音识别是否进入范围另定 |
| 长时间等待响应 | 保留已发送记录与可见等待状态，继续不依赖模型的观看操作；必要时转作者备用回应 | 不重复扣礼物，不假装 Z 已作出尚未生成的承诺 |

礼物先沿用已有小礼物金额（12 金币）与库存协议，手机内以礼物图标/赠送凭据表现；后续是否将所有实体礼物改成数字礼物需要单独梳理。候选星星瓶是其他观众的效果示例，不凭一张图增加玩家新商品、兑换币或付费商城。已有礼物发送只转出库存，直接购买发送才扣金币。关键礼物语义由物品定义决定，不能让手机图标等同于未经处理的远程实物搬运。

切片范围先收敛到“预购后在手机赠送”，不新增手机即时购礼；上表的即时购买为完整版候选。未来开启直购前重算白天 5 分钟购买和两路机会成本。三个候选共用该规则，选择某个视觉方案不会顺带批准新的经济系统。

## 4. 时间、金币与路径

**取消精力是系统规则改动，不是藏掉一个数值条。**没有精力上限、扣减、恢复、低精力门槛或替代的体力/专注预算。饭点与工作班次作为日程结构保留，吃饭不再承担恢复精力的功能。

- 普通行走、查看、打字、AI 等待：不扣游戏分钟。工作、调查、制作、训练等确认行动按既定分钟结算。
- 购买、赠礼、制作仍可能消耗金币/库存；“只耗时间”指取消精力，不使经济和材料免费。
- 原 20:00—22:00 和三个作者节目窗口可暂时保留于后台。单条弹幕、礼物、报名不单独扣 40 分钟；互动与节目推进使用不同的请求和收据。
- 玩家看到继续观看/离开等自然操作时，再预告推进到何时。每个节目窗口只推进一次；转发同条弹幕、AI 重试或再次进入画面不能重复计时。后台节目窗口不是三个发言额度。
- 不允许无限免费聊天替代白天准备与实际履约。识别贡献仍按真实事件去重，Z 的知识和关系门槛仍读取已完成事实；不把聊天限速变成新的行动点。
- 未抽中连麦时，有免费弹幕/投稿提交的有效回应机会，不能让随机抽选成为 D3 邀约的唯一通路。投稿提交免费不代表制作材料免费。低金币时合法工作不需先支付恢复成本；窗口已经错过仍会失去机会。

首版至少安排一个公开话题，可用现场观察事实通过弹幕接续，不要求礼物或中奖；演示“被回应”与“已获得邀约”仍相隔兴趣、身份关联和 D3 履约等条件。具体免费话题贡献与失败补救以切片回放验证，不能只证明按钮可点。

## 5. 动态美术的下一步

C 方向的本地交互设计预览用于细化观看、礼物抽屉、报名等待、抽中通知、连麦中、未抽中、点名回应等状态，以及中文/English 的排版差异。当前赠礼沿用“白天已购、夜间扣库存”的切片规则，不二次扣金币；随机连麦仍须先报名。旧三张概念图继续用于方向比较，图中输入框和表情本身不包含运行实现；HTML 预览的控件反馈也不等于游戏状态协议或动态角色已完成。

Z 的直播资产单独制作：后发、前发、脸、眼白/瞳孔/眼皮、眉、嘴、身体、衣袖、手与装饰分层；先验证清冷待机、倾听、思考、微笑、轻笑、致谢，以及说话嘴型与视线。建议先做一段短连续演出，检查像素边缘、网格变形、发丝遮挡和嘴型时序，再冻结资产尺寸。

Live2D 是表现目标，也可比较固定像素帧与分层骨骼。实际采用 Cubism 还是其他 Godot 动画方案，需看一致性、集成、授权和维护成本；不凭静态图宣称 SDK 已选或模型已绑定。若使用连续网格变形，要专门验证像素在小幅旋转和缩放下是否产生抖动/模糊。

模型输出可描述允许的情绪与动作意图，表现层从批准的动作库中选择；节目导演负责回应哪个 message_id、何时说、是否打断、动作优先级。语音/字幕/表情应共用同一条回应时序，不能各自独立随机播放。文字内容合理不等于已经完成实时演出。

## 6. 研究与验证

- 《动物迷城》K01 保留时间与日程的机会成本，K03 保留白天准备进入夜间，K04 保留关系依赖真实交流，K08 改为时间、金币、库存之间的取舍；按用户要求取消原本借鉴的精力预算。原作事实不改写。
- Neuro-sama 用作用户指定的 AI 主播体验参照。本轮访问了[官方频道入口](https://www.twitch.tv/vedal987)，网页没有返回可分析的直播画面，未据此宣称复刻了其内部系统、随机连麦或全部 UI。
- [Live2D 官方编辑器介绍](https://www.live2d.com/en/cubism/about/)、[表情教程](https://docs.live2d.com/en/cubism-editor-tutorials/expression/)、[表情运行协议](https://docs.live2d.com/en/cubism-sdk-manual/expression/)与[眨眼设置](https://docs.live2d.com/en/cubism-editor-manual/eye-blink-settings/)用于确认分层插画、参数、表情与嘴型属于独立制作/运行步骤，不能由一张 PNG 自动得到。

验证分层记录：旧 v1 三图和静态导览用于画面与方向比较；C 的 HTML 预览需另检查中英排版、控件状态与本地交互，不在本文预记通过结果；未来在引擎验收多条弹幕、同段多次不同赠礼、重复请求、未抽中连麦、节目时间推进、模型失败和读档恢复。两版设计预览均不向真实直播平台发送消息、赠礼或接通电话，也不提供实际 AI/Live2D 系统证据。
