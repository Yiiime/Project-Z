## 让参考过程可检查

对于实质玩法改动，保留一条简短但完整的链：

```text
本轮研究依据 → 采用或偏离的理由 → 本项目具体规则 → 实现位置 → 可观察的验证结果
```

例如，开发打工功能时，查 K02 与 K08，然后明确本项目是否让工作提供访问权限。如果当前目标只需要赚钱，也可以不采用访问权限，但要写清本轮取舍，而不是默认忽略研究。

记录到[机制采用记录](机制采用记录.md)。已有设计文档包含详细说明时，此处只链接，避免重复维护。

## 启动与迁移注意事项

根目录的 [AGENTS.md](../AGENTS.md) 是 Codex 项目指引入口；README 和研究文件由该入口明确要求按需读取。把链接写进指引并不意味着所有链接正文都会自动注入上下文。

按官方说明，Codex 在运行/会话开始时构建指引链；同目录的 `AGENTS.override.md` 优先于 `AGENTS.md`，更深层指引可覆盖较上层约定，整体有长度限制。因此指引保持简短，长资料保留在研究目录。新会话应从本项目或其子目录启动；如果新会话读到的规则不对，检查当前目录、覆盖文件和指引是否被截断。[OpenAI 官方说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

2026-10-10 已完成一次独立 Codex CLI 启动实测：在本项目根目录运行临时、只读会话（`codex exec --ephemeral --sandbox read-only`），要求其不调用工具、不读取文件，只根据启动指引回答研究对象、机制卡范围和交付要求；问题本身未给出游戏名、卡编号或文件名。该运行正确识别《动物迷城》、K01—K12，以及“研究依据→本项目规则→状态→实现位置→验证证据”的记录要求，正常结束。这证明本地 CLI 新运行加载了项目指引；不等同于桌面端每个未来会话或每次开发质量都已验证。

以后可用一句“先列出本任务相关的研究依据与机制卡，再继续开发”抽查实际采用情况，无需每次重新粘贴整套研究。参考是否充分仍须看具体决策、实现与验证证据，不能只凭启动时读到指引判断。

迁移到另一仓库或 worktree 时，必须将根指引、研究和关联设计文档一起带过去。2026-10-10 检查时，这些资料尚未纳入 Git 跟踪；本文不表示已经提交或推送。文件存在于当前工作区，不能据此保证另一个 checkout 或云端已拥有它们。
