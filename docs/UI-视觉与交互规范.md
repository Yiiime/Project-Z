## 2. 必须贯穿整套界面的视觉规则

### 2.1 场景先于界面

画面首先是一处能行走、观察和交谈的地方。环境提供路线与监视线索，人物行为表达关系变化，UI 解释玩家当前能做的事。

采用小角色、2.5D 横向分层的舞台式空间：近景遮挡物、中景可行走平台、次中景巡查或工作区域、远景海面与灯塔形成层次。横向路线可以包含楼梯、坡道与上下平台；画面表现不等于承诺全 3D 自由旋转镜头。

- 普通探索与交流中，人物全身高度建议约占画面高度的 12%—20%；关键交流可适度拉近，仍保留脚下平台和附近路线。
- 通过朝向、距离、停顿、递出物件和移动表达关系；不依赖常驻的大头像或半身立绘。
- 玩家、Z、配角沿用相同的比例、服装识别点和描绘方式，不因切换页面而变成另一套人物资产。
- 冷色远景与暖色近景拉开层次；关键可行走区域不能与前景剪影完全融为一体。
- 气泡随说话者定位，但文字始终保持正向、清晰。气泡尾端必须能识别指向的人物。
- 演出单、接线柜、维护台、门闩等重要物件需要能被再次认出；场景变暗时不能只靠记忆猜位置。

默认界面覆盖量以保持至少约 70% 的场景可观察为目标，不按每页硬算面积。调查记录、设置、复盘等专注阅读界面可以扩大；此时应明确已进入阅读状态。不能为满足覆盖比例而缩小中文。

### 2.2 色彩职责

以下色值为 UI 起始令牌，不是从示意图精确取样的最终材质参数。场景可围绕它们扩展，不把整张背景套成单一滤镜。

| 职责 | 建议色值 | 使用原则 |
|---|---|---|
| 深靛背景 | `#151C2B` | 夜色、气泡底色、必要的局部遮罩 |
| 灰紫层次 | `#4B465D` | 远景、雾、未选中轮廓；不承担正文阅读 |
| 暖琥珀光 | `#E8B16D` | 灯光、人物附近的温度、可观察的现场注意信号 |
| 珊瑚交互 | `#F17C68` | 当前聚焦选项、选中的谈话材料、明确的操作反馈 |
| 主文字 | `#EFE9DF` | 对话、关键事实、操作名称 |
| 次文字 | `#BFBCC6` | 来源、已读说明、非关键状态；同样保证可读性 |
| 沉静轮廓 | `#8D8496` | 气泡边线、输入线、未聚焦边界 |

珊瑚色表示“正在选择或操作”，不能同时普遍表示危险。已发生的风险用图形、文字和现场行为解释；例如巡查视线变化配合“有人正在核对你的证件”，而非把全屏涂红。

白天仍可使用灰蓝海面、灰紫阴影与暖色日光，不能为了统一而把所有时段都画成夜晚。直播的台前灯光可以更亮，但后台、私人交流和外部接收端仍属于同一个视觉体系。

### 2.3 字体与排版

- 设计基准为 1920×1080、16:9。所有承载游玩信息的中文界面字均不小于 24 px；正文与对话优先 28—32 px，页面标题 36—44 px。
- 24 px 是阅读下限，不是所有文字都应使用的默认字号。背景招牌上的无关装饰文字可以更小，但不能在那里藏必须辨认的线索。
- 采用一种清晰的中文黑体作为主体，使用常规与中等两档字重；不以英文装饰字、极细体或书法字建立关键层级。
- 中文正文行高为字号的约 1.45—1.6 倍，证据正文避免过长通栏。气泡一般为 1—3 行，每行约 12—18 个汉字；长解释分为可推进的短段。
- 标题、正文、来源和动作之间靠位置与间距分层，不把每句话包成独立卡片。
- 画布外缘预留约 48 px；相邻可点击内容留出明确间隙。气泡不得压住人物的头、可操作物、通路或当前正在观察的巡查。
- 低分辨率和较小窗口应重新排版、增大 UI 比例；不能整张等比缩小，把 24 px 中文压成 16 px。
- 主文字与其实际承载背景的对比以至少 4.5:1 为内部设计目标。半透明底板须在最亮与最杂的背景处复查；只计算文字与理想纯色底的对比不能视作通过。

### 2.4 界面材质与图标

使用薄轮廓、低明度半透明底、轻微不规则的气泡边缘。纹理只提供手工感，不能穿过字形或降低清晰度。

图标以简单线条和少量实心形状构成，文字仍承担主要含义。键位提示沿用同一套边框、字号和命名。笔记、手机、演出单可以有各自的物理材质，常驻 HUD 不因此变成剪贴簿。

不使用网站导航、功能卡片墙、仪表盘式数值矩阵、厚重毛玻璃大面板、巨大宣传标题、装饰性排行榜或与本局无关的收藏计数。

## 3. 固定布局与信息优先级

| 位置或层级 | 主要职责 | 不应放入的内容 |
|---|---|---|
| 左上角 | 日期、当前时段、地点，必要时显示本时段工作 | 全部支线、长期目标清单、每分钟变化的提醒 |
| 场景内 | 人物气泡、当前调查热点、可观察行为 | 全图透视标记、所有 NPC 的意图、隐藏监视结论 |
| 左下角 | 当前讨论的证据或正在使用的信号，短摘要即可 | 全背包、长篇材料正文、默认展开的所有记录 |
| 下方中央 | 自由输入；需要时提示当前指向的事实或计划 | 始终占据大面积的聊天历史 |
| 右下角 | 此刻有效的少量键位、返回当前层级 | 所有系统快捷键同时展示 |
| 临时阅读层 | 证据原文、记录、计划确认、复盘 | 与当前阅读任务无关的功能模块 |

同屏优先级为：当前必须处理的现场变化 → Z 正在说的话或玩家正在读的证据 → 当前动作 → 日期与一般提示。只允许一个主要交互焦点；切换焦点时收起不再需要的附加信息。

## 4. 信息来源与监视表达

### 4.1 严格区分四种知识

记录与证据界面统一使用以下文字标签，辅以不同小图标；不只靠颜色区分。

| 标签 | 示例 | 可展示到什么程度 |
|---|---|---|
| 我看见了 | 演出单写着第四声钟后灯塔熄灭 | 呈现材料内容与取得地点，不直接判定世界真相 |
| 某人声称 | 场务称停电只是节目安排 | 保留说话者与原话，不自动升级为事实 |
| 我的推测 | 灯塔事故可能有人提前安排 | 明确仍待验证，不能冒充任务答案 |
| Z 亲自核验 | Z 与玩家共同看到工作人员操作 | 只有实际发生的共同核验可使用；若仅有她的口头转述，应写“Z 说她已核对” |

玩家持有材料不等于 Z 已经知道；出示材料不等于她已经相信；她理解真相不等于愿意离开。界面不得用一个勾选动作跨过这三层区别。

### 4.2 不显示全知安全状态

允许提示亲眼所见、实际收到的通告或玩家查阅过的记录，例如“巡查向后台走去”“门禁要求重新核验证件”“连麦已被切断”。这些提示应有场景、字幕或终端记录作为来源。

禁止显示“当前安全”“无人监视”“公司没有怀疑”“安全时间还剩 40 秒”等没有来源的结论。巡查离开画面不证明摄像头停用，咖啡馆也不是永久安全区。

不显示好感度、觉醒百分比、人感值、信任进度条或全局警戒槽。关系变化通过 Z 说出的疑问、兑现的承诺和之后的主动行为表达。普通调查不显示倒计时；最终迁移站明确呈现的“目的地待复核”计时可以显示，因为它有可读取的设备来源。

## 5. 跨页面一致的交互规则

### 5.1 调查与表达

- 查看物件后先得到内容，再决定记录、出示或暂时收起；不能仅凭光标扫过就视作角色已阅读。
- 对话中可以指向一份材料或一项计划。选中状态使用珊瑚轮廓并显示短名称，让玩家知道当前话语的对象。
- 推荐表达是完整主线的可用入口。显示两条为常态，必要时最多三条；键位与点击结果一致，明示“选择即说出”。悬停只高亮，不发送。
- 自由输入框与推荐表达分开。输入框拥有焦点时 Enter 发送，Shift+Enter 换行；发送后只有一条玩家发言进入本轮，不因重复按键重复触发行动。
- 键盘选项快捷键在文本输入时停用，避免打字触发选项。不能让用于移动的按键同时编辑草稿。
- 草稿保留至发送或明确放弃；暂时查看证据、连接出错或退出输入焦点不会悄悄删除草稿。
- 自由输入聚焦时，Esc 先退出输入焦点；再次返回的目标在提示中明确，例如“结束交谈”或“返回探索”。

### 5.2 Z 的响应、拒绝与系统故障

Z 的气泡表达她接受了什么、仍担心什么、愿意做哪一步。拒绝通过具体理由说明，不弹出“亲密度不足”或“说服失败 -10”等系统判词。

如果请求超出作者支持的行动，回答要与世界规则一致，例如“我打不开这扇门，我们得找有权限的人”。不能先承诺一项不存在的能力，再在执行时突然失败。

等待回应时仅保留轻量的“等待 Z 回应…”和状态动效；不要显示模型、令牌、提示词或推理过程。等待期间不扣除时段、不推进会导致失败的现场时间。

连接或服务故障与角色拒绝必须分开：前者使用简短的系统提示“回应未能完成，你的话已保留”，提供重试；后者仍在角色交流中呈现理由。重试不得重复扣除活动时间或重复执行已确认的行动。

### 5.3 活动耗时与实时模式

普通移动、阅读、查看记录和打听不推进时段。正式工作、深入调查、正式约谈在提交前明示其时段成本及将错过的机会，优先写具体后果，例如“联调将结束休息时段，你会错过 Z 在咖啡馆的停留”。

进入关键潜行前显示简短确认：已保存、现场将按实时变化、当前约定的信号。长计划与长解释在此之前完成；实时阶段以短指令和已约定信号为主。

打开暂停、查看必要说明或等待系统回应时，不能让玩家在后台悄悄损失逃离窗口。后续实现必须说明并验证暂停范围，静态图不能代替这一验证。

### 5.4 操作反馈与运动

反馈顺序为输入被接受 → 人物或设备发生变化 → 记录必要结果。每一步只出现所需提示，不为同一事件同时弹气泡、横幅、角标和音效文字。

选择焦点有清楚轮廓，按下有短暂回应；非即时完成的动作要能辨认进行中与已完成。不可用操作写出玩家能够知道的原因，不能只降低透明度。

动画服务定位：气泡出现、人物转头、递出物件、设备状态变化。避免不断漂浮的控件、长时间全屏转场、依赖闪烁提示风险。后续动效应提供减少动态效果的选项。

## 6. 全套界面的分工

| 界面或状态 | 必须回答的问题 | 视觉与交互约束 |
|---|---|---|
| 标题、继续与存档 | 我可以开始、继续或回到哪里？ | 沿用小岛气氛；少量文本选项；存档只显示已知进度，不预告后续真相 |
| 开场与外部接收端 | 我是谁，当前缺少什么？ | 说明场务身份、七天中的当前日期；接收端就绪与尚未获得 Z 状态／授权分开，不显示虚假的完成比例 |
| 白天自由探索 | 我能去哪、当前有什么可观察机会？ | 低覆盖 HUD、可行走路线、有限热点；任务文字不替玩家标出隐藏最佳路线 |
| 工作与时段取舍 | 此动作会占用什么机会？ | 成本与具体错过的机会在确认前显示；取消不产生消耗 |
| 物件与证据查看 | 材料写了什么、来自哪里？ | 原文可读，记录与推断分离；完整演出单按需展开，不永久占据三分之一画面 |
| 与 Z 私下交流 | 我们在谈什么，她如何回应？ | 指向材料、清楚气泡、少量推荐表达与自由输入；人物及附近巡查仍可观察 |
| 调查记录与共同约定 | 我知道什么，Z 实际知道什么？ | 用来源和经历分组；条目可回看；禁止把未发生的核验标成完成 |
| 夜间直播 | 当前是公开说话还是私下交流？ | 清楚标示弹幕／连麦渠道与窗口；少量背景弹幕，不用滚屏盖住 Z 或行动线索；不自动翻译暗语的真实意图 |
| 日终与次日变化 | 我的行动改变了什么？ | 以短场景、Z 留话、门禁或人物安排变化呈现一到两项结果，避免统计结算板 |
| 来源核验与感知自检 | 记录与 Z 的经历有什么对应？ | 保留维护终端的设备语言，但精简到本次核验所需字段；两秒通道自检不命名为意识测量 |
| 合作与路线确认 | 谁在何时做什么，失散后怎么办？ | Z 用自己的话复述；显示当前方案与仍未约定的问题，允许纠正；不自动替她同意 |
| 撤离准备与模式切换 | 是否具备已知条件，下一步是否进入实时？ | 分列已核实、尚待确认和未准备，不使用单一“准备度”；明确存档与返回准备入口 |
| 实时潜行 | 谁正在看、我和 Z 当前各在哪里？ | 依可见视线、灯光、人物动作与信号判断；少量上下文操作，短指令优先，不开长聊天面板 |
| 迁移站与传输 | 哪一步在运行，什么会打断它？ | 可显示真实设备进度与目的地待复核计时；两种隔离风险区分；Z 暂停后不再出现主动聊天与移动 |
| 失败与局部重试 | 发生了什么，我应重试执行还是回到准备？ | 已知原因、关键现场事实、重试位置；不公布隐藏解法，不把所有失败归结为 Z 不信任 |
| 外部恢复与结束 | 迁移实际完成到哪一步，Z 怎样回应？ | 展示接收端恢复与源端本次运行退出；用本局共同经历回应，不宣称证明数字意识哲学连续性 |
| 设置与阅读辅助 | 我能否调到舒适可用？ | 字号、音量、字幕、输入与减少动态效果保持清楚；PC 是本轮基准，iOS 布局另行验证 |

部分项目可以是同一个界面的不同状态，无需机械拆成十七个独立页面。整套静态示意优先覆盖核心因果与状态变化，不为了凑页面重复摆放同一张场景。

## 7. 失败信息必须区分的层次

| 失败或受阻类型 | 应呈现的可知原因 | 可提供的返回方向 |
|---|---|---|
| 材料不足 | Z 指出尚未证明的具体部分 | 查看现有材料，继续调查或更换当前主张 |
| 共同理解未建立 | 她只知道字面含义，未参与此前约定 | 返回交流确认，不能靠重复发送暗语默认成功 |
| 计划有歧义 | 行动位置、时机或等待规则尚未说清 | 在进入实时阶段前补齐并让 Z 复述 |
| 权限不匹配 | 门禁拒绝、登记窗口已锁定等实际反馈 | 返回准备、改约联调或使用已发现的另一条路线 |
| 被现场看见 | 可见巡查、拦截动作或确实收到的核查通告 | 重试执行或回到准备，不凭空报告其他区域的目击者 |
| 远程隔离 | 维护终端显示复核触发隔离 | 区分与现场闯入的失败来源，回到撤离或准备存档 |
| AI／连接故障 | 系统回应未完成，与角色态度无关 | 保留输入与已完成行动，安全重试，不写入叙事惩罚 |

复盘只总结玩家或现场能知道的事实。可解释性并不等于显示全部后台状态，也不等于用“标准答案”奖励某一句措辞。

## 8. 全套静态示意 QA 清单

以下为本轮审查项目。通过静态检查只表示图面足够可信，不能写作交互或玩法验收通过。

### A. 方向与跨页一致性

- [ ] 仍是小角色、横向分层、可辨路线的 2.5D 空间，没有悄悄变成第一人称大头像聊天。
- [ ] 人物比例、服装、色彩职责、气泡边缘和图标语言跨页一致。
- [ ] 白天、直播、后台和外部恢复有情境差别，又能辨认是同一作品。
- [ ] 大多数游玩画面保留环境观察空间，不依赖网站式面板证明功能完整。

### B. 中文与阅读

- [ ] 所有关键中文逐字核对，没有重复字、漏字、乱码或似字非字；文字意思与玩法一致。
- [ ] 主文案、证据与控件按 1920×1080 基准满足字号下限；缩略图不能充当原尺寸阅读验证。
- [ ] 行长、换行、标点与气泡边距合理，没有文字碰框或尾部被截断。
- [ ] 最亮、最暗和纹理最复杂位置均可读；小输入提示与返回提示也经过检查。
- [ ] 重要线索放在可阅读的 UI 中，场景小道具上的微型字不承担唯一信息来源。

### C. 布局与操作暗示

- [ ] 一眼能辨认当前地点、正在做的事与下一项操作。
- [ ] 当前主要焦点只有一个，气泡不挡住人物、路线、热点或关键巡查。
- [ ] 推荐表达、输入草稿、发送按钮与已说出的台词区分清楚。
- [ ] 珊瑚焦点不会被误读成危险；次要选项不会因为过暗被误读成禁用。
- [ ] 键位提示只包含当前有效的操作；返回目标与当前层级一致。

### D. 知识与监视逻辑

- [ ] 玩家观察、他人说法、玩家推测、Z 核验没有混为同一事实。
- [ ] 未出示、未约定或未共同经历的信息没有提前写入 Z 的认识。
- [ ] 没有好感、觉醒、信任或全局警戒进度条。
- [ ] 没有全知安全结论、隐藏监视倒计时或透视式路线答案。
- [ ] 监视与门禁提示可以指出具体来源；巡查离开不被解释成整个区域安全。

### E. 核心循环与关键状态

- [ ] 至少一组页面看得出“调查 → 交流 → Z 的行动 → 新机会”。
- [ ] 直播明确属于公开渠道，暗语必须对应本局既有约定。
- [ ] 时段消耗、进入实时、等待回应三个状态在画面说明中没有混淆。
- [ ] 路线确认包含双方职责及等待／备用约定，不能只有“开始逃离”。
- [ ] 传输中 Z 暂停的状态与她的画面行为一致；不会一边转移一边继续说话。
- [ ] 成功没有仅靠文件或头像宣告，失败能够看出具体归因及重试入口。

### F. 状态覆盖与异常处理

- [ ] 至少说明未选择、聚焦、已发送、等待、回应、拒绝、系统错误的视觉区别。
- [ ] 必要操作存在不可用原因、进行中与完成的表达；没有无说明的灰按钮。
- [ ] 失败提供执行重试与准备回退的适当入口，不把所有问题都导向重开整局。
- [ ] 存档回滚不被画成 Z 在新周目记得旧周目的证据。

## 9. 后续实现必须单独验证的项目

静态图不验证以下内容，后续交互原型或游戏实现需另外验收：

1. 键盘、鼠标焦点与中文输入法；输入时快捷键不会误触，推荐表达和自由输入均能完成主线。
2. 实际字体渲染、不同分辨率与 UI 缩放、气泡避让、长中文与多人同时说话时的布局。
3. 点击范围、焦点顺序、可用与禁用状态、暂停与 Esc 的层级；草稿与上下文能否被保留。
4. 光照与镜头变化后的实际对比度；音效与颜色之外是否仍有可感知的反馈。
5. 自由表达的理解一致性、拒绝可解释性、约定记忆、Z 行动与台词是否相符。
6. 回应延迟、断线、重试和回滚不会扣除额外时间、重复行为或污染下一周目。
7. 普通活动的时段成本、实时开始提示、暂停范围、待复核计时、现场隔离与远程隔离是否遵守同一套规则。
8. 撤离成功是否完整经过源端迁移、接收端核验、外部恢复及源端本次运行退出。
9. 试玩者能否解释一次选择的影响和一次失败的原因，整套阅读与操作是否支持约 30 分钟的内容目标。

如后续考虑 iOS，需要单独设计触控目标、软键盘占屏、输入负担与横屏可读性；PC 示意通过不能据此声称已经支持 iOS。

## 10. 本轮交付的边界

全套静态示意用于判断美术一致性、页面层级、主要操作与状态覆盖。它不等于生产资产、角色动画、可运行 UI、AI 接入、联网服务、潜行规则、迁移系统或经过测试的游戏。

生成图中的文字需逐字复核；选定的画面结构最终应由真实文字与组件重新实现。页面间有因果关系不代表已具有可点击跳转，画上了进度和计时也不代表数值经过调优。

后续评审要分别记录：视觉已选定、页面已覆盖、交互原型已验证、游戏逻辑已验证、玩家试玩已验证。任何一层通过都不能替代其他层。
