# NPC本地修复与交互实验室

本次只修改本地代码，没有提交、推送或发布。独立网页沿用游戏的Catalog、Policy、Engine、MemoryBank，不需要打开Unity。日期逻辑、物理任务执行器、Unity视觉样式保持本轮开始时的状态。

## 打开与体验

- 当前地址：<http://127.0.0.1:4341/lab>，仅本机访问。
- 下次启动：双击`unity-sideview/启动角色交互实验室.command`。也可在`unity-sideview`运行`node Tools/start-character-lab.mjs --open`。
- 模型沿用本机已有配置，API Key不进入网页。页面右上角显示实际服务商和模型；没有配置或模型失败时明确报错，不用固定台词伪装模型。
- 选择任一角色直接对话。右侧可切换关系、记忆、本轮输入、模型输出、事件、任务、完整数据和人设，也可导出JSON。
- NPC交流：选择另一人和地点→布置测试环境→给一次交流机会→继续下一轮。双方是否交流、谈什么、何时结束由NPC决定；普通对话每次推进一轮，便于观察，仍沿用现有会话预算。玩家交谈占用中的角色不能参加NPC交流。
- 剧情消息：勾选实际知情角色后投递；未勾选者不会收到。引擎确认事实与普通观察信息分开。投递用于添加上下文，随后对话或NPC交流中作判断，不自动推进日期。
- 任务：NPC正式提出后可接受/拒绝，接受后可邀请NPC协作。协作仍由NPC判断。页面不提供“点一下就把收拾物品任务完成”的虚假执行回执。
- 新建测试会生成独立初印象与新的`lab_`世界；刷新继续当前测试。数据库为`unity-sideview/Tools/MemoryLab/.data/character-lab.sqlite`，与Unity存档分开。启动日志在同目录`character-lab.log`。

观察区是测试者的完整后台视角，不能据此认定所有NPC都知道同一件事。正式游戏仍只展示台词；Action/Info在后台保存。这里的“布置到地点”是明确的测试环境设置，不是NPC实际走路的证明。

## 本地修复内容

| 审计项 | 当前处理 | 仍需注意 |
| --- | --- | --- |
| C01 直播绑定 | 单独定义Unity增强的HostBinding.memoryUrl | 原始/live/open不必返回此字段 |
| C03 NPC关系 | 玩家对话、A2A、直播、本人感知均可影响本人对多个相关NPC的关系 | A→B与B→A独立；不能替缺席角色改变态度 |
| C04 自身目标 | 静态角色契约从运行Policy生成，排除向自己通信/改关系 | 仍需本轮合法动作与来源校验 |
| C05/C06 直播 | observe校验stage，propose校验完整三部分turnSchema；媒体桥使用同一结构 | 不将弹幕Action误用为岛上移动 |
| C07 说话者 | utterance仅接受玩家或现有人物 | 引擎消息走story_event/observation |
| R01 来源串线 | sourceEventId绑定刚sync的本轮输入；省略时只在同一会话内查找 | 旧会话经历可以召回，但不能冒充本轮输入 |
| R03 文档漏项 | 补记忆检索视图、协作请求/状态、步骤进度、回执/存档、诊断日志等类型 | 传输层仍有手工描述，不是所有HTTP入口都共用一个校验器 |
| 关系审计 | 最近12次变化保存理由、来源种类、前后值；原始提案/事件另外保留 | 传闻不自动成为事实，幅度不等于可靠性 |
| 存档保护 | 无效结构先拒绝，再进行恢复/取消操作 | 本轮不调整既有时间约束 |
| 后台日志混入剧情 | 反思诊断日志无角色听众，不进入对话历史和感知来源 | 完整数据仍保留这些日志 |
| 失败诊断 | 保留校验失败的模型输出和对应输入，页面显示错误 | 被拒绝的台词不展示为已说出口，Info不提交 |
| C02 / R02 / R05 | 日期约束、物理执行器、完整剧情编排暂缓 | 本测试页不证明已实现完整逃岛流程 |

已有故事关系作为基线；缺失的边以50/50和`neutral_unspecified`标记，不另造人物故事。每轮可以改变最多7个不同目标，数值在0—100，必须有非零变化及本轮实际可见来源，同一事件不重复计分。帮助Z的判断由人设、与Z/玩家/其他人的关系、记忆、动机、风险和能力共同决定，没有“好感达到某值必然服从”的开关。

## 接口与文件位置

```text
网页（/lab）
  → /api/lab/turn、encounter、continue等
  → Engine按角色组装上下文（本人记忆/关系/地图/实际来源）
  → 当前人设 + 动态契约 → 模型
  → Policy校验 → proposal
  → 网页呈现精确台词 → /api/lab/commit
  → 关系/记忆/任务状态落库；物理Action保留待执行
  → 下一轮读取更新后的本人状态
```
