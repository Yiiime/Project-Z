# 接口与扩展

世界事实由游戏确认。模型在已知事实和允许的动作范围内表达，回应通过校验后才播放。当前范围是一位角色 Z、一份当前存档和两段可替换事件。

| 顺序 | 输入 | 结果 |
| --- | --- | --- |
| 1. 玩家选择 | 事件 ID、选项 ID | 游戏记录带 ID、日期和地点的实际事件 |
| 2. 准备回应 | 存档 ID、状态版本、请求 ID、角色可知事件、允许动作 | 预写台词或在线模型请求 |
| 3. 接收回应 | 文字、情绪、动作、引用的事件 ID | 校验身份、版本、长度、动作及引用 |
| 4. 播放与保存 | 通过校验的回应 | 播放动作；接续机会消费一次，保存状态 |
| 5. 下次相遇 | 新日期与本局历史 | 生成对应经历的后续请求 |

对应协议定义在 [Models.cs](../Assets/ProjectZ/Core/Models.cs)。同一次请求只消费一次；推进日期、新游戏或取消当前请求后，不应用旧结果。在线服务会合并重复请求，并拒绝相同 ID 携带不同内容。结构校验可以约束引用和动作，不能证明每句话在语义上都正确，真实模型效果仍需试玩。

**新增事件**：复制 episodes.json 中的一项，换成唯一事件 ID；选项包含实际事实、当下台词、次日台词、情绪和动作。地点使用场景已注册的 locationId。两段样例与第三段配置扩展测试共用 GameSession；没有为每段事件单独写流程。内容版本变化时要编写存档迁移，当前版本会拒绝不匹配的旧存档。

**更换角色资产**：当前 ZPerformance 驱动占位角色的头、手臂和嘴部表情。正式角色应增加一个适配器，将同样的 look、nod、wave、pause 映射到 Animator、骨骼约束和面部表情；不要把游戏事实更新放进动画脚本。

**接回 Memory Lab**：保留工作区原有 demo，不复制它的实验数据库。下一步需要把 WorldEvent 投影为 Z 的观察，携带存档 ID、角色 ID、时间和来源；检索返回当前允许访问的记录与来源 ID。遗忘与恢复规则尚未接入本工程，不能把所有已保存事件都视为永久可访问记忆。当前在线请求仅使用游戏提供的共同经历，没有调用 Memory Lab。

**团队整合**：先对齐事件 ID、角色 ID、时间单位、存档版本、动作白名单与资产命名。当前协议使用 slotId 与 revision 隔离运行态；未来多角色需增加各自的感知投影和记忆权限。若团队采用其他引擎，可以复用内容、协议、服务与源资产；Unity 场景、材质、动画控制器需要另行适配。

**首轮实机验收**：两条不同选择分别真实游玩、退出并继续；次日表现对应本局经历。新游戏不继承过去。在线超时可以恢复；旧回应不抢回画面。新增一段事件沿用同一套机制。最后检查中文、交互距离、碰撞、嘴部表情和窗口尺寸。
