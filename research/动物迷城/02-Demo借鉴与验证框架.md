# 从《动物迷城》到未来 Demo：借鉴与验证框架

日期：2026-10-10。性质：基于研究提出的创作参考，**不是已经确认的新游戏方案，也不修改《来自月亮的 Z》现有玩法**。原作事实和来源见[玩法与机制研究](01-玩法与机制研究.md)及证据笔记。

**版本提示：**本文的规模与 Z 映射保留前期研究语境，不是当前 v2 的范围规格。项目后来形成了[21 天 v2 总案](../../docs/游戏设计总案-v2.md)；本轮[源码深读](05-社区源码深读与Z实现参考.md)已按 v2 校对适配。K01—K12 继续作为稳定研究编号使用。

## 1. 怎样理解“很大程度上复刻和借鉴”

建议把目标定为：在较小内容规模内，保留原作关键行动、约束、跨系统联系和结果反馈。是否成功，应观察玩家是否会自主形成计划，并利用制度、人物和环境来执行计划。

| 复现层 | 应保留什么 | 验证方式 |
|---|---|---|
| 行动逻辑 | 观察、交谈、交易、学习、准备、越界、补救 | 玩家能用这些动作完成一条完整路径 |
| 成本结构 | 每次重要行动占用时间、资源或关系机会 | 玩家会比较至少两种有差别的投入方案 |
| 因果联系 | 生活行动改变下一阶段可做的事 | 玩家能解释今天的准备为什么帮助了今晚 |
| 路径差异 | 同一目标有依赖条件不同的解法 | 第二次游玩会改变准备，而非只选另一段结尾 |
| 反馈方式 | 条件可理解，状态可追踪，失败有原因 | 不看攻略也能知道缺什么、还能做什么 |
| 表现载体 | 人物可识别、空间可记忆、日程可观察 | 玩家能把“某个人/某个地点”与具体机会联系起来 |

人物、台词、世界观、地图结构与美术素材适合重新创作。这样可以更自由地保留机制，且不会让新设定被原作剧情牵着走。本轮没有提取或复制原游戏素材。

**最大的范围误判：**把完整作品的双主角、几十个 NPC、大量技能和长线事件，直接当成首个 Demo 的目标。地图小并不代表内容成本小；人物、时间、任务和路径交叉越多，需要处理与验证的组合也越多。

## 2. 优先级：先保留哪些联系

| 优先级 | 机制 | 首个可玩切片应达到的程度 | 可以暂缓的部分 |
|---|---|---|---|
| P0 | 行动耗时与日程 | 少量明确窗口；行动前显示已知成本 | 逐分钟拟真生活与复杂季节系统 |
| P0 | 人物与权限 | 关系或承诺能打开一种真实行动 | 几十人完整身世与全关系图 |
| P0 | 工作与探索 | 工作既带来收入，也提供某种访问机会 | 多职业经济和每种工作的独立小游戏 |
| P0 | 环境持久变化 | 准备之后，门、设备、路径会保留变化 | 全地图物理破坏 |
| P0 | 多解 | 同一障碍至少两种代价不同的解决方法 | 每个问题都有所有流派解法 |
| P0 | 结果与补救 | 失败改变状态，并留下可理解的下一步 | 大量终局分支和惩罚动画 |
| P1 | 检定与准备 | 装备/能力/状态明显改变风险 | 全技能树、极端骰面和重掷流派 |
| P1 | 生存压力 | 少量资源形成取舍与恢复 | 饥饿、卫生、药物副作用等全部模拟 |
| P1 | 阵营承诺 | 一个可理解的收益与代价选择 | 三套完整帮派支线 |
| P1 | 证据与逃脱分离 | 完成调查和逃离不是同一变量 | 所有结局组合 |
| P2 | 战斗 | 仅当它是预期主要乐趣时纳入 | 独立完整战斗 RPG 的内容量 |
| P2 | 第二主角 / 新游戏+ | 第一条循环验证后再决定 | 在第一条路径未成立前生产第二套内容 |

P0 指验证这种体验最先需要的部分，不代表每个未来项目都必须采用。若目标明确是战斗导向，战斗应升至 P0，并主动减少社交和叙事范围。

## 3. 可复用的十二张机制卡

以下卡片均为机制抽象与创作建议，不是原作规则逐字规格。

### K01：行动推进时间

- **玩家决策：**现在执行，还是观察和准备之后再执行？
- **条件与变化：**重要行动明确消耗游戏时间，重新计算人物和设施可用性。
- **应保留反馈：**行动前的已知耗时、行动后的新时段与错过机会。
- **常见失败：**对话阅读速度被计入游戏惩罚；玩家打开菜单仍不断丢时间。
- **验证问题：**玩家是否敢停下来想，是否仍觉得选择有代价？

### K02：工作换取访问机会

- **玩家决策：**选择高工资岗位，还是能接近目标区域的岗位？
- **条件与变化：**资格、工作时段和活动范围共同控制进入；劳动还能带来钱或制度认可。
- **应保留反馈：**岗位允许进入哪里、能做什么、离岗意味着什么。
- **常见失败：**所有工作只换收入，探索与生活完全分离。
- **验证问题：**玩家是否会为接近线索而选择一次经济上并非最优的工作？

### K03：白天准备改变夜间

- **玩家决策：**今天把哪个小改动留到夜里利用？
- **条件与变化：**在合法窗口观察或操作设备，保存可供之后利用的环境状态。
- **应保留反馈：**准备是否完成、作用位置，以及晚间能否实际兑现。
- **常见失败：**夜间地图加载后重置；剧情演出声称准备成功，但玩法未变化。
- **验证问题：**玩家是否能把一次白天行动与夜间突破直接联系起来？

### K04：关系成为能力入口

- **玩家决策：**与谁建立关系，愿意为此投入什么？
- **条件与变化：**了解其需要，完成有理由的交换，得到技能、物品、介绍或协作。
- **应保留反馈：**人物明确记得原因，奖励在另一场景实际可用。
- **常见失败：**统一送礼刷条，所有人物只差奖励数值。
- **验证问题：**玩家记住的是“给了几件礼物”，还是“我帮了谁什么事、对方为什么愿意帮我”？

### K05：同一障碍有不同成本的解法

- **玩家决策：**支付关系成本、物品成本、时间成本，还是承担失败风险？
- **条件与变化：**每种解法用不同前置完成同一状态变更。
- **应保留反馈：**尚未满足的已知条件，以及方法造成的后续差异。
- **常见失败：**三个选项最终都检查同一个钥匙；某个解法在所有条件下都绝对最优。
- **验证问题：**不同玩家是否能形成不同而合理的方案？

### K06：能力来源嵌入世界

- **玩家决策：**先找出获得能力的方法，还是尝试现有能力能走的路径？
- **条件与变化：**书籍、人物、工作或经历提供可发现的能力，成长资源决定是否启用。
- **应保留反馈：**发现、解锁、装备/启用和效果分别清楚。
- **常见失败：**所有技能一开始摆在菜单里，人物与地点只剩装饰。
- **验证问题：**玩家能否从情境线索推断“谁或哪里可能教我这个”？

### K07：检定之前能改变条件

- **玩家决策：**赌一次，使用稀缺补救资源，或先强化准备？
- **条件与变化：**状态、工具、技能等影响可行性或成功机会。
- **应保留反馈：**概率/难度的变化来源、失败成本，以及重试是否仍要付费。
- **常见失败：**能力没有可感知作用；在长流程末尾用一次不可预见的随机失败抹掉全部投入。
- **验证问题：**玩家是否能说出自己为什么选择此时尝试？

### K08：资源之间有替代关系

- **玩家决策：**花时间挣钱再买补给，还是消耗现有补给争取窗口？
- **条件与变化：**至少两种资源能以不同效率相互转换，且存在恢复途径。
- **应保留反馈：**每条转换路径的直接成本和机会成本。
- **常见失败：**无限刷一种货币解决所有问题；或少一次补给就永久无解。
- **验证问题：**资源紧张时玩家是否仍在做决策，而不是只能等待或重开？

### K09：阵营选择有明确代价

- **玩家决策：**现在站队获得支持，还是保留接触其他势力的机会？
- **条件与变化：**加入或承诺增加一侧资源，同时收窄另一些机会。
- **应保留反馈：**主要收益与可预见的损失，在承诺前被理解。
- **常见失败：**无提示锁掉长线任务；所有阵营可以零成本同时满级。
- **验证问题：**选择前能否表达理由，选择后是否感到结果符合预期？

### K10：共享准备支持路线切换

- **玩家决策：**继续当前路线，还是利用已有成果转向另一个方案？
- **条件与变化：**基础区域/人物信息被多路线共享，最终门槛各异。
- **应保留反馈：**转向时哪些投入仍有效，哪些需要补做。
- **常见失败：**每换路线完全重来；或两条路线从头到尾只差名称。
- **验证问题：**发现新机会后，玩家是否会调整计划而不是惋惜沉没成本？

### K11：失败改变局面但保留行动空间

- **玩家决策：**接受损失继续，修复关系，改换方法，或重试？
- **条件与变化：**局部失败触发有针对性的状态变化；终局失败另有清晰条件。
- **应保留反馈：**发生了什么、什么仍有效、有哪些补救。
- **常见失败：**失败无后果；或一次小失误连锁摧毁所有路径。
- **验证问题：**玩家能否不求助攻略继续形成一个新计划？

### K12：逃离与解决故事问题分别结算

- **玩家决策：**已经能走，是否继续调查或帮助某人？
- **条件与变化：**出口、证据、合作和时机分别记录，结局读取其组合。
- **应保留反馈：**结尾反映玩家具体做过的事，不要求公开所有隐藏条件。
- **常见失败：**最后一个对话选项覆盖此前所有行为；离开地图自动等于所有真相已解决。
- **验证问题：**玩家能否把结局归因于过程中的选择？

## 4. 一个可控制的验证切片

以下仅是预算控制建议，尚未替用户决定故事、人物或美术：

| 维度 | 建议起点 | 这样限制的目的 |
|---|---|---|
| 主角 | 1 位 | 先证明一套行动循环 |
| 地点 | 4—6 个有明确联系的区域 | 足以表达合法/受限空间及绕行 |
| 人物 | 5—7 位承担不同资源或权限功能的人 | 足以产生依赖，仍能审查状态交叉 |
| 时间 | 2—3 个完整游戏日或等价时段组 | 展示准备、执行和次日后果 |
| 目标 | 1 个共同目标，2 条条件不同的路径 | 验证真多解与路线切换 |
| 资源 | 2—3 种核心资源起步 | 先证明取舍，再决定增加多少生活细节 |
| 失败 | 至少一次可恢复失败和一个可解释的终局 | 检查容错与结果反馈 |

如果预期只有约 30 分钟，以上数量仍可能过多。应以玩家能走完一条链、理解另一条链为准，不以把全部系统名塞进 Demo 为准。尚不能根据公开资料给出可信开发工期；团队规模、引擎基础、动画要求和文本工具都会改变成本。

## 5. 实现时的组织方式：这是建议，不是原作架构

后续已对社区代码继续追到实际调用处，详见[时间、任务、关系、道具深读与 Z 实现参考](05-社区源码深读与Z实现参考.md)。其中补充了请求排队与实际完成、关系观察与净变化、物品使用与库存结果、读档基线与新行动的区别；以下组织方式仍为创作建议。

建议先把世界事实与展示层分开，避免把关键状态藏在某段对白是否播放过里面。

| 状态对象 | 应独立记录的内容 | 应避免的混淆 |
|---|---|---|
| 时钟 | 天数、时段、局部窗口 | 菜单阅读耗时与游戏行动耗时混在一起 |
| 人物 | 当前安排、关系、已知事实、承诺 | 好感达到值就默认同意所有事情 |
| 权限 | 谁获准在何时进入哪里、执行什么 | 身处房间就自动拥有全部操作权限 |
| 物品 | 持有者、位置、用途标签、耐久/数量 | 听说过物品就当作已持有 |
| 能力 | 已发现、已解锁、当前启用 | 发现技能就自动生效 |
| 场景 | 门/设备/路径的持久变化 | 切地图时丢失准备结果 |
| 任务与证据 | 线索、核实、完成条件、结果 | 看到线索就默认推理正确 |
| 存档与事件 | 已结算事件、随机结果、模式限制 | 读档重复发奖、重复扣费或前后矛盾 |

单次行动可以统一描述为：

```text
前置条件 → 显示已知成本 → 玩家确认行动 → 校验条件仍成立
→ 结算资源/时间/风险 → 写入世界状态 → 展示结果与新机会
```

路线可以先画依赖图，再写对白。否则长篇台词写完后才发现两个关键物品互相依赖、NPC 已被剧情移走，修复成本会更高。

内容生产同样需要控制：每个角色先明确当前目标、资源、开放窗口、承诺和反应，再写具体对白。每段新增文本都应服务于识别人物、暴露信息、改变关系或反馈结果中的至少一项。

## 6. 与《来自月亮的 Z》的关联，仅作为候选

本轮读取了本项目的现有玩法文档与 2026-10-09 地点分工。最新地点分工为码头询问信息、咖啡馆打工购物、道具间白天与 Z 交流、灯塔权限和关键道具；其中部分与旧玩法稿尚未完全同步。

| 现有设计内容 | 可借鉴的机制联系 | 需要保留的本项目边界 |
|---|---|---|
| 码头问询 | 人物日程与信息来源决定线索可获得性 | 听到传闻不等于完成核实 |
| 咖啡馆劳动与购物 | 时间转换为补给与行动准备 | 当前价格、收入只是静态 UI 示意，不能当平衡数据 |
| 道具间接触 Z | 关系建立能改变协作机会与分工 | Z 理解、相信、愿意合作应分别成立 |
| 灯塔许可与设备 | 合法进入提供准备机会，行为仍有可追踪后果 | 许可不是所有操作的授权，取得道具不是迁移成功 |
| 双人合作逃离 | 路线是若干条件和双方行动的组合 | Z 的同意不能被一个通用好感阈值替代 |

《动物迷城》的资料没有证明生成式 AI 是其核心运行机制。若未来继续做 AI Native 的 Z 项目，可以借鉴其世界规则和作者编排，同时让自由表达服务于理解与协作。语言模型不应凭一句承诺创造钥匙、权限、已完成事件或不存在的路径。这是结合本项目既有边界的建议，不是从原作推得的技术结论。

现有依据：[玩法介绍](../../docs/月亮Z-完整玩法介绍-v1.md)、[最新地点分工](../../ui/locations-v1/README.md)。

## 7. 怎样判断做出了想借鉴的体验

原型阶段优先观察行为证据，暂不把小样本百分比当作统计结论。

1. 玩家能不看攻略说出当前目标、缺少条件，以及至少两种可考虑的办法。
2. 玩家因未来计划而改变当下行为，例如为访问权选择工作，而不只追求即时收入。
3. 一次人物关系投入在后续场景中产生可见用途，且玩家知道其中缘由。
4. 同一地点在不同时段或准备状态下提供不同机会。
5. 一次局部失败后，玩家能解释原因，并有代价合理的补救选择。
6. 两次游玩采取不同路径时，准备动作、资源分配或人物接触确实不同。
7. 结局反馈对应过程状态，没有“拿到证据就自动得到同意”等跳步。

如果这些成立，才有理由增加 NPC、技能、天数和分支。若不成立，应先修正行动之间的联系，而不是继续添加菜单、台词或美术场景。
