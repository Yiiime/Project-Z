# 《来自月亮的 Z》Chapter1：一天 Demo

2026-10-12。Godot 4.7.2 + GDScript 工程，使用 Compatibility 渲染。白天已接入本轮像素地图重制，保留海岛和现有角色；昼夜界面已按 C.02 概念统一优化，版本 `0.2.0-d1-ui`。当前实现的是 **D1 07:00—23:00 的一日切片**；完整 21 天故事及原 D1—D3 验收仍未完成。

## 开始试玩

- 双击 [启动试玩.command](启动试玩.command)，启动本机服务并打开 [浏览器试玩](http://127.0.0.1:61327/)。这是本地地址，需要启动脚本保持服务运行；不应直接双击 `build/index.html`。
- 双击 [启动Godot.command](启动Godot.command)，启动原生试玩窗口。要编辑工程，可用 Godot 4.7.2 编辑器打开 [project.godot](project.godot)，主场景为 [main.tscn](main.tscn)。
- 网页入口与原生工程使用同一份规则和场景代码。当前没有 Windows 或 iOS 安装包，也没有在线发布地址。
- 已导出的[独立浏览器试玩包](https://github.com/seanlee111/Z-from-Moon/releases/tag/demo-v0.2.0-d1-ui)包含本地启动脚本、构建及许可证；需要本机 Python 3，无需安装 Godot。包内操作说明见 [PLAYTEST.md](PLAYTEST.md)。

首次进入选择“开始新的一天”，关闭到岛提示，然后靠近登记亭的许舟报到。鼠标操作界面按钮；若键盘没有响应，先点一下游戏区域。

| 按键 | 功能 |
| --- | --- |
| WASD / 方向键 | 移动 |
| E | 靠近 NPC、门或场务箱后交互；继续进行中的活动 |
| M | 查看地图，地图不传送 |
| I / J | 背包 / 日记 |
| T | 查看日程 |
| Esc | 关闭当前面板或打开暂停菜单 |
| F5 / F9 | 保存 / 读取手动槽；也可从暂停菜单操作 |
| F3 | 开关脚底、阻挡与合法交互范围调试叠加 |

动作完成后自动保存。场务、咖啡和制作从确认开始保存 `pending` 与实际步骤；中途可以暂停、保存和读取，确认后的活动必须完成，不能靠关面板取消。坏主档会尝试恢复上一份有效 `.bak` 并明确告知；主档和备份都坏时不覆盖当前进度。网页与原生运行环境的存档不自动互通，切换浏览器或地址也不应视为已同步。

## 这一天怎么玩

白天在码头小街、咖啡馆、道具间之间探索，和许舟、林乔、陈叔、陆岑交互。灯塔维护区可问询权限，当前不开放进入。D1 白天不会提前与 Z 见面。

- **报到与工作：**报到 30 分钟；场务搬箱和交接 60 分钟，正确完成得 16 金币。错误交接真实消耗时间，之后在陈叔在岗时花 15 分钟复核，再领原工资一次。咖啡班在 08:40 或 14:00 开始，完成三位客人的订单后结算 90 分钟、30 金币。
- **两种准备：**小礼物 12 金币，材料包 8 金币，购买均需 5 分钟。已完成场务的玩家可在 08:30—09:40 工作台窗口完成 60 分钟教学，消耗一份材料得到作品；最晚 08:40 开始，因此会错过上午咖啡班。
- **日程：**普通走路、查地图、读字和打字不耗游戏分钟。12:00—14:00 是固定午间日程；晚饭可在 18:00 后用 30 分钟完成。没有精力、体力或专注预算。
- **夜间：**20:00 打开手机直播。真实观察过码头铜铃，才可使用对应话题；已有礼物才能送出，发送不再扣购买款。作品在主节目中出示后仍归玩家。发送、被回应与节目推进是不同事件，三次“继续节目”各推进 40 分钟。
- **连麦与日终：**连麦自愿报名、随机抽选，以本地文字交互表现；接通后最多 3 轮离线作者接话，按真实场务、咖啡、作品和铃声事实回应，不增加认识、金币、物品或许可。次数由已保存消息派生，读档不重置；结束后恢复普通弹幕。未抽中不扣钱、不扣关系，弹幕和作品路径仍在。22:00 进入复盘，确认后到 D1 23:00，显示当天结果并保存，不进入 D2 或自动发出私人邀约。

一条易核对的路线是：报到 → 场务 → 买礼物 → 08:40 咖啡班 → 观察铜铃 → 午间日程 → 等到夜间 → 回答声音话题并赠礼 → 看完节目。最终应为 **74 金币、礼物 0、有效认识贡献 3**。也可选择材料与作品路线；不必两路都做。

## 美术与 AI 的实际边界

当前[白天像素地图](../docs/地图像素重制与空间交互-v1.md)使用五张独立图集、脚底碰撞、前后排序、遮挡淡化、物件接触影及合法目标 E 提示。海岸地面和可走区共用多边形，房间墙脚、出口与交互点明确；M 地图由当前场景对象与通行数据生成。主角采用四方向、每向四帧图集；NPC 为独立站立图。

世界在独立 **640×360 SubViewport** 渲染，中文与 HUD 在 **1600×900 主 UI** 排版。默认 1280×720 窗口对应世界 2 倍整数放大；1600×900 预览为 2.5 倍 Nearest，仍存在像素宽度不均的非整数缩放限制。人物约 40 世界像素、移速及交互距离是本项目调校，尚未按原作实机录屏标定。

首版三张预绘场景已清理掉原主角，岛上烘焙人物也已移除；主角四向精灵、部分 NPC、可搬运箱、交互提示、地图与界面分别由引擎绘制。当时咖啡馆老板与顾客、道具间陈叔及场景家具仍有烘焙在背景中的部分；主角为四向静态帧配轻微步行位移，前景遮挡和完整逐帧步行动画未生产。这些底图和图集继续作为历史材料保留。

Z 使用空房间背景与透明四表情图集，切换常态、温暖回应、闭眼和思考表情，带轻微呼吸/眨眼。文字回应读取本局真实事实，以离线作者规则产生；不是联网 LLM、真实直播观众、语音通话或 Live2D SDK。独立五官、前后发、手臂绑定、口型和声音资产尚待制作。图像生成来源与对齐限制见 [generated-prompts.json](assets/generated-prompts.json)，详细资产边界见[开工与资产清单](../docs/Chapter1-一天Demo-开工与资产清单.md)。

网页版弹幕已接入[浏览器原生 DOM 输入桥](scripts/web_input_bridge.gd)，以原生文本框承接中文组合输入，再通过现有 `chat` 请求提交原文；输入桥不直接修改世界状态。组合输入期间不发送，收到提交回执后才清空，打开礼物、节目确认或暂停面板时隐藏输入层。下方 92 项检查包含新增文本输入、组合状态、遮挡和长消息滚动测试，尚不代表真实浏览器中的手工原生 IME 候选输入已经验证。

从项目根目录复跑：

```bash
godot --headless --path game --script res://tests/test_rules.gd
godot --headless --path game --script res://tests/test_integration.gd
godot --headless --path game --script res://tests/test_night_view.gd
godot --headless --path game --script res://tests/test_pixel_world.gd
```

`--headless` 不创建游戏窗口；`--path game` 选择工程；`--script` 执行对应测试，失败返回非零退出码。集成测试使用隔离的用户存档目录，人物以合法可站立坐标定位，不能用其通过替代连续键盘行走、画面质量或真实用户体验验收。这些结果也不代表原 D1—D3 的全部 D01—D16 或 G0—G6 已通过。
