# Day0–1 开场交互迭代

任务 PR #67，基线 main a141001。只完成用户要求的前三项，第四项（可分发的本机服务与配置打包）等待用户体验确认后再做。用户明确追加授权修改 `Scripts/UI/StartPageView.cs` 与 `Scripts/FirstDay/FirstDayOverlay.cs`。

## 行为

- 姓名输入采用浅色紧凑卡片、可读输入框与居中按钮。姓名框、首页确认框和登岛邀请在窗口尺寸变化时重新适配，限制可视边距，保留中文输入法组合输入保护。
- 开场先自由闲聊。至少3次实际播放完成的主播发言、4条实际显示的虚拟观众消息，以及45秒有效观看时间后，才开放抽奖工具；暂停时的时间不计入。达到条件后由主播自然想到第1000场、介绍七天小岛邀请，不按固定台词播报。
- 虚拟弹幕来自当轮生成内容，逐条错开显示；提前打断的台词不发布对应反应。开场进度持久化，重复回执不重复计算。
- 抽奖显示可点击礼盒，等待期间不会自动开奖、不会因两分钟执行超时丢失。完整复用用户 HTML 内嵌的原视频，保留 1.30 秒待点、从 1.75 秒开启、8.80 秒展示邀请、从 9.60 秒收下的交互时点。两处姓名随纸面运动动态合成。玩家点击“收下邀请”即明确接受；主播确认名额后衔接登岛，不再弹第二次确认。按用户追加要求，10.20 秒收尾即结束，不出现原视频后面的“再看一次”。
- 暖场完成与开奖完成分开；失败、离开和取消不会制造获奖事实。礼盒等待期间暂停继续生成主持台词。

## 设计参考

参考研究 K03 的“发送、展示、回应和推进分别确认”与 K04 的“口头意愿和实际操作分开”。本轮调整开场呈现节奏与玩家点击反馈，不改变七天名额规则、世界日程或剧情完成条件。未把生成动画当成玩家已接受邀请。

## 验证

服务测试覆盖真实解析器、播放器完成回执、弹幕显示回执、暖场门槛、存档恢复、点击证据与重复回执。`OpeningInteractionVerification` 在独立 Unity 场景中检查多分辨率实际布局、姓名输入、礼盒不自动开奖和动态名字；其事件驱动测试不等同于完整剧情通关。最终结果随本地交付包附上。


最终回归：`npm test` 171/171 通过；真实供应商文本验证约100秒到达带玩家名邀请，未出现输入校验失败。该验证使用脚本回放和点击回执，不代替真人完整剧情试玩或语音验收。Unity 6000.3.27f1 实际运行通过99项检查，包含姓名和信件五种分辨率、视频待点/开奖/收下状态、动态名字及无重播收尾。后续附本地 macOS 试玩包，第四项尚未执行。
