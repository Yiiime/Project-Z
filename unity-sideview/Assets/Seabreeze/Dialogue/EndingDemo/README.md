# 第七晚 · 结局 Demo

本模块在 Project Z 横版工程里提供一个独立的结局切片：作者上传本地故事文件 → 第七晚码头 → Z 自主选择 → 全部知情经历的回望 → 选择与执行结果分别承接 → Z 的最后一句话。

## 最快试玩

双击本目录的 `启动结局试玩.command`。浏览器会打开本机码头页面，右上角 **上传故事文件** 是内置入口。

也可从仓库根目录运行：

```bash
node unity-sideview/Assets/Seabreeze/Dialogue/EndingDemo/server.mjs
```

- 码头：<http://127.0.0.1:4319/>
- 文件入口：<http://127.0.0.1:4319/editor>
- 独立结局：生成后自动进入 `/ending?run=...`；刷新或服务重启仍能读取该次结果。

**需要 Node.js 22 或以上。** 无额外 npm 依赖。服务仅监听本机。关闭启动器终端会关闭该次服务；再次双击可重新打开。端口已被其他服务占用时，会在终端提示。

启动器会按需沿用本机 `~/Project-Z/unity-sideview/Tools/MemoryLab/.local/model.json` 的已有连接；也可以在编辑页填写 DeepSeek 或方舟的连接，或通过 `Z_MEMORY_CONFIG` 指定配置文件。密钥不会出现在经历或结局导出中。

## 用一份本地文件内置故事

上传 TXT、Markdown 或本 Demo 导出的 JSON，不需要逐项填表，也不要求特定模板。普通文本可以直接写七天的回忆、岛上发生的剧情、Z已经知道的处境，以及玩家最后说的话；不同经历之间空一行即可。也可以直接把本地文件发到当前聊天，请 Codex 接入。

页面只有 **选择故事文件 → 预览整理结果 → 使用这份文件**。TXT/Markdown 由模型标注段落日期、标题、记忆／剧情和 Z 是否知情。原文不交给模型重写，逐段完整保留；模型只是标注。幕后、未告知消息和未来设想保守标为 Z 未知，不进入她的决策和回望。预览可展开全部原文，作者应检查知情标记；修订内容直接改本地文件再上传。

普通文本最多60,000字、200KB及40段；长段自动切分。JSON 可包含显式结构，直接校验导入，无需先调用模型。未点击“使用这份文件”时，当前本局不会被覆盖。覆盖本局只改变下一次结局，历史生成结果保留自己的记忆快照。

去留条件从文件里的明确事实整理：准备未说明时不默认有船，离岛成功未确认时使用 pending，留岛安全未确认时使用 uncertain。文件中的明确执行结果只在抉择之后承接。请把 Z 已知内容与作者幕后备注分段写，避免一段混入秘密后被保守整体排除。

已有模型连接默认沿用。没有连接时，页面下方的折叠设置只需填写一次；密钥不会进入文件导出。

`scenario.example.json` 是首次运行的示例，不是正式剧情定稿，其中包含为 Demo 创作的玩家互动。上传后的作者文件保存在 `~/.project-z/ending-demo/scenario.json`，包括原始文件名与原文。`Z_ENDING_DATA` 可指定另一目录。每次结局保存在 `runs/<id>.json`；上传新文件不会改写历史结果。页面可下载当前经历JSON以便备份或重复使用。

## Unity 试玩

用 Unity **6000.3.27f1** 打开 `unity-sideview/`，先启动本机结局服务。

菜单 **Seabreeze → Ending Demo → Open independent seventh-night scene** 打开独立场景，然后 Play。

- “上传故事文件”打开同一个文件入口，使用文件后回到 Unity 点“重新加载经历”。
- “听听她的选择”调用同一个模型服务。
- Unity 按段呈现开场、每段回望、选择与后果；长文支持滚动。
- “打开独立结局页面”打开同一次生成的完整页面，不会再次调用模型。

不修改 Street、现有 HUD、时间系统、主线任务、真实存档或全局构建场景列表。新增 `EndingDemo.unity` 仅属于这个独立切片，主游戏不会自动跳入。

编辑器方法 `Seabreeze.EndingDemo.EndingDemoAuthoring.BuildMacPreview` 可单独构建 `Builds/EndingDemo/ProjectZ-Ending.app`。构建产物不提交到 Git。

## 选择和记忆规则

沿用当前 Z 人物档案，不加载其他岛民的私有背景。第一次模型调用只得到当前局面、玩家最后的话、离岛准备与全部知情经历，自主输出 `leave` 或 `stay`。未执行的后续结果不会提前注入。

第二次模型调用锁定第一次选择，逐条生成回望。服务验证每个知情经历ID恰好出现一次，再按日期呈现；缺失、重复或引用未知ID都不发布结局。最终理由可以只抓住少数关键经历，回望页面则覆盖全部知情经历。ID校验保证引用覆盖，不能证明每句生成文字都语义正确，作者仍需阅读与编辑输入以评估内容。

本 Demo 没有好感分数、投票或“玩家付出够多就必须离开”的判定。喜欢和信任玩家可与不同意方案并存。她想离开，不意味着已经走成；她想留下，也不意味着关停计划被取消。

与七日参考的差异：本切片把抉择安排在用户指定的 **第七天晚上**，直接从文件预置的局面开始，不要求演完前六天。结局的离岛执行与留岛后果目前由作者预设，没有接通完整地图的登船任务执行器。

## 研究依据与机制采用

- **K04：关系有具体原因。** 保留由具体承诺、亲历和知情事实改变判断的结构；使用作者文件中的经历代替完整七日任务产出，不新增固定分数。
- **K12：理解、合作、真正逃离分别结算。** 保留 `departureReady`、Z的 `choice` 和 `leaveOutcome` 三者分离；留下使用独立后果，不给安全豁免。
- 参考 `research/动物迷城/01-玩法与机制研究.md` 第12节及 `02-Demo借鉴与验证框架.md`。这是本项目对研究机制的适配，不声称复刻原作结局或实现完整逃脱玩法。
- 本模块遵守现有规则，没有改变完整游戏的机制，因此不把作者预设回执登记为主工程离岛实现完成。
