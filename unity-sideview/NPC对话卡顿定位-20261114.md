# NPC 单聊无回复：诊断记录

本轮针对用户反馈“进入对话页面后，NPC 一直不说话”定位。被诊断的本地包为 `0a0976c`，PR #70 保持草稿。本轮未修改运行时代码、原始存档或本地 App。

## 已确认的阻塞链

1. E 扫描、NPC 注册和单聊面板能够正常工作。使用用户第二天存档的隔离副本，在 Street 对林序按 E，面板打开、输入控件可用，首日剧情锁和场景切换锁均为 false。
2. `MemoryLabClient.FocusAfterDelivered` 必须等待世界打开、事件同步和当前角色运行记录同步。`CanGenerate` 在此期间为 false，单聊发送入口被禁用。
3. 每个 `/api/game/runtime/sync` 都进入 `gameResponse`，生成完整 checkpoint：读取历史记录、序列化并同步压缩全部 NPC 运行历史，再冻结每条记录和清单。单次实测耗时约 0.51–1.12 秒。
4. 多角色同步请求在 Node 主线程串行排队，连 `/api/health` 也受影响。八个真实 checkpoint HTTP 请求并发时，健康检查从空闲 0.009 秒上升到 4.037 秒；此测试禁用了模型调用。
5. Unity 的健康请求只允许 3 秒。一次超时就将 Reachable/opened 置为 false；`MemoryGameController.ConnectionChanged` 在玩家等待回复时调用 `CancelAll`，取消会话。重连又会重开世界并等待同步，形成反复等待。

这能够独立复现“已发送但没有回复”。原局已退出，无法还原退出前每个瞬时变量；这里明确区分日志事实与隔离复现，不把直播的单条 `state_conflict` 当作根因。

## 复现与测量

- 原局单聊的 14 个生成 job 均 succeeded，14 个 proposal 均 committed；当前事件序号 180/180，保存时两个 outbox 均为空，后端 liveRoom 为 null。没有“所有已到达模型的单聊都失败”的证据。
- 隔离 Unity 复现：按 E 后约 36 秒才允许发送诊断问候；发送后约 4 秒触发健康超时，PlayerActor 被清空，NPC 回复未提交。此为成功复现故障，诊断程序按失败条件退出，不记为功能验收通过。
- 独立无模型测量：三次 checkpoint + freeze 总计 1120.55 / 541.07 / 509.77 ms；运行历史压缩后 base64 长度 4,606,892 字节。
- 八个真实 HTTP checkpoint 请求全部返回成功，响应时间 0.55–4.09 秒；穿插的 health 请求等待 4.037 秒，超过客户端 3 秒超时。
- 第一次诊断工具未持续重绘 Game 视图，截屏协程等待造成面板入场未完成；该次结果剔除。补齐 Game 视图 Focus/Repaint 后，`PlayerInputReady=true`，再次复现同步超时取消会话。
- 另有独立行为差异：`NpcConversationCoordinator.BeginPlayer` 仅在 FirstDay.Active 时自动请求开场对白。第二天可进入空白单聊、等待玩家先发送。是否也是用户此次现象的一部分，需要结合“有无发送文字”确认。

## 代码位置与修复方向

- `Tools/MemoryLab/server.mjs`：`gameResponse`、`referenceCheckpoint`、`/api/game/runtime/sync`，减少每条同步生成完整历史快照的开销，保留存档和回执一致性。
- `Tools/MemoryLab/lib/engine.mjs`：`checkpoint` 的同步历史读取、JSON 序列化与 `deflateRawSync`。
- `Tools/MemoryLab/lib/store.mjs`：`freezeCheckpoint` 重复遍历、哈希全部记录。
- `Assets/Seabreeze/Scripts/Memory/MemoryLabClient.cs`：`Health` 的 3 秒阈值及一次失败立即重开世界；`FocusAfterDelivered` 的无期限等待。此文件尚需用户追加路径授权。
- `Assets/Seabreeze/Scripts/Memory/MemoryGameController.cs`：`ConnectionChanged` 不应因短暂健康检查延迟直接取消正在等待的玩家会话。此文件尚需用户追加路径授权。
- `Assets/Seabreeze/Editor/NpcInteractionDiagnostics.cs`：隔离存档继续、E 交互、发送和回复各阶段的阻塞变量记录。只在显式执行 Run 时启动，不进入 Player 构建。
