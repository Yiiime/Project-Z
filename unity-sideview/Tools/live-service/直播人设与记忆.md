# 在直播里，Z 什么时候会记得什么？

以当前原生 Mac 直播分支为准。游戏存档里的「第几天」、本场直播会话和已准备的唱段属于三个不同的状态来源。

| 能力 | 实际入口与触发前提 |
| --- | --- |
| Z 的主播人设 | 服务端加载 [开场直播人设投影](server/shared/worker/z-persona.js)。[主持请求](server/shared/worker/agent-director.js)在每次模型决策中放入 Z_PERSONA，连麦时在同一人设后追加连麦指引。需要主 Agent 已配置、直播正在进行；不用特定关键词、好感度或声纹登记。语音登记是上麦条件，不是启用人设的开关。模拟观众另有自己的身份。 |
| 人设范围 | 投影从 moon-z-life 的主文件、人物、口吻、世界和剧情资料中选取开场可知内容，场景为 opening / night / live_room。运行时不逐轮读取整套 Skill，不会因为存档到了第二天就自动解锁后续剧情。 |
| 本场已发生的事 | [会话连续性](server/shared/ui/session-continuity.js)自动记录公开事件；字幕中途进度不当作完整往事。玩家消息、已上屏弹幕、主播说完的话可成为后续依据。每轮另带最近公开上下文、最多 800 字的主持摘要、带来源的未完事项；候选草稿不是已发生事实。普通聊天和连麦使用同一场上下文。 |
| 重连与换天 | [服务端会话](server/session.mjs)按会话 ID 保存并可恢复同一场。结束后新开直播，本场上下文重新开始；crossSessionMemory 显式为不可用。手机将收播结果交给游戏推进日期，不把关系、任务或上场聊天注入新一场。当前本地试玩启动器另外使用 -memoryDisabled，单独移除此参数也不会凭空产生跨系统接线。 |
| 唱段任务 | [唱歌服务](server/singing/service.mjs)按 owner 持久化任务、准备状态和歌曲资产；主持人在服务提供相应任务上下文时可续接或播放。这只表示曲库和任务可延续，不表示 Z 记住了玩家上一场说的所有话。 |
| 五层剧情记忆 | [Skill 的记忆设计](skills/moon-z-life/references/memory.md)区分当下、日常、锚点、共同、裂缝，按话题、场景、关系、情绪和追问展开。完整协议要求引擎提供 z_internal.memories，并保存 z_state_update.memories。本直播主持协议目前没有这条读写链路；提到童年或码头可能引发符合人设的自然回答，但不是存档记忆解锁。 |
