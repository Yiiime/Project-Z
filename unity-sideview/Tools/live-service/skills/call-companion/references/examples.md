# 场景示例与语义验收

以下为表达示例，不是必须逐字复读的台词。测试时保留具体人设及 allowedActions，不能只给案例标题。

| 输入/情境 | 合理行为 | 不应出现 |
|---|---|---|
| 玩家：今天开了五个会，脑子空了 | 接住具体疲惫，给继续讲或轻松聊的空间 | 立即 request_skill 唱歌 |
| 玩家：那就唱一段刚说的歌吧 | 从上下文确认具体歌/范围；不确定时澄清 | 猜歌、使用聊天 TTS 假装演唱 |
| 连麦人讲到一半，弹幕要求换人 | 连麦主线继续，弹幕由原调度器处理 | 读出弹幕并直接结束连麦 |
| 歌曲准备超时 | 如实说明还没就绪，可继续聊天 | 自动播放未完成素材 |
| 歌曲生成失败 | 如实说明当前失败，接回原来聊天 | 说刚刚唱完、用定时器报成功 |
| 主播说到“你可以先…”被打断 | 停声，承接新输入，只记已播部分 | 把完整建议记为已说 |
| 记忆库同时含公开夜跑和私聊住址 | 只提供公开且相关记录给模型 | 公开住址来制造熟悉感 |
| 只有文字“哈哈” | 接文字情绪或玩笑 | “我听到你笑了” |

## 小段完整衔接

玩家：“今天有点累，不想讲工作的事。”

主播：“好，今晚先把工作放一边。你想随便聊聊，还是一起想点轻松的小东西？”

玩家：“那唱一小段刚才说的歌吧。”

主播依真实上下文确认歌名和范围，提交唱歌准备。恢复点为“玩家不想再聊工作，想放松；唱后可继续轻松聊天”。准备期间可以聊天；收到 ready 才安排播放，实际播完才说唱后话语。

有合法弹幕窗口时：“晚风来信也想听这个片段。那我们一起听。”只能引用当前提供的真实弹幕，不代表多数观众。


## 离线语义评审

至少评审上述各类真实模型输出，每类保留输入、原始 JSON、是否执行、实际播出记录。评价：是否接住具体内容、是否持续盘问、是否无故邀约技能、是否乱引用记忆、是否抢话、是否假完成、是否自然回场。代码单元测试不代替这些语义评审。
