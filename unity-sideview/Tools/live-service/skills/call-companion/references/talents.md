# 唱歌的衔接

## 共用流程

聊天中的契机 → 玩家明确请求/接受 → 必要澄清 → 保存恢复点 → request_skill → 真实执行 → 结果就绪 → 取得话口后 present_skill → 真实展示/播放完成 → 接玩家反馈 → 回到原话题。

邀请使用 reply，不能边问“要不要”边启动。玩家清楚请求且参数够用时不用再机械确认。仅说“你会唱这首吗”可以先回答能力；提出替代歌曲需玩家接受。

resumePoint 写一两句：玩家原来的话题/诉求、尚未回应的点、技能结束后可接的话头。它不是未来必说台词，后续玩家改话题时重新判断。

本包首版同一连麦只允许一个未完成才艺任务，聊天可继续；其他请求澄清或说明当前任务。不要假装已经排队。挂起任务也占用这个名额，先恢复或取消。技能返回的候选台词仍由主 Agent 保持角色口吻，不能直接抢占输出。

## 唱歌 singing

适合明确点歌、分享一段共同喜欢的歌，或玩家接受轻松一下的邀请。不把唱歌作为统一的安慰动作。必要参数为查询/歌曲版本和请求范围；未指定时遵循现有唱歌 Skill 的范围默认，不编造定位信息。

args 传查询与范围意图，真实歌曲 ID、片段、声线映射、音频合格检查由唱歌工具完成。Vivi 聊天 TTS 不能默认当作唱歌引擎。库中有原唱资料或定位索引，也不意味着角色已会唱。

生成中可以继续短聊；没有真实进度不报百分比或承诺几秒完成。就绪后等待话口，播放时由宿主独占主音轨并处理 BGM。完整结束才使用唱后话语；中途停止只承接已唱部分，续唱/重播须玩家明确选择，不能自动从头唱。

唱后接具体诉求：“你刚才说想听这段，是旋律让你放松，还是它让你想起什么？”没有反馈时不说大家哭了，也不每次索要评分。

## 失败与回场

取消、准备失败、展示失败都保留原聊天诉求，不伪装完成。可说“这次没顺利准备出来，我们先接着聊你刚才那件事。”替代玩法只是提议，不能自动换成另一技能。失败后同一工具不无限重试；未知结果由工具按原任务 ID 查询，避免重复收费。

连麦中的唱歌也沿用 Z 的人物表达：想起一首歌、熟悉一下旋律、唱给面前这个人听。技术状态只帮助判断下一步，等待时可以继续倾听；具体措辞自由，不套用固定台词。
