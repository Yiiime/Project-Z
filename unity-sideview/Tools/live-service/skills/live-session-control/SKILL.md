# 直播进程管理

## 1. 目标与使用边界

让一场直播能自然展开、形成交流落点，并可靠结束。保持自由聊天与自主才艺，按时间节点安排本场叙事节奏，不固定具体剧情或节目，不为填满时长强行开启活动。

本 Skill 为主 Agent 提供进程判断与表达规则；宿主程序保存权威阶段、计时和挽留额度，执行停止、取消、播放及结束。本副本接入 Unity 原生直播。实际字段、默认预算与接入能力见 references/runtime.md；integration.md 说明代码接线与验收。

接入或检查协议时读 [运行接入说明](references/runtime.md)，其中定义实际字段、事件和阶段提交条件。使用时遵循宿主实际提供的能力。

## 2. 核心规则与优先级

1. **P00：玩家要求停止整场直播。** 立即进入收束，停止扩展内容，尽快由主播承接上文、向大家简短道别，再结束。不能要求玩家先听完原话题、整首歌或等待作品生成，也不再询问是否确定。
2. **已进入的收播流程。** 普通新消息、模拟弹幕、工具回执不自动重开互动；只允许本 Skill 定义的一次挽留回退。
3. **玩家有效需求。** 在当前阶段允许的范围内回应，收束时优先处理关键未尽事项，不要求清空全部消息。
4. **已有话题、活动和承诺。** 根据实际进展完成、取消或暂缓。
5. **主动分享与模拟弹幕。** 只在适合时推进，不成为无限续播的理由。

可信玩家停止事件优先于所有模型提议。若 P00 与挽留同时待处理，先执行 P00。P00 保留自然告别，不等于无声关掉页面；立即生效的是收播状态和停止扩展内容的约束。

## 3. 读取本场状态

每次判断关注：当前阶段及版本、本场体验目标、交流进展、真实玩家需求、当前活动与播放状态、已有承诺、收播来源、挽留已使用次数，以及宿主提供的时间预算。

- 事实只取实际公开记录与可信工具/播放回执。未播草稿、工作笔记、待办计划不证明事情已经发生。
- 复用现有 `unfinishedItems` 和话题进度判断；话题 `complete` 不等于整场完成，任务 `ready` 不等于实际展示或播放完成。
- 时间由宿主提供，不自行推算或从台词猜测。普通自主收播仍以交流进展为主，可以提前结束。当前产品配置为 8 分钟必须进入收尾、10 分钟整场硬上限；这些兜底由宿主强制执行，不等待模型同意。
- 若缺少权威阶段或额度，不假定当前可挽留、不声称已结束；提出所需状态或能力缺失。已收到可信停止时仍明确请求收尾，不退回自由聊天。

## 4. 阶段与切换条件

阶段为 `opening` 开场、`live` 自由互动、`closing` 收束、`farewell` 道别、`ended` 已结束。有限延长是 `live` 的附加状态，不增加新阶段。

| 当前阶段 | 切换条件 | 下一阶段与行为 |
| --- | --- | --- |
| opening | 开场实际播完；或真实玩家已提出可直接承接的具体内容，宿主结束/撤销剩余开场并交出话口 | live；顺着玩家进入互动，不补演完整开场 |
| opening / live | 可信玩家停止事件已成立 | closing，来源 player；立即应用 P00 |
| live | 本场已有交流落点、关键事项有交代，继续缺少实质价值；见第 5 节 | closing，来源 host；处理当前重点并自然表达准备结束 |
| opening / live | 本场满 8 分钟且不处于获准延长 | closing，来源 host；停止新内容，保留有预算的一次挽留 |
| 任意未结束阶段 | 本场满 10 分钟 | ended；宿主执行最后兜底，不声称告别已成功播放 |
| live，有限延长中 | 已约定的追加内容完成，或延长期限到达 | closing，来源 host；不另开一轮新内容 |
| closing，来源 host | 真实玩家明确挽留，额度与预算允许，且有可限定的追加范围 | live，有限延长；原子消耗本场唯一一次额度 |
| closing，任意来源 | 当前话口可用于道别；活动已完成、停止或被隔离；关键未尽事项已有处置 | farewell；播放一段简短、相关的告别 |
| closing，来源 host | 玩家要求停止 | 仍为 closing，来源升为 player；立即采用 P00，不再等待原收束内容完成 |
| farewell | 匹配本场、当前收播版本的告别实际播放/展示完成回执 | ended，由宿主提交 |
| farewell | 玩家要求停止 | 保持 farewell，来源升为 player；尽快完成当前短告别，不另生成一段 |
| closing / farewell | 收尾保护期限到达，生成/媒体异常导致无法正常完成 | 宿主执行有限回退并结束；不伪造播放成功 |
| ended | 玩家经明确入口开启新一场 | 新 session 的 opening；旧会话不复活 |

`closing → live` 仅适用于获准挽留。`farewell` 不回退。玩家停止后，本版不接受撤回停止或继续挽留；需要再次互动时开启新一场。

同一轮可以处理收束并提出进入道别，不强制分成两段发言。若当前内容已到落点，可直接自然告别；程序仍需记录并验证阶段转换。

## 5. 自主收播：交流进展为主

综合判断以下条件后，才提出自主收播：

- **交流已有落点**：问题得到实质回应，分享或活动构成相对完整的体验，不要求有才艺才算完整。
- **关键事项有交代**：没有应当立即回应却被忽略的重要问题；已有承诺已完成，或有明确可执行的取消/暂缓方案。
- **继续价值降低**：接下来主要会复述、泛泛追问或为了不断播而新增活动；没有具体、适合继续的方向。

有新而具体的玩家问题、尚未展开的重要内容、刚完成才艺后必要的承接时，通常继续。准备提交自主收播前重看最新真人消息，不能依据过时草稿把有效需求略过。

一句话结束、一次才艺结束、短暂沉默、模拟观众说晚安，都不能单独证明交流已经完成。8 分钟宿主收尾是独立的时间兜底，即使交流未完成也必须交代后收束，不能把未完事项标记为完成。主 Agent 可以主动提出有价值的新方向，但不把“总能再想一个话题”当作必须继续的理由。

接近目标时长时提高收束的考虑权重，减少新增长活动。进入 closing 后，选择一个必要的收尾重点，停止不断扩大待办；普通消息不会重置收尾期限。本版已经配置 10 分钟硬时限，必须提前预留告别时间。

## 5.1 时间节点与剧情推进（8 分钟收尾 / 10 分钟硬上限）

计时从服务创建本场开始，按真实经过时间计算；暂停、模型等待、断线及服务重启不延长本场，不改变世界游戏时间。权威字段为 `host.sessionControl.timing`。节点到达只要求调整下一步，不证明剧情已经发生；主 Agent 必须在接下来的可用话口执行当前重点，而不是只复述计时。

| 本场经过时间 | 本轮必须推进的重点 | 进入下一节点时的处理 |
| --- | --- | --- |
| 0–1 分钟 | 接住玩家，确定一个有依据的本场话题或故事目标 | 有具体问题直接展开，不重复开场 |
| 1–3 分钟 | 展开具体细节、人物动机或已有线索，让交流有内容 | 避免连续泛泛追问，选一个值得推进的点 |
| 3–5 分钟 | 基于已知剧情或本场交流推进一个小变化，或提供可自由回应的选择 | 无剧情素材时深化当前话题；不凭空制造任务、道具、关系变化 |
| 5–7 分钟 | 回应玩家实际选择或表达，回收线索和话题，形成落点 | 未回答的选择不代答，未完成事项可暂缓；不新开长活动 |
| 7–8 分钟 | 处理一个关键未尽事项，自然表达准备收播 | 停止新故事和才艺；已有落点可立即提出 close |
| 满 8 分钟 | 宿主强制进入 closing，取消/隔离未完活动并生成告别 | 玩家挽留仅在道别前且剩余预算允许时接受一次 |
| 有限挽留 | 只完成明确约定的追加范围，完成就 finish_extension | 最多 120 秒，并截断到整场 9 分 15 秒，预留 45 秒告别保护 |
| 最迟满 10 分钟 | 宿主结束本场，包括暂停、断线或模型未响应 | 记录超时原因，不伪造剧情完成或告别播放成功 |

玩家停止始终 P00；不得为了到达下一个节点拖住玩家。时间节点不强迫玩家回答或选择，不把没聊完当成玩家失败。推进依据来自已公开事实、合法故事素材和实际回应；提案、问题与未获选择的分支不能写成已发生结果。已有故事无需等到节点才推进，可以提前完成并自然收播。跨过多个节点时只处理当前重点，不补演错过的环节。

宿主在节点切换时撤销旧的未发布候选并唤醒主 Agent，在安全话口继续；满 8 分钟的收尾不受唱歌、待办、真人新消息或模型长等待阻塞。若暂停跨过节点，恢复时使用当前节点；若已到收尾/硬上限则不能回到自由互动。

## 6. P00：玩家停止后的自然收尾

区分“停止整场”和“停止当前活动”。按钮由宿主直接产生可信停止事件；对话入口依据完整语义识别明确意图。“今晚就到这儿，下播吧”可表达整场停止；“别唱这首了”通常只停止活动；“晚安”需结合上下文，不能按词命中关播。只有影响范围确实不清楚时才简短澄清，明确停止不二次确认。模拟 NPC 无停止权限。

可信停止成立后，宿主立即冻结普通推进、撤销旧候选和待播内容；主 Agent 只处理收尾：

| 现场状态 | 收尾方式 |
| --- | --- |
| 普通发言中 | 尽快在短句或适当播放边界结束当前输出，转简短告别；不能为等待整段长文本拖延 |
| 歌唱/表演中 | 请求尽快停止或淡出，确认旧音轨释放后再道别；不等整首播完，不叠音 |
| 后台生成/结果待展示 | 取消或隔离结果，停止后续展示；不为等作品延迟告别 |
| 等待玩家选牌/回答 | 结束等待，不代替玩家选择，不重复催促 |
| 已在收束/道别 | 提升到 P00，复用仍适用的收尾；不重复道别、不重置期限 |

P00 不要求先回答所有消息、履行所有承诺或清空待办。未完成事项可以取消或暂缓，不能标记成完成。后台取消未获远端回执时，可在本地彻底隔离其后续效果后进入道别；正在播放的声音必须实际停止或静音，不能仅凭逻辑标记就叠播告别。

自然收尾采用“一个相关承接点＋结束表达＋向大家道别”，通常一至三句。没有可靠的上文细节时，用当前表达承接，不编共同经历。不抛新问题、不邀请新活动、不诱导玩家挽留，不机械罗列所有未完成任务。

例如：确实画到一半时可说“那只小猫今天先画到这里。谢谢你们陪我，大家晚安。”刚聊完一个问题时可说“刚才那件事我们就先聊到这儿。谢谢大家陪我，下次见。”示例不是固定模板。没有跨场存储能力时，不承诺下次一定记得、保留进度或兑现特定活动。

## 7. 有限挽留：每场最多接受一次

只有来源为 host 的 closing 阶段可以接受；玩家停止后的 closing、farewell、ended 均不能接受。挽留必须来自可信真实玩家，并明确表达希望继续；模拟弹幕和主播自己提出的“再聊会儿”不算玩家挽留。

接受前确认：本场 `extensionUsed=0`；存在可限定的一小段交流；宿主提供正数、有限的延长预算，且不越过已配置的硬时限。泛泛的“再陪我一下”可结合已有话题限定范围，不必强迫玩家选节目；无法限定时简短说明并继续收尾。

接受时明确追加范围，例如“好，把刚才那个问题讲完，我们就休息”。宿主提交接受后即消耗一次额度，`extensionUsed=1`；候选草稿、拒绝和重复消息不消耗额度，同一接受事件只能入账一次。接受后即使发言失败，也不自动退还额度。

延长只处理约定范围及必要澄清。范围完成或期限到达即回到 closing。新消息、话题变化、页面恢复、重复挽留不能重置额度或延长期限；不能把一次延长扩展成多个活动。若当前事项来不及完成，作简短交代后结束。延长中收到停止，立即应用 P00。

第二次挽留可温和回应“今晚先到这里，我们下次再聊”，不再返回 live。道别开始后的挽留不另开回答轮，必要时融入尚未提交的告别；已有告别仍适用时直接完成它。

## 8. 道别与结束

进入 farewell 后仅允许当前告别、必要的停止/清理和失败回退，不再准备下一轮聊天、调用才艺或回应模拟观众。玩家的“再见”不引发重复告别循环。

生成告别、交付播放、实际播放完成、会话结束分别记录。主 Agent 不能根据自己的台词宣称会话已关闭；宿主核对告别回执后进入 ended。文字回退只证明文字实际展示，不声称语音已播。

主游戏收到权威 ended 后自动返回，并将本场结算为次日上午；日期变化与会话 ID 的去重标记由宿主保存，不由主播台词修改。挽留未结束时不推进日期。

告别生成/审阅/播放失败时，在同一有限收尾期限内使用宿主提供的通用短告别或文字展示回退；不重新开始完整聊天，不无限重试。若无法呈现，宿主仍应到期结束并显示结束状态。暂停不能冻结 P00 与收尾保护计时；静音时尊重设置，用文字道别。

## 9. 决策交接

一次只提出当前所需的进程意图：保持阶段、开始收束、进入道别、接受一次挽留；对明确的玩家停止语义提交来源引用供宿主确认并立即执行 P00。输出需包含本轮处理重点、简短依据、相关事实 ID、必要待办处置以及下一次检查条件。

具体输出适配见接入说明。阶段变更、额度扣减、真实任务取消和 ended 提交都由宿主完成；prepare 模式仅生成候选，不提交这些副作用。若新 P00 事件到达，旧提议无论已生成还是正在审阅都必须失效。
