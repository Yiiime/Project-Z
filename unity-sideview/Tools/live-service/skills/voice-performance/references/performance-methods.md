# 片段与演绎方法

## 1. 从观众线索定位内容

| 观众给出的内容 | 下一步 |
| --- | --- |
| 一句完整台词和情绪：“把这句话用委屈的口气说出来” | 直接按提供台词配，不必查出处；标为 user_provided |
| 可读取的文字或音视频片段，指定范围 | 读取并核对角色/顺序，保留范围和来源 |
| 一个梗、人物事件或模糊场景 | 检索线索，确认实际片段及版本，再提取 |
| “最近很火的那个二创版” | 核对时效与内容，区分二创和原作；无法唯一匹配则问一个区分问题 |
| “按这个情境编一段” | 明确 original/adaptation，写可用长度脚本，不假冒原台词 |

以“薛甄珠抓小三”这类请求为例，它在本文件中只是观众检索线索，不是已核实的场景或台词。必须从实际结果确认人物、作品和具体剪辑；不能把训练记忆中的类似片段当成已经检索到。

推荐检索过程：用观众给出的独特人物/事件/作品线索找候选 → 读取可访问来源的实际内容 → 判断原作/剪辑/二创版本 → 确定演绎范围与角色 → 核对待用台词。搜索次数和等待服从宿主预算；没有可靠结果就说明，不能无限搜索或编造命中。

涉及歌词或长篇影视台词时，采用当前可使用内容和允许的范围；需要完整原文但没有可用素材时可请观众提供，或提出原创情境演绎。摘要/概述可以帮助识别，不能作为逐字原台词的证据。

## 2. 提取与处理不确定台词

区分：实际听到/看到的台词、自动转写结果、从上下文推测的词。原文演绎前核实影响含义的词和角色归属；缺字时不能自动补成“原话”。

多角色转写若只标“说话人 1/2”，先核对角色关系；无法确认时请观众明确或使用中性的角色 A/B，经确认后再演。不能因为某种声音听起来年轻就凭空判定角色身份。

只需要表演观众提供的一句台词时，不增加前后剧情。需要缩短或改写时明确指出改编范围；已获准原创则不必每个新增词都再询问。

## 3. 把情绪转为可执行表达

| 情绪要求 | 表演意图示例 | 容易失真处 |
| --- | --- | --- |
| 生气但克制 | 句子更短、关键字有力度、句间稍停 | 一律大声喊叫，失去“克制” |
| 委屈但忍着 | 适度放缓、部分句尾收住，维持清晰 | 全段哭腔或擅自加入哭声 |
| 阴阳怪气/讽刺 | 结合台词语义安排重音、轻微拖长或反差 | 每个字都夸张，听不懂原意 |
| 兴奋 | 更有活力、节奏变化、重音突出 | 盲目加速造成漏字、尾音截断 |
| 冷静坚定 | 稳定语速、清楚句尾、重点明确 | 平到没有角色意图 |

表格描述的是艺术意图，不是供应商参数。适配器必须把它映射为所用引擎真实支持的 controls 或提示渠道，保留 unsupported 状态。不要承诺引擎没有的精确笑声、哭腔或呼吸控制。

情绪可沿片段变化；有明确戏剧转折时按实际语义规划，不把每句都设到同一强度。没有观众指定时，依据已核实情境作合理选择并简短说明，不脑补原人物未表达的心思。

## 4. 文本、声音与表演提示分离

一个 segment 可如此组织；以下台词为本文件原创测试内容：

```json
{
  "segment_id": "seg-01",
  "order": 1,
  "role_id": "role-a",
  "spoken_text": "我等了很久，你至少该告诉我一声。",
  "emotion_intent": "生气，但努力保持礼貌",
  "delivery_notes": ["重点放在至少", "句尾收住，不喊叫"],
  "pause_after_ms": 400,
  "source_anchor": {"type": "original", "source_id": "fixture-original-script"}
}
```

普通 TTS 输入不能拼成“生气，但努力保持礼貌：我等了很久……”。如果引擎支持独立 instruction 字段或已验证标签，由适配器传入；如果不支持，台词保持干净，并诚实限制可控效果。

表演提示先描述用途，再匹配实际资源。例如眉头轻皱、看向镜头或短暂停顿；没有对应动作资源就省略，不随便输出 `angry_01`。同一片段的嘴型用实际音频驱动，不能以文字情绪标签驱动假同步。

## 5. 声线选择与角色区分

默认当前角色声音。观众明确要求某个已有音色则在能力清单中核对版本、语言和可用状态。扮演角色可以保持 Z 的声线，用节奏、语气和停顿区分；要多音色时才选择实际可用替代，不追求“越多音色越好”。

单声线无法可靠体现观众要求的两种声线时，说明并提出同声线双角色方案。未确认前不能输出“已切换两种声音”。真实演员/人物名称不能被当作可用 voice_id，不能自动启动声音克隆。

表演范围内采用其他声音不修改角色长期配置。演后接话、错误提示和普通聊天仍交给主 Agent，按宿主最新日常音色发声。

## 6. 时间轴与质量检查

逐段合成后先确认每个真实 duration_ms，再编排顺序和停顿。若引擎已有尾部静音，检查后决定是否额外插入停顿，避免意外长空白。多角色间响度差异可由音频处理调整，但不能借此改变角色分配或掩盖漏读。

片段级字幕可绑定实际片段边界；逐词高亮需真实词级时间来源。动作可绑定 segment_start/segment_end 等确实可触发的锚点；精确句内动作需要可靠对齐，不能凭字符数猜测后宣称精确。

质检至少试听/核对以下问题：

- 台词是否完整、有无误读、重复、串角色或把提示念出来。
- 角色音色是否来自已确认清单，前后片段是否意外漂移。
- 指定情绪是否可辨，是否因夸张影响清晰度。
- 停顿、衔接、音量和结尾是否自然，是否有非预期主持旁白。
- 字幕与提示是否有真实时间/资源依据，失败时能否清理。

模型只能报告已实际检查的结果。音频不可试听且没有可用核对手段时标记 unverified，留给 demo 人工验收，不因为生成成功就全标 pass。

## 7. 演后互动

完成回执到达前不说“演完了”。完整播放后可以问情绪是否到位，或接观众已有的具体反应。遇到“第二句再冷一点”，先处理修改；遇到“再来一次”，若没有其他改动，复用同一已验收结果并新建播放实例。

中途被打断时可以说“好，先停在这里”，不能用完整结束模板。演绎播放期间即便收到弹幕，也先排队，不叠加 Z 的点评声音。
