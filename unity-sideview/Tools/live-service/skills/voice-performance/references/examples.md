# 示例与验收

本文件的台词为原创测试文本，ID、能力和任务状态为测试夹具。例子不是实际检索结果、声音资源或已生成音频；真实执行须以宿主回执为准。

## 1. 一句话已经说明白

观众：“把‘我等了很久，你至少该告诉我一声’用生气但克制的语气配一下。”

正确流程：保留提供台词 → user_provided 脚本 → 未指定声线则读取当前音色 → 核对克制生气的表达能力 → 生成 → 检查 → 排队播放 → 实际结束后互动。无需先查这句出自哪部剧，也不能声称它就是某剧原台词。

只输出一段“愤怒台词”没有音频不算完成。情绪提示“不要喊叫”不能变成被念出的语句。

## 2. 只有一个梗

观众：“来段薛甄珠抓小三。”

本例只提供检索线索，不断言片段实际内容：

```json
{
  "request_id": "fixture-request-meme",
  "performance_id": null,
  "revision": 0,
  "action": "lookup_clip",
  "speech": "我先确认一下你说的是哪一段。",
  "data": {"query": "薛甄珠 抓小三 片段", "reason_code": "clip_unresolved"}
}
```

| 检索后的真实情况 | 正确下一步 |
| --- | --- |
| 来源明确且可读取片段 | 核对人物、范围与台词后准备脚本 |
| 原作与二创两个版本都合理 | 简短询问要哪个，不凭热度替换 |
| 只有搜索摘要或评论 | 继续读取来源；无法读取则说明，不能宣称得到完整原文 |
| 台词有一处听不清且影响含义 | 回听/核实，无法确认则询问，不补成“原话” |
| 观众说“按那个感觉编一小段就行” | adaptation/original，明确是改编，使用原创台词 |
| 搜索服务失败 | 说明当前无法核对；不能认定梗不存在 |

## 3. 原创双角色脚本

观众明确要求原创两句：“一个人抱怨等太久，另一个人认真道歉，用当前声音演就好。”

```json
{
  "script_id": "fixture-script-2",
  "revision": 0,
  "content_mode": "original",
  "source_refs": [],
  "scope": "两位角色各一句，表达不满后认真道歉",
  "roles": [
    {"role_id": "role-a", "name": "等待的人"},
    {"role_id": "role-b", "name": "迟到的人"}
  ],
  "segments": [
    {"segment_id": "seg-a", "order": 1, "role_id": "role-a", "spoken_text": "我等了很久，你至少该告诉我一声。", "emotion_intent": "生气但克制", "delivery_notes": ["重点放在至少", "不喊叫"], "pause_after_ms": 400, "source_anchor": {"type": "original", "source_id": "fixture-script-2"}},
    {"segment_id": "seg-b", "order": 2, "role_id": "role-b", "spoken_text": "对不起，是我没交代清楚，让你白等了。", "emotion_intent": "认真道歉", "delivery_notes": ["语气放软但保持清楚"], "pause_after_ms": 0, "source_anchor": {"type": "original", "source_id": "fixture-script-2"}}
  ]
}
```

两个角色都可以绑定同一个当前可用音色，以语气区分。若观众改为“两种不同声音”，而 inventory 只有一个可用声音，必须说明限制并等待接受替代，不能只写两个 role_id 就宣称双音色。

## 4. 声线与表演提示边界

| 要求/状态 | 正确行为 | 不合格行为 |
| --- | --- | --- |
| 指定声线确实可用 | 使用其真实接口 ID 和版本 | 因另一个声音更方便而静默替换 |
| 指定原演员，但清单没有对应声线 | 说明只能用现有声音演角色，可提供清单内选择 | 把演员名字当 voice_id，或擅自克隆 |
| 语音生成支持情绪但无具体动作资源 | 输出真实语音，明确省略对应动作 | 虚构表情/动作资源 ID |
| 没有词级时间戳 | 使用实际片段边界提示 | 按字数估算并称逐字精确同步 |
| 工具把“停顿”念出 | 检查失败，修正输入渠道后有限重试 | 把它当作可接受演绎完成 |

## 5. 实际结束后互动

假设 fixture-playback-2 已完整播放当前版本，尚无其他反馈：

```json
{
  "request_id": "fixture-request-2",
  "performance_id": "fixture-performance-2",
  "revision": 0,
  "action": "interact",
  "speech": "刚刚这种忍着火的感觉，是你想要的吗？",
  "data": {
    "bundle_id": "fixture-bundle-2",
    "playback_id": "fixture-playback-2",
    "completed_segment_ids": ["seg-a", "seg-b"],
    "requester": {"id": "fixture-player-2", "source": "player", "message_id": "fixture-message-2"},
    "feedback_ids": []
  }
}
```

工具仅返回音频生成结束时不能使用此输出，仍应编排/检查/排队。重复完成回执不重复问同一句；观众已要求“第二句再冷一点”时优先进入 revise。

## 6. 修改与重演

| 输入/事件 | 正确处理 |
| --- | --- |
| “再来一遍”，没有新要求 | replay 已验收 bundle，新 playback_id，不必重新合成 |
| “第二句再冷一点” | revision 递增，重做受影响片段；显式复用未改片段并重新编排时间轴 |
| 改版后旧任务音频才返回 | 丢弃旧结果，不覆盖新 bundle |
| 正在播放时要求立即停止 | 停止真实音频及关联提示，等实际停止后再接话 |
| 播到一半网络中断 | 按真实播放位置恢复或说明只能重播/结束，不能称已完整演完 |
| 表演期间日常音色被用户切换 | 不悄悄改已确认表演映射；结束后聊天使用最新日常配置 |

## 7. 验收

| 检查项 | 通过标准 | 验证层 |
| --- | --- | --- |
| 模糊片段 | 先定位，摘要/记忆不冒充核实台词 | 检索证据与模型决策 |
| 原文/改编 | content_mode、来源及删改边界真实一致 | 脚本审阅 |
| 台词与提示分离 | spoken_text 无意外舞台说明、角色标签或主持收尾 | 脚本与试听 |
| 角色与声线 | 每句绑定可用资源，角色不等于原演员声音 | 清单/请求与试听 |
| 情绪 | 能听出指定方向且不牺牲台词清晰度 | 人工/可用音频评估 |
| 完整结果 | 有可播放语音、对应脚本及真实可用提示或明确省略项 | 结果包检查 |
| 时间轴 | 时间来自实际音频/对齐，不伪造句内精度 | 时间记录与回放 |
| 主音轨互斥 | 播配音时没有额外主播聊天声音叠加 | 实际混音回放 |
| 完成事件 | 客户端完整播放结束才触发演后互动 | 事件回放 |
| 中断清理 | 旧音频、字幕/动作提示停止，主音轨释放 | 运行时回放 |
| 版本与重试 | 旧结果不覆盖新要求，重新合成后重新计算时标 | 运行时回放 |
| 重播与幂等 | 新播放实例可正常结束一次；同一回执不重复收尾 | 运行时回放 |
| 观众反应 | 不捏造反馈，不提前评价未播片段，不抢演绎音轨 | 事件交接与模型输出 |

结构校验不能替代真实音频和 demo 联调。本文件不宣称已完成声音服务接入、情绪效果测试或动作同步验证。
