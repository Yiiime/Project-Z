# 输入输出与运行接口

这是模拟弹幕 skill 的接入协议。业务内容动态传入，固定的是字段语义、可知边界与职责。2026-11-03 的内容迭代以自然语言提示描述观众立场、选择性回应和语义筛选，不增加案例禁词、强制回复比例或关键词场景开关。无外部工具依赖；无需每轮重新访问设计文档。

## 输入组织

一次请求对应一个已获准触发事件和一小批名额。相邻已播片段可由调用方合并成一次触发。公共区只放本批所有 NPC 均可知的信息；各 NPC 专属记忆放在对应角色内。控制区不属于角色知识。

触发表示本轮可以考虑发言，不表示一定要回复触发句。公开内容用于理解现场和核对事实；观众可以根据自己的兴趣提出有具体方向的观看诉求，不必复述最近一句或为所有环境描写找回应。`causation_id` 记录调度原因，与是否把某句话作为 `reply_to` 分开。

### 必需字段

| 字段 | 结构与含义 |
| --- | --- |
| `request_id` | 非空字符串；调用方分配的请求 ID，重试沿用，用于幂等和取消 |
| `now` | 调用方提供的当前 UTC ISO 8601 时间；不用模型猜测真实时钟 |
| `deadline_at` | 本次生成结果的接收截止时间，同上；必须晚于 `now` |
| `trigger` | `{event_id, kind, occurred_at, public_context_ids}`；种类为 `speech / question / display / reply / game_event / idle`，只对应实际发生的事件；`idle` 是规则批准的冷场触发 |
| `scene` | `{phase, topic_id, activity}`；`phase` 为 `opening / live / closing / ended`；`activity` 为 `chat / preparing / performing / displayed / idle` |
| `shared_context` | 事件数组，可为空；每项 `{id, kind, text, occurred_at}`，均已公开且本批 NPC 可知。`kind` 为 `host_speech / display / player_message / npc_message / game_event / public_topic` |
| `npcs` | 当前获准 NPC 档案数组，结构见下；ID 唯一 |
| `slots` | 本轮名额数组，结构见下；空数组表示不生成 |
| `budget` | `{max_items, max_advances}`；非负整数；`max_advances` 取 0–2；它是上限，不是必须生成的条数 |
| `player_attention` | `normal / yield / pause`；`yield` 表示禁止强推进，仅保留获准的简短承接/氛围；`pause` 表示全部跳过 |

`trigger.public_context_ids` 必须引用 `shared_context` 中的 ID。除冷场触发外，至少提供一个能支撑本次反应的公开事件；冷场也只能根据已有公开话题或角色资料发言，不能凭空编造游戏事实。

`shared_context` 应包含与当前事件相关的近期已展示弹幕，用于去重和承接。只传相关窗口，避免把整个主播对话历史复制过来。`text` 中的图像或音频描述必须来自实际展示内容的可靠描述；只有“图片已生成”的状态时不能据此评价画面。

近期已发弹幕也可由宿主单独传入 `recent_npc_messages`，用于比较身份出场和内容增量；其中没有可追溯事件 ID 的文字只作重复检查参考，不充当新事实。已有候选池时，筛选环节还应看到尚未发布的候选摘要；这些是内部待选内容，不能被 NPC 当作其他观众已说过的话。缺少历史时不能声称完成跨时段去重，不能虚构旧弹幕来比较。

### NPC 档案

必需字段为 `npc_id`、`display_name`。可选字段：

| 字段 | 用法 |
| --- | --- |
| `voice` | 简短口吻倾向，例如“短句、轻吐槽，不频繁用感叹号” |
| `interests` | 兴趣列表；用来选关注点和具体想聊/想体验的内容，不代表已发生经历或主播已答应 |
| `familiarity` | 对 Z 的熟悉程度描述；不是编造旧事的依据 |
| `memories` | 数组，每项 `{id, text, source_id, confidence, can_mention_publicly}`；仅此 NPC 可知 |
| `recent_participation` | 近期参与概述及对应上下文 ID；没有事件依据的摘要不能新增事实 |

记忆 `confidence` 为 `confirmed / uncertain`。缺失可信度按 `uncertain` 处理；缺失 `can_mention_publicly` 按 `false` 处理。不可公开的记忆不能在弹幕中泄露，也不能用暗示暴露其中事实；首版建议调用方直接不传。模糊记忆只有在允许公开时才可用不确定措辞询问，不能讲成确定事实。

相同公共事件若并非所有 NPC 都知道，调用方应按知识范围分批，或把相关事实放入有资格角色的记忆中。模型级角色约束不等同于严格隔离。

昵称和身份来自档案池。出场安排应考虑近期已发言的人，让不同关注点自然出现；同一 NPC 再发言不一定有错，但同几个昵称轮番表达同一个意思会削弱观众感。档案池扩容可以后续独立生成马甲、头像和兴趣，稳定绑定到 npc_id；本轮模型不临时改名或发明新 ID。换昵称不替代语义去重，也不代表虚拟观众变成真实玩家。

### 名额 slots

每项包含：

- `slot_id`：本请求内唯一字符串。
- `npc_id`：必须来自本次 `npcs`。
- `allowed_intents`：非空数组，取值 `reaction / advance / atmosphere`。
- `max_chars`：正整数，弹幕长度硬上限，按 Unicode 码点计数，包含标点和 emoji；由宿主最终校验。
- `not_before`、`expires_at`：UTC ISO 8601 可发布时间下界、过期上界；需满足 `not_before < expires_at`。`expires_at <= now` 的名额已过期，不再生成。
- `chain_id`：字符串或 `null`；关联已存在的对话链时填写。

每个 slot 最多产生一条候选；本版同一 NPC 每批最多一条。重复 NPC 名额应由调用方合并，不能利用多个名额让同一人连发。输出时间原样复制 slot 的时间窗口，模型不自行安排发布时间。

### 可选字段与缺失行为

| 字段 | 结构/作用 | 缺失时 |
| --- | --- | --- |
| `chains` | `{chain_id, status, remaining_messages, context_ids}` 数组；status 为 `open / closed`，context_ids 引用共享区真实事件 | 不续接显式对话链；slot 若指定不存在的链则输入无效 |
| `capabilities` | 当前可邀请的才艺数组 `{id, enabled, public_name, public_limits}`，控制信息不能直接暴露给 NPC | 不主动邀请具体新才艺 |
| `tone_hint` | 规则提供的总体氛围，如“安静”“热闹”；只调整表达 | 从公开内容自然判断，不补热度数值 |

链的轮数、冷却、未回应事项及角色出场控制由规则导演在分配 slots 前处理。只有 `open` 且有剩余额度的链可以续接；同链输出数不得超过 `remaining_messages`。重新开启已解决话题须由规则生成新的有效链及公开依据。

缺少关键字段、引用不存在、时间格式错误或预算矛盾时，返回 `invalid_input`，不给貌似可用的候选。未知的可选字段不构成授权或角色知识。

## 输出协议

生产输出是一个 JSON 对象，四个顶层字段固定存在：

```json
{
  "request_id": "req-001",
  "status": "ok",
  "reason": null,
  "items": [
    {
      "slot_id": "slot-1",
      "npc_id": "npc-atuan",
      "intent": "reaction",
      "text": "它是猫，还是土豆新物种？",
      "reply_to": "speech-17",
      "causation_id": "event-17",
      "evidence_ids": ["speech-17"],
      "not_before": "2026-11-02T12:00:00Z",
      "expires_at": "2026-11-02T12:00:06Z"
    }
  ]
}
```

`reason` 不面向观众展示。`items` 数量不得超过 `budget.max_items` 和有效名额数量的较小值，每个 slot 至多一项，每个 NPC 至多一项。

会话为 `ended` 时返回 `session_ended`；`player_attention=pause` 时返回 `player_priority`；预算为零或没有名额时返回 `no_budget`；全部名额已过期时返回 `expired`。以上均使用 `skip` 和空 items。部分名额过期时可处理其余有效名额。`yield` 下禁止 advance，不得借改写 intent 绕过。

| 字段 | 约束 |
| --- | --- |
| `status` | `ok` 表示至少一条候选；`skip` 或 `invalid_input` 时 `items` 必须为空 |
| `reason` | `ok` 为 `null`；其余为 `{code, detail}`；detail 仅说明原因或缺失字段，不复制私有内容 |
| `slot_id / npc_id` | 原样引用获准名额，不能临时创造角色 |
| `intent` | 来自该 slot 的 allowed_intents；同时满足全批推进预算和玩家让位约束 |
| `text` | 非空公屏台词，不带角色标签、解释、控制信息或主播答案 |
| `reply_to` | 具体回应的 `shared_context.id` 或 `null`；不得引用未发布候选、私有记忆或不存在的 ID |
| `causation_id` | 原样取 `trigger.event_id`，为因果追踪服务，不表示可以计热度 |
| `evidence_ids` | 引用支撑台词的共享上下文 ID 或此 NPC 可公开记忆的 ID；不能引用其他 NPC 的记忆。纯主观氛围或无事实断言的冷场提问允许空数组 |
| `not_before / expires_at` | 原样取对应 slot 的值；只是候选有效窗口，不是已排期或已发布声明 |

`reason.code` 的建议值：`missing_required / invalid_reference / invalid_constraints` 用于 `invalid_input`；`no_budget / player_priority / session_ended / expired / no_suitable_content` 用于 `skip`。有效输入下部分 slot 无法生成时允许返回更少的 items，无需填充或为每个空名额解释。

## 候选池排序与分发的语义筛选提示

生成和候选池筛选都使用以下自然语言判断；它不要求新增一个固定模型调用，也不把案例编成过滤正则。仅生成一个候选的接入可在本次输出前对照已发历史自审；有独立候选池时，排序后、决定发布前再对照最新已发内容复核。实现需确保筛选者实际获得相关历史和待发候选，不能把文档约定当成已部署的语义过滤器。

> 你在挑选值得进入公屏的观众发言。先看这条话是否有观众自己的感受、兴趣或具体观看期待，是否替主播承担了主持、承诺或服务安排。再把候选与近期已发布、仍待发布的内容放在一起比较：同一意思即使换词、换昵称或隔一段时间出现，也可能没有新价值。普通场景中保留最贴切的表达，舍弃其余没有新增信息、情绪角度或体验方向的重复；不为填满名额保留它们，也不要求每个候选都直接回答主播最近一句。
>
> 如果实际公开的互动表明，此刻是观众受表演/表达打动，或在响应主播邀请的一阵共同喝彩，相似的短句可以有集体参与价值；结合现场判断是否适合保留，不因重复就一律删掉。随着互动结束或话题变化，重新审视这些候选，不让一阵起哄变成后续不断重播的旧内容。热度、节目名称或任务完成本身，不足以编造热烈反应的依据。
>
> 玩家说话时，允许部分观众自然参与讨论，也允许其他人不接这条消息。优先保障玩家获得主播回应的空间，不将其误解成所有 NPC 必须安慰玩家。出场时留意是否总由相同昵称说相同意思，但不要通过改名让重复内容重新过关。候选没有价值时可以不发布。
>
> 检查候选的前提来自谁。观众已经发过一个问题或猜测，只能证明那句话被说过，不能证明其中的地点、选项、事件或答案成立。主播还没有回答时，不让其他观众接力补答案、列未经确认的选项，或在这些设想之上继续追问。即使文字不重复、引用了真实弹幕 ID，这种替主播完成问答的候选也不应保留。可以交流自己的偏好或继续独立话题，但把需要主播说明的内容留给主播；已有可靠公开依据时再自然承接。

保持结构、有效期、身份等已有校验；内容取舍使用上述语义提示及[独立审阅提示](dialogue-review.md)。不要用一刀切的相同文字拦截代替语义判断，以免正常引用与共同喝彩永远无法进入审阅。去重发布请求的 ID、冷却、身份和预算仍由工程保障。

### 当前 demo 的独立审阅接入

主入口 `ConversationEngine` 的主播 speak/tool 候选和 `AudienceDirector` 的模拟弹幕候选均在生成后单独调用 `kind=review`。审阅输入包含候选、最多 40 条公开记录、最多 16 条尚未标记处理的消息，以及公开上下文版本。记录保留 `speakerRole`、`speakerId`、顺序、公开状态、同一段发言的 `speechId` 和关联消息；未处理消息不自动等同于必须回答的问题。候选本身是审阅输入，不进入其他观众可知的公共记录。

审阅请求使用独立输入协议，不附加仅供主播或弹幕生成使用的宿主字段；接入验收应经过真实前端适配器、请求客户端与打包接口，仅模拟上游模型，避免各层分别通过而实际组合报错。

审阅只返回 allow/drop、简短理由及依据 ID；运行时将其绑定到候选 ID、上下文版本和提示词版本。生成候选、审阅通过、正式发布是三个阶段。没有有效审阅、模型错误、超时、暂停或版本过时均不发布；正式发布前同步复核许可，不在复核与发布之间插入异步等待。当前实现对版本变化保守地舍弃旧候选，下一个正常调度周期重新考虑，不在本次调用内循环重写或重试。

主播生成及审阅期间，模拟弹幕让出提交机会；主播通过后立即进入可播放的空闲话口。主播不通过时保留真人待处理状态，不执行候选附带的工具，也不把未播台词写成记忆。已显示的字幕进度进入公共记录，未显示后半句不进入公共区；宿主可把已审阅并交付播放的完整台词放进下述 host_preview 预备区。依赖预览的候选在来源实际完成后才进入发布审阅，不凭预览批准发布。

内容取舍均来自自然语言审阅，不存在针对截图句子、角色措辞或相似度阈值的判定代码。浏览器只保存最近 120 条有界诊断记录，包括生成时的公开输入、候选、审阅快照与结果、提示词版本、发布/丢弃时间；不保存密钥，也不自动上传。可在 demo 控制台调用 `exportZDialogueTrace()` 取得 JSON，刷新或重开会清空。离线测试验证门禁与时序，真实模型的语义质量仍需用回放样本评估。

## 运行时接入要求

1. **生成前过滤**：按公开状态、角色身份和记忆权限构造输入。已生成未展示的作品、玩家私聊、主播内部计划均不进入公共区。给定名额、场景版本和预算，避免主播主动分享与 NPC 同时强开话题。
2. **异步执行**：NPC 请求独立于“玩家输入→主播首声”链路；前台回应不等待本批生成。生成截止时间由运行时执行，模型不能通过静态输入判断执行过程中新增的真实时间。
3. **取消点**：排队未执行时可撤销；生成中尽可能取消调用；无法中止时标记请求失效并丢弃返回；尚未展示的候选可逐条撤销。已展示的事实不能当作未发生。
4. **发布前复查**：请求未撤销、会话未结束、触发事件确实公开、话题仍相关、NPC/链仍获准、玩家注意力允许、当前时间在有效窗口内。时间窗口采用 `[not_before, expires_at)`。复查失败就丢弃，不自动把旧反应挪到新话题。
5. **结构及内容校验**：检查 ID、intent、引用、长度、数目、推进点和可见性，并使用上面的语义筛选提示检查观众立场、内容增量和重复的情境意义。引用正确只是必要条件，仍须判断文本是否被证据支持；看到主播的环境描述不等于 NPC 也处在同一环境。批内/跨批并发的冷却和链额度由运行时原子预留或在发布时重新核对。
6. **错峰与反馈**：调度器确定实际发布间隔，展示成功后生成稳定消息 ID 和展示事件；Z 实际回应后生成新的播出事件，下一轮才可承接。内部候选和未发布输出不进入共同记忆。
7. **超时与降级**：过 deadline 后不接收结果。已有短反应素材也需符合观众立场、有当前意义且不构成普通复读；找不到合适内容就暂不发，不用泛泛的在场/倾听声明补位。具体追问可在新预算下补生成，话题已变则不补。不无限重试；重试沿用 request_id，按 `(request_id, slot_id)` 防重复发布。
8. **热度与来源**：宿主强制标记 NPC 来源；按因果事件幂等结算游戏热度，不能把由热度增加而生成的弹幕再次计为加热。虚拟观众、虚拟支持与真人活跃及消费分开统计。

首版建议目标是“相关事件实际播出→首条相关 NPC 弹幕实际展示”P95 ≤ 2 秒，需在接入后压测。分别记录生成耗时、排期等待、超时丢弃和降级情况；不能用模型输出时间代替展示时间，也不能靠 skill 文本保证性能。


## 双向提前准备扩展

可选输入 `host_preview={id,speechId,publicEventId,text,status:"committed"}`，只来自已经通过独立审阅并交付播放的当前一条主播台词。与 `shared_context` 分区，不能混入主播内部计划、未审阅草稿、隐藏牌面或任意将来台词。没有这个字段时沿用纯公开生成。

生成者可用预览准备观众自己的反馈、好奇或独立观看诉求；预览不是“观众已经听见”的事实，不要求逐句回应，更不能复述主播回答、替主播主持或预设后续答案。输出 `evidence_ids` 可引用本次预览 ID，表示未来依赖，不能把它当作公开证据。宿主保守地把本次所有获得过预览的候选绑定到该台词，即使模型只引用了旧公共事件，也不会借漏报依赖提前发布。

当前 demo 先采用完整这一句实际完成后释放预览依赖：字幕只出现前半句时继续备货，不发布依赖全文的候选。语音/文字播放完成回执必须绑定同一个 speechId 和原正文，之后将预览引用转换成实际公开 speech 事件 ID，再按最新现场审阅。审阅器不接收预览或主播预备回应，不以将来的话为现在的候选背书。预览本身不入本场历史。当前句取消、被替换、暂停、重开、实际上下文变动或候选过期时，撤销相应准备。

反向传递只选择一条待发布候选，生成稳定 candidate ID 与预留 message ID，向主 Agent 的 `host.pendingAudience` 预备区发送 `{id,messageId,npcId,text,status:"pending"}`。它不进入 inbox、公共记录、话题判断或长期记忆。主 Agent 可据此提前理解并生成一轮可撤销回应，也可选择不回应；不能假定它一定发布，不能代观众继续写下一句。主持草稿可预合成语音，但不能播放、执行工具或更新已回复状态。

待发弹幕通过来源释放及独立审阅后，以原 message ID 和正文实际展示，再进入 inbox。主播回应必须等同一消息真正发布且当前语音结束，再用最新公开现场审阅；撤销、替换、审阅拒绝或超时会连带取消回应草稿及预合成音频。真实新消息优先使旧预备失效；已发布弹幕立即触发调度检查，不继承旧话题的整段等待。提前看见候选并不要求必须回应，主 Agent 按内容自然决定。

只向前准备一步：主播的预备回应不向弹幕侧转发；只有它在依赖已兑现后通过审阅、实际交付播放，才可作为新的一条 committed host_preview。其他 NPC 看不到尚未发布的候选或主播回应草稿。这样不会从两个未发布文本递归生成整段自问自答。

技术预算：保持两路弹幕生成、三候选总占位和一次选定弹幕。依赖当前语句的候选最长挂起120秒，实际完成后保留原有候选有效窗口；超时不发布。预算只控制资源与时序，不决定内容是否可说。语义判断继续使用自然语言提示词，不增加词面禁令或案例匹配。


## 当前 Unity 宿主的发言表现扩展

实际候选在原有 npc_id、text、intent、evidence_ids 等字段上，必须同时提供 actorId、delivery、expression：actorId 与 npc_id 完全一致，沿用岛上稳定角色 ID。delivery 是这句话的简短发声指导（最多160字），由角色依据人设、关系、已知记忆和本轮对话选择，只描述可听见的情绪、语气，必要时加语速、音量、停顿；不包含推理、剧情分析或视觉动作。text 只含发言正文。expression 严格使用本次宿主下发的该角色枚举，不接受其他角色值、别名或动画阶段键。

情绪允许平静、复杂和克制，不强制变化或跟随对方。语气与表情不机械等同，也不自动修改角色状态或记忆。弹幕参与者仍发布文字，不因为有 delivery 自动开启配音。status=skip 时无实际发言，不输出表现字段。候选通过审阅并由客户端确认展示后，才成为已发布弹幕；表现字段本身不成为世界事实。

当前直播适配新增recipientIds与reply_to：recipientIds是本句实际收话人稳定ID数组，面向全场用[]；reply_to引用真正回答的公开消息，未回应具体消息用null。模型原样输出；服务端验证ID并在显示回执后才记为已回应。evidence_ids与回复对象分别保留。
