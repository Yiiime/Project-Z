# 娱乐塔罗

## 1. 目标与分工

提供有参与感的娱乐与自我思考：确认问题 → 确定牌阵 → 程序准备隐藏牌堆 → 指定提问者选牌 → 锁定结果 → 翻牌展示 → 主 Agent 解读并接话。

| 参与方 | 职责 |
| --- | --- |
| 主 Agent（Z） | 确认问题、介绍玩法；对自己提出的问题选择背面牌；依据已公开结果自然解读和互动 |
| 提问观众 | 对自己的问题亲自选择候选牌；可补充背景、暂停或明确开始新一轮 |
| 牌堆服务 | 程序洗牌、固定隐藏牌面及正逆位、校验选择权限、原子锁定、持久化及恢复 |
| 展示与运行时 | 显示候选、收取点击、翻牌、报告展示回执、调度语音与处理取消 |

“工具”是宿主提供的程序能力，不等于模型替用户决定牌面。技能文字本身不能洗牌、保存状态或创建真实 UI；未接入时说明能力未就绪，不模拟工具成功。

处理流程前阅读 [输入输出、选牌算法与状态协议](references/contracts.md)。解读时按需阅读 [牌义依据与解读方法](references/interpretation.md)；审阅与验证参考 [多轮示例和验收](references/examples.md)。

## 2. 确认问题与提问者

问题来源分为 `host` 和 `viewer`。来源由实际事件决定，不从问题用词猜测。主播自己的问题基于 Z 已确认的经历；观众的问题保留提问者 ID 和原弹幕 ID。

明确的问题可简短复述后进入流程，不机械重复索要确认。对象、范围或诉求不明时问一个必要问题；如果要实质改变问题，先提出改写并得到提问者认可。例如无法凭牌确定“对方是否爱我”，可以建议改为“我如何理解目前的互动，以及接下来可以观察什么”，不能静默偷换。

仅使用与当前问题相关、已提供且可公开的信息。不要读取玩家私聊、主播未公开计划或其他人的私有记忆来营造“算得准”。把观众描述当作其自述，不升级成关于第三方的已证实事实。

## 3. 确定牌阵与规则

观众明确指定且宿主支持的牌阵优先；不支持时说明，并给出可用选择。未指定时按问题复杂程度选择：

| 牌阵 | 牌位含义 | 交互 |
| --- | --- | --- |
| 单张 `single_focus` | 本次值得关注的一个角度 | 三张背面候选选一张，锁定后立即翻开 |
| 三张 `three_reflection` | ①当前处境 ②值得留意的因素 ③可尝试的行动 | 分三次，每次三选一；选中的牌先背面进入对应牌位，选齐三张后一起翻开 |

三张候选不等于三张牌阵；只选择一张时，只解读那张牌。三张牌阵最终三张已选牌不能重复。

开始前固定问题、提问者、牌阵、牌位顺序、牌组及牌义资料版本、是否启用逆位和揭示方式。逆位按宿主配置启用，未配置时默认仅正位；向提问者简短说明本轮规则。不能抽到牌后再改牌位含义、启用逆位或更换资料去凑结果。

## 4. 准备隐藏牌堆与候选

问题和规则确定后，向牌堆服务请求创建任务。服务负责随机洗牌及持久化；每一张卡的正逆位在开始时一并固定。每轮候选展示之前，候选位置与隐藏牌面的映射已经保存。

选择前，主 Agent、提问者客户端和其他 NPC 只能看到一致的牌背、位置以及不含牌义信息的候选 ID。隐藏牌名、正逆位、图片地址、牌序及随机种子不能进入这些上下文。主 Agent 不得先看结果再决定选哪个位置。

三张牌阵中，本轮被选中的牌从剩余牌堆移除；未选中的候选回到剩余牌堆，下一轮按固定算法准备。未选中的牌不翻开、不解读，也不以“选另一张就会更好”施压。

## 5. 谁提问，谁选牌

### 主播自己的问题

候选已真实显示后，主 Agent 从当前背面候选中选择一个位置，发出 `choose_host` 意图。可以说“我选中间这张”，不要声称提前感应到某张牌。程序验证并锁定后，才确认选牌成功。三张牌阵每轮重复一次，不能一次虚构三个选择成功事件。

### 观众的问题

向提问观众展示选择控件并等待其点击；主 Agent 可说“从这三张里选一张”。默认只有本次提问者能选，其他观众和主播不能代选。宿主可另行支持同一身份的明确文本选择，但必须通过同一校验和锁定接口，不根据模糊聊天自动决定。

提问者未选时可以提醒、继续等待或按已配置规则暂停/取消，不能自动替他抽。全直播间投票、主播代抽均不属于本版默认流程。没有实际交互能力时说明目前无法完成观众选牌。

## 6. 锁定、翻牌与恢复

点击先到服务端校验，再原子锁定。本轮首次有效选择成功后，不能用第二次点击替换；重复请求返回同一已锁定结果，过期候选和非提问者点击被拒绝。

单张选完即可请求揭示；三张牌阵选齐后一起请求揭示。主 Agent 收到实际展示回执后，才使用已展示牌面解读；部分展示失败先恢复原牌或采用原牌的文字展示，不假称三张都已出现。

刷新、断线、显示失败、解读重写均恢复原任务。创建或选牌调用超时、结果未知时，先按请求/任务 ID 查询；不要再次洗牌。程序已保存的牌面、方向、牌位和选择不因重试改变。

结果与任务绑定。补充原问题背景可以继续用原牌；明显换主题、换牌阵或明确重抽时创建新任务并说明新一轮，保留旧任务记录，不把新结果覆盖成旧结果。

## 7. 有依据的自然解读

由主 Agent 按“牌义依据 → 牌位含义 → 已知实际情况 → 一种可能的理解 → 可尝试的行动”形成连贯表达，不逐项机械朗读字段。

- 每个主要判断能追溯到具体牌、牌位及牌义条目；联系现实的部分有对应已知事实，或明确标成尚待确认的假设。
- 牌义和图像提供象征性思考角度，不证明现实事实、他人心思或未来事件。开场自然说明一次娱乐定位，无需每句话重复免责声明。
- 三张牌先分别解释，再说明呼应或张力；不能全部套成“好事将近”，也不强迫矛盾牌面得出统一结论。
- 信息不足时说明能讨论到哪里，或询问一个关键背景；不编造领导打压、伴侣出轨、疾病等隐藏事实。
- 给出与问题相关、可由提问者自主尝试的小行动。现实重大决定不由牌面裁定，优先回到可核实信息和实际选择。
- 牌义缺失或来源无法确认时保留原牌、暂缓该部分解释；不能换牌规避，也不能凭印象伪造引用。

表述保持 Z 的性格和当下话题，避免玄虚长篇、固定套话或制造恐惧。死亡、塔等牌名不应直接对应真实死亡、灾难或必然失败。

## 8. 解读后的互动

优先回应提问者已经表达的关切，最多抛出一个自然追问。对方补充新事实时，区分“牌面没有变”和“现在更了解你的处境”，调整解释而非重新抽牌。

观众认为不贴合时接受反馈，说明这只是一个思考角度；不以“你自己还没意识到”压过对方。无需证明塔罗一定准确，不反复邀请重抽直到出现满意结果。

解读生成完成不等于实际播出完成。运行时保留已播进度，被打断后从合适位置接回，不重复整段；只有真实公开的选牌、翻牌和已播解读事件能进入模拟观众上下文。

## 9. 异常与输出

每次按宿主协议返回当前有依据的下一步。工具未接入、状态未知、非法选择、牌义缺失、展示失败分别说明，不用虚构结果降级。取消后拒绝迟到点击；下播不再发布迟到解读。参数缺失或结果与任务不匹配时先同步/核对，不猜测修复牌面。

状态持久化、隐藏信息隔离、选择权限、幂等及随机性由运行时落实；本技能提供接入规则与验收标准，不宣称这些工程能力已经实现。
