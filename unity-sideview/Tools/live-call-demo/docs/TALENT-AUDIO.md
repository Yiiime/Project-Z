# 演绎与预制清唱执行链路

主 Agent 通过 start_performance / start_singing 自主发起，通过 finish_activity 结束或取消，通过 replay_talent 重播刚完成的同一音频；没有固定节目或自动连续播放。工具经过后端参数校验及前端实际状态校验。

## 单声线演绎

开启声音按钮并连接原有 Vivi 2.0 TTS 后可用。脚本支持 original 或 user_provided；后一种必须引用当前真人消息，并按原消息顺序使用原文。尚不支持原片检索、ASR 转写、多音色、克隆或任意情绪效果。

每次 1–6 段，每段最多 160 字、总计最多 600 字；pauseAfterMs 为 0–2000 毫秒。整段音频最长 180 秒，准备总超时 120 秒，每段沿用原 TTS 超时。这些是执行资源预算。修改内容创建新任务，旧任务先结束；同任务重演复用缓存，不重新合成。

2026-11-02 真实主 Agent 决策验证：温柔安慰的“加班后留灯”和悬疑侦探的“门后有人”分别返回 start_performance，生成不同原创台词、分段情绪、动作与停顿，记录位于 output/performance-variation-check.json。该检查仅验证真实模型的脚本决策，没有重新合成 TTS 或验证哭腔、耳语等听感。Live2D 的八种 mood 在当前 TTS 适配中映射到 happy / warm / serious / thinking 四种语气。

绘画已升级为动态结构化矢量生成与对象局部补丁，沿用 simple-drawing skill 和按需画板。详见 [自主主持与才艺](AUTONOMOUS-TALENTS.md)。

主 Agent 现在可能同时产出分段脚本，host 请求的服务端时限为 20 秒、客户端总时限为 24 秒；其他请求沿用原时限。新真人消息仍取消过时决策，不强行等待旧脚本。

台词 text 与 mood / gesture / pauseAfterMs 分离。只将台词提交原 /api/tts；情绪提示、语速适配沿用原实现，不新增供应商参数。每段绑定当前 Vivi 声线。字幕在真实片段边界完整展示，嘴型仍为音频能量驱动，不声称逐字口型对齐。

准备阶段核对解码、时长、非静音、供应商字幕与台词一致性、片段顺序和动作资源。供应商字幕不是独立 ASR，演技、自然度与音量一致性尚未做独立听感验收；不把这些项目写成已通过。缺字幕或内容不一致时拒绝播放并返回 transcript_unverified。失败不会转成文字播放成功，也不自动重试付费请求。

## 预制曲库素材交接

ui/talent-config.js 中 TALENT_CATALOG.songs 仅保留《晚安》（颜人中歌曲版本）的 Vivi 2.0 清唱第一段完整副歌，约 32.28 秒。2026-11-02 用户试听后明确接受并要求入库；docs/reviews/wanan-vivi2.json 保存人工验收依据及文件哈希。直接使用原候选音频，未裁切或重新生成。

主 Agent 在每轮可见 songLibrary 中取得准确 songId、版本和片段，自主决定是否演唱。曲库有一首歌不代表固定节目或定时重播；播放结束由真实 onended 唤醒主 Agent，自然接话并收束任务。空库、未知曲目、缺文件、解码错误或静音文件都不能成功播放。

后续提供 MP3 / WAV 文件、歌名、版本、准确片段范围及对应歌词。试听确认是认可的 Z 歌声音色、单人无伴奏、旋律与歌词正确、开头和结尾完整。每个条目对应一段已经定位的完整音频，不在线随意裁切。

文件放入 ui/audio/songs/，在 ui/talent-config.js 加入类似记录（仅字段示例，不是已验收素材）：

```js
{
  id: 'song-version-chorus',
  title: '真实歌名',
  version: '具体录音版本',
  section: '第一段完整副歌',
  src: '/audio/songs/song-version-chorus.mp3',
  voiceIdentity: 'z-vivi',
  voiceVersion: 1,
  aCappella: true,
  approved: true,
  reviewRef: '实际试听记录，含歌词、旋律、音色、无伴奏、结尾检查',
  sha256: '文件实际 SHA-256'
}
```

仅验收后才填写 approved: true；sha256 绑定本次验收文件，更换文件必须重新验收。voiceIdentity / voiceVersion 表示已确认与 Z 日常声音身份一致，不代表普通 Vivi TTS 自带唱歌能力。当前最多 30 个条目、单文件 12 MiB、总音频 32 MiB、单段 180 秒以内。超出时扩展存储或播放方案，不静默截短。

运行 node scripts/build-site.mjs 后，只有清单中的已验收音频被打包到 /audio/songs/ 白名单路由；不会公开其他文件，禁止符号链接、远程 URL 和路径穿越。修改曲库后重建并重启 demo。歌名、版本和范围作为主 Agent 可选资源；模型只能传 songId，不能生成音频地址。

## 播放、取消与接话

preparing → ready → starting → playing → completed；也可能 interrupted / failed。开始前再次检查声音、音色身份和版本；静音或音量为零会停止当前才艺。页面暂停或切后台保留播放位置，恢复时接着播；停止按钮可直接取消，普通弹幕由主 Agent 判断。

准备期间允许聊天，音频准备完后在当前话语结束的边界取得唯一人声音轨。播放中主 Agent 只能等待，或按真人明确停止要求先取消再说话；普通聊天不会抢占声音。结束和失败后唤醒主 Agent，由它安排反馈、收起或下一步。

任务、产物、播放实例各有独立 ID；仅当前 AudioBufferSource 的真实 onended 能产生 completed。取消、静音、失败、旧结果、重复回调不能冒充成功。中断保留实际播放位置；重播使用新 playbackId。完成音频保留到该任务结束，重开页面不恢复旧节目。

当前没有独立 BGM 混音轨，因此没有新增配乐。歌声文件本身必须无伴奏。

## Live2D 实际能力

当前仍是 Haru 示例模型。live2d-config.js 有 8 种情绪姿态：自然、开心、温柔、认真、思考、害羞、低落、惊讶。

live2d-actions.js 共 28 个条目：16 个允许自动调用的动作、自然待机 none、5 个待标定候选动作、6 个原始样例片段。自动动作包括双手展开、掩嘴、摊掌、挥手、托腮思考、点头、摇头、侧头、倾身、强调、低头看牌替代动作、举掌、抱臂、放下手臂、突然惊讶和惊喜发现。

日常聊天和演绎都由主 Agent 选择这 8 种情绪姿态及 16 个已标定动作，也可选择 none，只换表情、不做手势。聊天不再固定用 explain 映射动作。host 返回 mood、gesture、transition（smooth / sudden）；默认平滑衔接，随实际语音或文字播放开始，突发反应可由 Agent 显式选择 sudden。

主 Agent 收到带中文含义的动作清单及最近六轮已发往播放层的表现选择 recentExpressions。保持情绪连续、避免重复、允许留白等自然表现要求在主持提示中，不在代码里按关键词、固定比例或动作列表循环。历史不是实际模型渲染的证明；播放层仍遵守重复动作冷却、暂停及轻柔动画设置，省略动作时不会自动换成另一个。等待不额外派发动作，也不抢占才艺形象。

资源中有更多条目不代表全部允许自动使用；没有新增模型、贴图或任意舞蹈能力。

## 验证

离线测试覆盖参数与状态、原文来源、不可用音频、整段准备、片段动作、音轨互斥、真实结束、重复回执、暂停续播、旧 resume 竞争、停止和重置、重演缓存、空曲库、缺文件和验收哈希。

浏览器使用合成提示音验证真实 Web Audio 解码、字幕与 Live2D、结束回执；测试音频不进入正式曲库。这些验证不等于真实 TTS 演技或清唱素材的听感验收。
