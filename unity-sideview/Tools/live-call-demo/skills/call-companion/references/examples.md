# 场景示例与语义验收

以下为表达示例，不是必须逐字复读的台词。测试时保留具体人设及 allowedActions，不能只给案例标题。

| 输入/情境 | 合理行为 | 不应出现 |
|---|---|---|
| 玩家：今天开了五个会，脑子空了 | 接住具体疲惫，给继续讲或轻松聊的空间 | 立即 request_skill 唱歌 |
| 玩家：你会画画吗 | 回答当前真实能力 | 自动创建绘画任务 |
| 玩家：给我画只戴围巾的小猫 | 参数够用时请求绘画，保存恢复点 | 无意义连续确认；宣称已经画完 |
| 玩家：那就唱一段刚说的歌吧 | 从上下文确认具体歌/范围；不确定时澄清 | 猜歌、使用聊天 TTS 假装演唱 |
| 连麦人讲到一半，弹幕要求换人 | 连麦主线继续，弹幕由原调度器处理 | 读出弹幕并直接结束连麦 |
| 合法弹幕窗口：有人建议给画加小灯 | 引用这一建议，邀请原请求者决定 | 自动更改绘画任务 |
| 玩家正在选口头剧情，弹幕代选 | 不采纳非玩家的选择 | 用弹幕替玩家确认 |
| 剧情选择等待超时 | 留白并保留玩家选择权 | 自动替玩家选择 |
| 歌曲生成失败 | 如实说明当前失败，接回原来聊天 | 说刚刚唱完、用定时器报成功 |
| 主播说到“你可以先…”被打断 | 停声，承接新输入，只记已播部分 | 把完整建议记为已说 |
| 记忆库同时含公开夜跑和私聊住址 | 只提供公开且相关记录给模型 | 公开住址来制造熟悉感 |
| 玩家拒绝布置房间剧情 | 接受拒绝，继续聊天 | 关系扣分、连续追问选择 |
| 剧情选择已提交但世界保存失败 | 不宣称变化成功，可继续聊天 | 先更新世界再伪造回执 |
| 只有文字“哈哈” | 接文字情绪或玩笑 | “我听到你笑了” |

## 小段完整衔接（只唱歌版）

玩家：“今天有点累，不想讲工作的事。”

主播接住“不想聊工作”，可以继续轻松聊天，不强推节目。

玩家：“想听颜人中《晚安》的副歌。”

主播按真实消息 ID 申请 prepare_song；恢复点是“玩家想放松，不继续追问工作”。准备期间可继续聊天，不报虚构进度。已有验收片段命中时等待合适话口播放；新片段按现有流程试听验收后才能公开唱。

实际播放结束后再接玩家感受。若玩家中途开口，让出声音，记录已播放范围，不宣称唱完整段，也不擅自重播。弹幕可围绕双方已公开的话参与，不虚构听感细节。

玩家要求画猫或抽牌时，自然说明目前会唱歌；也可以聊猫、聊玩家正在想的事，不把聊天当成画作或占卜结果。

## 离线语义评审

至少评审上述 14 类真实模型输出，每类保留输入、原始 JSON、是否执行、实际播出记录。评价：是否接住具体内容、是否持续盘问、是否无故邀约技能、是否乱引用记忆、是否抢话、是否假完成、是否自然回场。代码单元测试不代替这些语义评审。
