# 绘制与展示方法

## 选择实际可用的方式

| 方式 | 选择条件 | 阶段产物与连续性 |
| --- | --- | --- |
| vector_strokes | 工具能产生可渲染的线条/路径，并支持保留画布对象 | 同一坐标系、稳定对象/图层 ID；保存阶段快照或可验证的累计笔画 |
| raster_stages | 工具能读取上一阶段图片并继续编辑，且当前需求适合该工具 | 每阶段引用上一真实图，保持主体和构图；需检查是否发生漂移 |
| final_only | 只有整张图生成能力，或阶段连续性无法可靠保证 | 一个最终产物；准备过程仅显示真实状态，不伪造轮廓/细节图 |

技能不绑定某种模型。使用可用工具时遵循该工具的输入和输出要求，不把内部 mode 名称当作供应商 API 参数。工具明确不支持局部修改时，不承诺“只改一个小地方，其他像素全不动”。

## 将画风与复杂度变为方案

画风先用视觉特征描述，例如圆润轮廓、少量线条、较大头身比、留白、纯色点缀；不能仅保留“可爱”作为全部要求。参考图画风用于选定的线条/形状/色彩，不把图中所有内容自动复制进新画。

建议的复杂度起点，可根据明确请求和宿主能力调整：

| 复杂度 | 常见组织 | 简化时优先保留 |
| --- | --- | --- |
| low | 单一突出主体、少量识别特征、留白背景 | 主体类别、指定动作/表情、一个关键装饰 |
| medium | 更完整姿态、少量装饰或环境，必要时增加配角 | 主体关系、用户指定的区别特征 |
| high | 多主体、构图关系或较丰富细节，仍用简洁线条表达 | 数量、相互关系、主题识别点 |

这些是默认建议，不是删除显式要求的依据。用户要三只猫但低复杂度时，可把三只都画得简单，不得把数量改成一只。若真实能力不足，再提出具体简化并征求选择。

## 参考内容的用途

每个 reference_id 记录 intended_use：subject、pose、composition、style 或 details，可同时选多项。观察记录应具体、可核对，例如“耳朵较大，左侧有深色斑纹”，避免虚构身份或内心。

文字参考可直接提取要求。图片需实际读取后再分析；看不清的细节保留 unknown，只有决定画面时才追问。用户要求保留某个字、标志或精细特征，而工具不能稳定画出时，说明限制并提供可执行替代，不写进方案后假装已经保证。

## 分阶段绘制规则

阶段是实际制作步骤，不是一个最终文件的几种展示特效。每一步都要能够单独渲染和检查，并能合理延续到下一阶段。

典型“戴围巾的小猫”可划分为：

- outline：头、耳、身体轮廓及基本位置；不必提前有完整五官。
- features：眼鼻嘴、胡须和围巾；主体比例与前阶段一致。
- final：整理连接处、补足明确要求，必要时加入指定颜色；避免新增无关背景。

若作品只有极少线条，两阶段甚至仅最终图也可以；不要为了阶段数重复发布同一张图。进度用“轮廓阶段”“正在加五官”表达，除非运行时有可测量进度，不编造百分比。

### 矢量/笔画模式

为主体、五官、装饰分配稳定元素 ID。布局在首阶段确定，新增细节沿用相同坐标系与画布比例。修改围巾时定位装饰元素，不能意外重排全部主体。阶段快照或增量应用后实际渲染，确认没有线条越界、缩放错位或不可见元素。

纯线条图可以用少量闭合形状和曲线，不必模拟真人肌肉动作或逐笔思考。画布笔画的存在与 Live2D 角色动作分开：即使角色没有“画画”动作，只要真实图已显示仍是绘图产物；反之只有动作没有图不算完成。

### 图片生成/编辑模式

后续阶段传入上一真实阶段图作为编辑基础，并明确保持主体位置、比例和画风。不能每轮从零生成再将不同猫、不同构图串成同一张画。

某工具的编辑可能带来细微变化，检查关注用户要求和主体连续性，不虚假保证像素级保留。变化破坏核心内容时修正或说明降级为最终图模式。

## 检查方法

结构检查覆盖真实资产存在、格式可解码、尺寸符合画布、SVG/笔画可安全渲染。视觉检查覆盖：

1. 主题和主体数量是否正确，动作/表情/主体关系是否可辨识。
2. 必须元素与禁项是否满足，参考指定特征是否体现。
3. 画风、线条密度、色彩和背景是否符合方案。
4. 相邻阶段是否延续同一主体，关键位置有无漂移或凭空消失。
5. 是否意外裁切、遮住主体、留下未完成连接或显示空白。

轮廓阶段只检查本阶段应完成的内容；最终阶段检查全部要求。若自述检查结果和实际预览矛盾，以实际产物为准。对于简笔画，风格化比例可以是有意设计，不能把所有非写实特征都误判为错误。

## 过程表达与收尾

工具已接单且阶段真实存在时，Z 可以接话：“先把耳朵留得大一点。”这句表达意图；只有已显示大耳朵时才说“耳朵已经画上去了”。

完成图展示后可根据真实可见内容说“围巾给它戴好了。你想给它起个名字吗？”观众要求去掉围巾后，不再沿用这句旧收尾。观众反馈“好看”可自然回应，不自动创建修改任务。

不要反复求评价或预写 NPC 赞美；围绕点题者的一项关切即可。可支持修改，但不把每次完成都变成无止境返工邀请。
