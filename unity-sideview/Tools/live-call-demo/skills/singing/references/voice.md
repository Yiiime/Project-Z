# 音色一致性与接入说明

## 动态沿用当前角色音色

音色以宿主当前角色配置为准，无需每次点歌重新选择。角色现在用什么音色说话，就使用经验证与其同一声音身份的歌唱配置。首版目标为单人无伴奏清唱，生成整段、检查后播放。

宿主提供 voice_identity_id、config_revision、展示名称、歌唱引擎的模型和接口音色 ID，以及映射验证结果。说话引擎与歌唱引擎可采用不同 ID，但映射需确认对应同一角色声线，并通过说话和清唱试听验证；名称相同不保证声音一致。不要把展示名称或另一个 TTS 产品的 speaker ID 直接当作当前接口参数。

缺少映射或当前声线不能演唱时，返回能力限制，不能悄悄使用其他声音。配置变更后按 contracts.md 的版本核对规则使旧任务/缓存候选失效；新请求读取最新配置。

## 可选验证案例：豆包 Vivi 2.0

Vivi 2.0 仅作为可选接入案例，不是默认音色或失败回退音色。以下为 2026-11-02 核对的资料，仅在宿主实际选用该方案时参考。

豆包实时语音 Seeduplex 接口文档提供 `enable_music` 开关；启用后会从曲库检索唱歌数据。文档将 Vivi 2.0 列为目前歌唱合成效果较有保障的四种主推音色之一。[官方实时语音接口文档](https://docs.volcengine.com/docs/doubao-voice/end-to-end-real-time-voice-full-duplex-version?lang=zh)

如果当前角色配置采用 Vivi 2.0，可以尝试这条接入路径，但不证明任意歌曲、指定段落、无伴奏和声线一致性都已达标。普通 TTS 的文本合成与实时语音唱歌能力应分开配置。实际参数层级、模型与音色 ID 在 demo 接入时按所选版本文档核对，不从此处猜测。

供应商内部“检索唱歌数据”也不自动等于宿主拿到了可审查的歌曲匹配结果、段落定位器或独立歌曲搜索 API。宿主需要可用曲库/检索适配层来落实先检索、找不到拒绝、版本消歧等规则；若接口不暴露结果，应增加独立查询依据，不能自造命中记录。

## 给歌声引擎的任务要求

由适配器把已确认字段转成当前接口能接受的请求；以下是内部指令模板，不是可直接发送的 API JSON：

> 用本次请求绑定、且与当前角色配置一致的声线，演唱已确认歌曲及版本的指定片段。保持对应旋律、歌词和节奏，保留角色当前声音特征。仅单人无伴奏清唱，不含乐器、背景音乐、节拍或叠加和声，不模仿原唱声线。音频中不加入开场白或结束语。只唱选定范围，不延伸、不重复。如果无法完成，不生成其他歌曲或替换声音。

歌曲身份、范围和声线都来自已确认数据。模板中的禁止条件需通过结果检查验证，不能仅靠提示声明为成功。

## Demo 验证建议

先选一首可检索、可定位的歌曲，试听“同声线说话 → 一段清唱 → 同声线说话”，确认声音身份衔接。随后验证：

1. 未指定片段时是否落在完整副歌；指定主歌、歌词起点、时间范围时是否遵循。
2. 是否能唱对旋律与歌词，是否出现朗读、错歌或尾音截断。
3. 歌声文件是否完全无伴奏；直播 BGM 静音后是否仍有生成音频自带的乐器声。
4. 播放结束、取消和重复回调是否正确控制唱后互动及音轨释放。

可先人工试听记录结果；这些检查尚未在本技能交付阶段执行。不设置未经实测的成功率、固定音域或延迟承诺。
