真实模型为现有本机配置的DeepSeek `deepseek-chat`。自动回归42项通过，团队检查264个C#文件无语法错误；回归使用显式测试替身，和上表的真实模型结果分开报告。

## 本次发现并修复的问题

1. 意向阶段混入实际通信字段，15次真实规划初测有3次失败。补充“走近”与“说话”的阶段约束，复测15次有效；意向失败现在结束任务，不再残留running状态。
2. 非通信动作偶尔输出`communication: false`。只对非通信动作的false／null空标记做省略规范化；true、空对象、字符串及缺失的真实通信信息仍按原规则拒绝。
3. 重新提任务漏写`task_followup`，或议程引用旧回合动作。增加当前拒绝任务的具体提示，并在输出契约中列出本轮合法目标／动作ID；未来动作尚不可用时允许next_action_id为空，不虚构已执行动作。
4. 不同存档使用相同剧情事件ID导致冲突。`PublishStoryEvent`将调用方稳定ID限定在worldId下；同一存档内重复投递不增加序号。可通过`StoryEventId(stableId)`查询最终ID。一个稳定ID表示一次事件，新事实必须使用新ID。
5. A2A生成时缺少实际旁听者，台词显示后才被披露规则拒绝，导致队列反复同步。宿主现在传入实际听众，后端在生成时限制可转述信息；Unity显示前复查，若出现新的听众则取消尚未展示的台词。没有放宽后台权限校验。
6. 记忆曾把愿望与当前计划写成承诺，反思也曾改变相对时间。细化提取／反思提示，并增加真实模型语义探针。自由文本仍是概率输出，不能以这些样本证明永远无误。
7. 游客中心有重复导航锚点。保留原先实际使用的绑定，删除重复项，加入地图身份唯一性与Unity／后台任务目录一致性回归。
8. 实际窗口观察发现HUD与告示板还残留“Day4起小岛毁灭”的固定文案，虽然后台没有发广播，玩家仍会看到错误公告。移除两处按日期生成的消息，保持现有样式，剧情消息仍由引擎显式投递。

首轮／中间轮的失败均保留在本机测试报告；不把只通过的重试冒称全部调用零失败。测试脚本自身也修正了读档epoch断言、关闭服务顺序、模型冷却等待；这些是验收工具问题，和产品修复区分。

## 明确验收失败的玩法部分

全地图与完整离岛玩法尚不能通过。代码检查结合实机任务路径确认：

- Skill地图有32个地点，Unity当前只有15个唯一锚点、3个实际场景。居民街部分路段、四处住宅、杂货铺、旧书屋、酒吧、海滨道路／栈道、沙滩与海湾等17个地点没有绑定；海湾等不可通行区域也不能仅补坐标就宣称可达。
- 11项玩家任务共有29个步骤；`ConfirmTaskStep`有接口定义，但没有实际物品交付、发电机维修、试航、拍照等调用者。接受任务和NPC同意协作已经接通，完成真实事项仍缺具体玩法触发器。
- `MemoryActionExecutor`目前执行move；“修好船”“拿到燃料”等自然语言描述不会创建物品、修复设备或触发离岛。
- 最终出航、Z自主确认、实际资源与海况／权限检查、离岛结果结算尚无完整执行链。测试未注入虚假的成功回执，也未用Day7自动成功替代这条链。

因此上述项目从“没测”变成了“已检查，因实现缺口未通过”。这份PR不通过添加固定剧情、任意新地图或假完成按钮来消除失败。

## 复现与证据

后端目录为`Tools/MemoryLab`，常规回归运行`npm test`。以下脚本**不会自动在CI调用付费模型**；使用本机环境变量配置，并将结果放在`/private/tmp/`：

```sh
node --env-file=/path/to/local.env verify-real.mjs /private/tmp/seven-day.json
node --env-file=/path/to/local.env verify-memory.mjs /private/tmp/memory.json
node --env-file=/path/to/local.env verify-planner.mjs /private/tmp/planner.json
node --env-file=/path/to/local.env verify-http-latency.mjs /private/tmp/latency.json
node --env-file=/path/to/local.env verify-service.mjs /private/tmp/isolated-service 8893
```

Unity独立版或编辑器指定临时`Z_MEMORY_SAVE_ROOT`，传入`-memoryService http://127.0.0.1:8893 -memoryExtendedOutput /private/tmp/unity-result.json -memorySoakSeconds 600`。编辑器另加`-executeMethod Seabreeze.Editor.MemoryExtendedVerificationEntry.Begin`。该验证入口仅在显式命令参数下启用，不参与正常游戏。

修复前的坏队列没有被偷偷清空或作为成功记录复用；复验使用新的临时存档，同一后端数据库保留多个世界以检查隔离。用户正在测试的原工程、服务和存档未被重置。

无法替代的环境验收：本机干净导入不是另一台实体机器测试。Windows、Intel Mac、其他GPU／显示缩放、所有屏幕尺寸和长达数小时的稳定性仍需要相应环境。已做的600秒级运行不能外推为无限稳定。
