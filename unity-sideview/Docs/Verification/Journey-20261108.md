# Z 答应去花店却不走：本地修复验收

## 断点与修复

旧链路只提供相邻锚点，不保存最终目的地；有动作待回执时后续只剩 wait，模型也看不见未完行程。执行器可能被日常移动、NPC 社交或玩家交谈打断；走完一步后还会向出生点闲逛。现在后台生成完整路线、保留 pending 行程；聊天暂停而非失败，A2A 不抢占，实际到达才结算；角色可以明确取消。

没有用台词关键词强制接受邀请，没有传送 Z，没有改动界面样式。以下 Unity 两轮均调用本机配置的真实模型，并使用 `/private/tmp/` 独立存档，不覆盖用户进度。

## 真实 Unity Play

入口：`Seabreeze.Editor.MemoryJourneyVerification.Begin`。

- 正常同行：Z 回答“有空啊，正想出门转转。小小晴的花店我熟，走吧，看看今天到了什么新花。”自主选中 `move_flower_shop`。
- 路线：`z_home → residential_middle → public_middle → flower_shop`。Z 实际坐标从 x=3.40 行走到 x=-5.9585，花店锚点 x=-6.00。
- 当前聊天未结束时停留；行走到 x=2.58 再次聊天时暂停，结束后继续同一条 action；无替换 action 或提前成功。
- 后台实际到达回执为 succeeded，Z 的个人记忆新增引擎 fact：“已实际走到目的地：flower_shop。”
- 取消同行：第二份存档中途说“我突然有事，今天不去花店了。我们先停下，下次再约好吗？”Z 回答“行，有事你先忙。花店哪天去都成，下次再约。”自主选 cancel_move；后台为 cancelled，停在 x=2.5988，未写到达，日常移动占用释放。
