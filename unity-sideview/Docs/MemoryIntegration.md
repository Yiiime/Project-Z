# 七人记忆与自主交谈试玩

在现有横版小岛中，七位 NPC 使用各自的人设和记忆决定找谁、谈什么。玩家仍是独立角色；Z 作为剧情人物，不由本模块操控。七人外观暂用现有资源并标注占位，主角已验收的动作和移动参数保持一致。

## 开始试玩

1. 双击 `启动七人记忆试玩.command`；或在 Unity 6000.3.27f1 打开 `Street` 场景并点击 Play，同时启动 `Tools/MemoryLab/start.sh`。
2. 在 `http://127.0.0.1:4330/settings` 填写模型配置，保存并测试连接。游戏右上角也有“模型设置”入口。
3. 用 A/D 或方向键走动，靠近 NPC 按 E 输入台词。可以站在附近旁听 NPC 交谈；范围外不会显示或记下完整台词。
4. 与长椅或咖啡交互推进游戏时段。进入 Day4 后出现“小岛将要毁灭”的系统公告。

独立试玩包同时提供游戏、Memory Lab 服务和本机 Node 运行时。分享包不包含密钥、数据库、真实存档或原始模型调用记录；首次使用需本机配置。原剧情可用 `-memoryDisabled` 启动。

## 场景行为

流程为选择对象、检查可交谈状态、预约参与者、真实走近、停步相对、轮流发言、结束并继续活动。首版同时调度一个会话；默认每次最多 6 句，同一对角色冷却 90 秒，接近限时 20 秒，会话限时 120 秒。模型往返较慢时，在完成一轮后按剩余时间提前收束。

NPC 之间交谈不打开全局剧情对话，不冻结玩家或第三人。玩家介入、角色消失、跨时段、切场景、载入和重置会取消尚未发生的发言。模型无配置或失败时显示状态并恢复等待，不用固定回复冒充模型。

游戏确认的会面属于亲历；台词里的外部事情属于说话人的陈述。亲历、听说、约定、个人观点与自然遗忘沿用 Memory Lab。记忆实际送入下一次选人、选话题和回应请求。

## 数据保护

| 数据 | 位置与处理 |
|---|---|
| 原试玩 | 原 `seabreeze-save.json` 保留 |
| 七人试玩 | 同应用数据目录下的 `seven-memory-save.json`，原子写入并保留备份 |
| 模型密钥 | 仅本机服务 `.local/model.json`，权限 0600，不在游戏存档中 |
| 新服务数据库 | `.data/game.sqlite`，与原实验台数据库分开 |
| 测试与录像 | 使用显式隔离目录、独立数据库；不提交个人数据 |

每份游戏存档携带已确认记忆快照与待提交事件队列。恢复时以游戏存档为准建立新运行标识；旧模型结果即使迟到，也不能把未来对话带回过去。Day4 的事件 ID、接收记录和玩家通知状态随存档保存。

## 验收入口

| 层次 | 入口 | 能证明什么 |
|---|---|---|
| 服务自动化 | `Tools/MemoryLab` 下 `node --test tests/*.test.mjs` | 知识范围、去重、时间线、证据、取消、密钥处理和故障恢复 |
| Unity 模拟模型 | `Seabreeze/Verify seven-character memory integration`，指定隔离替身服务 | 实际移动、E 交互、全员通知、会话结束、其他角色继续活动、切场景与读档 |
| 真实模型 | 同一验收入口连接真实配置的隔离服务 | 模型分别生成双方台词并通过实际场景流程；不代表所有人物组合都已穷举 |
| 原动作回归 | `CharacterMotionVerification.Run`，传入 `-memoryDisabled` | 已验收主角动作、比例与步行相位 |

报告区分模拟模型与真实模型。Unity 编辑器自身的 Search 索引启动异常如出现，会单列为编辑器问题，不混入游戏运行异常或隐去。

验证没有穷举七人的全部组合或所有模型。生成文本仍可能出现指代或概括错误；公开人物称谓已补入上下文，世界效果仍严格由游戏确认。Z 的公告知情在本模块剧情状态中保存，现有直播对话没有扩展到这套记忆。
