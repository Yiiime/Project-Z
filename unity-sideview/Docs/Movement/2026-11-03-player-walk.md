# 主角行走专项优化 · 2026-11-03

范围：Unity 6000.3.27f1 / URP 17.3.0 当前项目的主角水平移动、视觉步态和切片配置。没有改变场景、NPC、UI、剧情、输入映射或相机代码，没有新增依赖、测试工程或测试脚本，也没有执行已有测试套件。

## 定位结果

- 物理根节点稳定：在当前街道运行原控制器 200 个物理步，X 反向变化次数为 0，地面 Y 范围约 0.000001 世界单位。刚体已使用插值与 Continuous 检测；玩家没有 Animator、Root Motion 或位置动画曲线，运行相机也没有 Pixel Perfect 组件。
- 主要视觉来源：旧 `CharacterVisual` 将整张角色围绕脚边旋转 ±1.4°。直接调用真实动画入口 200 次，即使根节点完全不动，在本地高度 2.3 处仍测得 X 峰峰值 0.11233；修改后同一复现入口得到 0.00000。
- 图集轴线不一致：四帧分别按 alpha ≥ 32 紧裁，再用几何中心作为 Pivot。两张迈步帧的头轴位置相差约 0.069 世界单位（含 1.17 外层缩放）。原图透明边距并非原因。
- 旧 Idle 使用 `characters/player`，Walk 使用另一套图；换帧还会按各帧 bounds 高度重新缩放。步态相位固定按时间推进，与加速、减速及碰墙后的实际位移没有关联。

## 实现

1. `PlayerController.cs`：保留 Rigidbody2D 在 FixedUpdate 中控制速度；新增 0.06 秒的加速度渐变，制动或反向时消除相反方向的残留加速度。LateUpdate 使用插值后的实际水平位移驱动视觉。传送与对话锁定重置移动采样；锁定中传送通过独立 CapsuleCast 更新落地姿态。
2. `CharacterVisual.cs`：主角走路图分支取消整体横摇；朝向使用 SpriteRenderer.flipX。Idle 使用 walk_0，共用固定缩放和底部基准。步态每实际移动 2.8 世界单位推进一周，碰墙时不再原地迈步。上下起伏降至 0.012 本地单位并平滑淡入淡出；站立呼吸围绕脚底缩放，不平移根节点。NPC 继续原有分支。
3. `SpriteSheetImporter.cs`：新增只导入主角图集的 `ImportPlayerWalk()`。四帧共用 y=72、height=760 的原图纵向范围，保留各自 X/width、名称和 Sprite ID；校准头部/上躯干轴线的 Custom Pivot，避免每次重导恢复错误中心。原 PNG 像素没有改动。
4. `player_walk.png.meta`：已实际重导，四帧 Pivot X 为 0.51105031、0.48943067、0.50601583、0.53181379，Pivot Y 均为 0。无需运行时逐帧水平位置补偿。
5. `Player.prefab`：明确保存 accelerationRamp=0.06、playerStrideLength=2.8、playerBobHeight=0.012。

## 资源边界

目前仍是站立帧与两张相近的迈步姿势组成的离散循环，另有一张抬腿 Jump 姿势。距离驱动修复了播放节奏与位移失配，但不会凭空生成脚掌接触、经过、抬脚和另一侧腿的完整中间姿态，不能宣称已经实现 Ori 级连续动画或逐帧完全锁脚。后续正式素材需要同一画布/轴线的完整左右交替步态、起步/收步与转身过渡；当前脚本和图集仍可直接替换扩展。本轮交付及验证对象为 Unity 项目 Play 模式，既有独立 macOS 构建未在本轮重新打包。
