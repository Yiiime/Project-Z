# 场景资产 · PSB 分层规范 v1（建议稿）

> 2026-11-03 ｜ 适用：11 个地点 + 后续新场景 ｜ 依据：`码头地点_v1_实现说明与美术管线.md` §3、`场景盘点与项目结构规划_v1.md` §2/§6、`DockLocationBuilder.cs` / `ParallaxLayer.cs`
> 目的：PSB 既是美术母版，又能被 Unity 直接消费；换地点不换规范、换人不换命名。

---

## 0. 一句话结论

PSB 不是"把一张成品图切开"，而是按 **深度平面（视差速度）× 遮挡顺序（sortingOrder）** 两个正交维度，把画面重建成**一组同画布、同原点、被遮挡处已补画的整幅层**。
层数不是越多越好：先锁 4 个不变量，再套 11 层标准栈，最后用 manifest 把"深度/顺序/混合"从美术文件里解耦出来。

## 1. 四个不变量（先定，之后不许动）

| # | 不变量 | 建议值 | 为什么 |
|---|---|---|---|

## 2. 两个正交维度（最容易搞错的地方）

- **depth（视差）**＝这一层在空间里有多远 → 决定 `x = base + (camX − refX) × (1 − depth)`
- **order（遮挡）**＝这一层画在角色前还是后 → 决定 `sortingOrder`

**站在地面上的东西，depth 必须等于地面（1.0）**，否则它会相对地面滑动；它只是在"角色前"还是"角色后"上不同。只有"不属于这个空间"的东西（云、远海、光晕）才给 <1 的 depth。

| 对象 | depth | order | 说明 |
|---|---|---|---|
| 远山/远岛 | 0.30 | 12 | 慢速视差 |
| 长椅（站在地上） | **1.00** | 28 | 与地面同速，但在角色身后 |
| 地面 | 1.00 | 32 | 角色脚下 |
| **角色** | — | **50** | 不进 PSB |
| 草丛/栏杆 | **1.00** | 52 | 与地面同速，但挡脚 |
| 前景木桩剪影 | 1.10 | 56 | 比世界更快 |

常见错误：把"所有道具"塞进一个 `props` 层 → 长椅和远船一起慢移，视差一动就穿帮。

### 3.2 最小版（6 层，试点/占位用）

`sky` / `land_far` / `sea_near` / `struct_mid` / `ground_base` / `foreground`
能跑通视差与遮挡，够验证场景形态；正式交付再补 5 层。

### 3.3 三条硬规则

1. **一层一深度**：同一层里的所有元素必须落在同一个 depth 上；想要不同速度就拆层。
2. **被遮挡处必须补画**：隐藏任意一层，画面不能有洞；视差一动就露馅的地方就是漏补的地方。
3. **光效不烘焙**：灯笼/窗灯/水面反光单独成 `fx_` 层，加法混合；否则夜晚/雨雾变体没法调。

## 4. 命名规范

```
^(\d{2})_(fx_)?([a-z][a-z0-9_]*)$      # 标尺层例外：^99_guide_[a-z0-9_]+$
```

| 规则 | 说明 | 正例 | 反例 |
|---|---|---|---|
| 两位数字前缀 | 就是 Unity `sortingOrder`，前导 0 不能省 | `24_struct_mid` | `4_struct_mid`、`24-struct` |
| 全小写 + 下划线 | 无空格/中文/点/括号/斜杠 | `20_sea_near` | `图层 1`、`房子 copy 2`、`天空final` |
| 语义词表封闭 | 只用 §3 的词，11 个地点共用 | `32_ground_base` | `background2`、`bg/props` |
| `fx_` 跟随宿主 | 序号 = 宿主序号 + 1，depth 与宿主完全相同 | `24_fx_lantern`（挂房子） | 把所有光效合并成 `fx_glow` |
| `guide_` 且序号 99 | 标尺层，导出时跳过 | `99_guide_canon` | 用隐藏层当交付手段 |
| 角色固定 50 | PSB 里永远不出现人物 | — | 把路人画进 `prop_back` |

> 为什么把序号写进层名：PS 里拖一下图层就改了遮挡，靠"视觉顺序"沟通一定会错；序号写死之后，重排图层也不影响 Unity 的 sortingOrder，manifest 也能自动生成。

## 5. 画布数学（别靠眼睛估宽度）

- 视口宽 `V = 2 × orthoSize × aspect = 2 × 5.4 × 16/9 = 19.2` 单位 = **1920 px**
- 相机行程 `R = 8.8 − (−8.8) = 17.6` 单位 = **1760 px**
- 某深度层在行程内不露底所需最小覆盖：**`W(d) = V + d × R`**

| depth | 0.00 | 0.25 | 0.30 | 0.40 | 0.55 | 0.75 | 1.00 | 1.04 | 1.10 |
|---|---|---|---|---|---|---|---|---|---|
| 最小覆盖 px | 1920 | 2360 | 2448 | 2624 | 2888 | 3240 | 3680 | 3750 | 3856 |

**结论**

- 3840 画布可支撑 `d ≤ 1.09`；当前前景 1.04 在相机推到 ±8.8 时只剩 **45 px** 余量。
- 若想把前景提到 1.10，画布要 3856 → 取 **3872**（16 的倍数），或把前景压在 1.08。
- 单张纹理上限 8192 px ⇒ 单份 PSB 支持的相机行程上限 ≈ (8192−1920)/100 = **62.7 单位（约 3.2 屏）**；再宽就要分段 PSB 或改用可平铺图案。
- 纵向 1080 = 视口高 10.8，**没有出血**：现在相机 Y 锁死所以安全；一旦加屏震或纵向跟随，画布高改 1200（上下各 60 px 出血），构图仍按中央 1080 设计。

**同画布同原点**：所有层导出为同尺寸整幅图，pivot 统一 `Center`（与现 `ImportArt` 一致），场景里所有层 `position = (0,0,0)` 就能对齐。**不允许裁边后手摆位置**（显存真吃紧再走 §10 的 manifest offset 方案）。

**显存**：3840×1080 BC7 ≈ 4.15 MB/层；12 层整幅 ≈ 50 MB。预算按 **≤ 60 MB/地点** 卡，超了才裁 `prop_*` / `fx_*`。

## 6. 三条生产路线（母版怎么变成 PSB）

| 路线 | 做法 | 适合 | 代价 |
|---|---|---|---|
| **A 母版拆层**（推荐） | 先出定稿母版 → 逐层"选中物体 → 内容识别填充 → 独立成层" → 补画被遮挡处 | 交付质量最高、光照统一 | 人工最重 |
| **B 逐层生成** | 每层单独出图（绿幕/透明）再合成 | 快、可批量 | 一致性差（光位/透视/描边粗细会飘），需要人调 |
| **C 深度图辅助** | 用深度估计出深度图 → 按 depth 带切 mask → inpaint 补洞 | 介于 A/B，适合 11 地点这种同构场景 | 需要一条脚本管线；边缘要人工修 |

实操建议：**A 做 1 个地点定标准 → B/C 用来铺量 → 全部回 A 精修**。不管哪条路线，最终 PSB 都必须满足 §7 的约束，否则 Unity 侧一定会出问题。

## 7. 图层技术约束

| 项 | 要求 | 原因 |
|---|---|---|
| 格式 | **PSB**（>30000 px 或 >2 GB 必须）；所有场景母版统一 PSB | 工具链一致，便于脚本读层 |
| 色彩 | 8 bit/通道、sRGB（非 CMYK/16 bit/灰度） | Unity 纹理是 8 bit sRGB |
| 图层样式 | 投影/外发光/描边、调整层、剪贴蒙版、智能对象、文字、矢量形状 **全部栅格化** | 导入器不计算这些，会得到"没效果"的层 |
| 混合模式 | 一律 **Normal** | 发光靠独立 `fx_` 层 + Unity Additive 材质 |
| 隐藏层 | 不作为交付手段（是否导入依版本/选项而异）；标尺层用 `99_guide_*` 显式跳过 | 避免"本地看着有、导入没了" |
| alpha | 整幅层（sky/ground/foreground）必须 100% 不透明；物件层背景 alpha=0 且 **RGB=0** | 半透明或残留 RGB 会在缩放/压缩时泛色 |
| 边缘 | 外扩 1 px 后 Erode 1 px；物件边缘不得有绿/白描边 | 消除色键溢色与细边 |
| 图层数 | 6–14；组 ≤ 3 级；单 PSB < 40 层 | 导入时间与 prefab 层级可读性 |
| 不放 | 人物、UI、文字、水印、粒子、碰撞信息 | 这些在 Unity 里做；画进背景就死了 |

> 组（Group）只用于 PS 内整理，命名 `grp_*`，不要用组来表达深度——导入器对组语义的支持随时会变。

## 8. 变体策略（时段 / 天气 / 剧情）

4 时段 × 天气 × 11 地点，**绝对不要复制 44 份 PSB**。

时段的真实差异只有三类：① 天空/云 ② 光效强度与颜色 ③ 全局色调（曝光/白平衡/雾）。

- **基准 PSB 只做一份**（傍晚），层名/序号固定
- 天空：`sky_night.png` 替换同一层
- 光效：`fx_*` 的 color/opacity 走参数表，不重画
- 色调：Unity Volume（Color Adjustments / White Balance / 雾）统一压
- 差异特别大的地点（灯塔夜、天文台）才单独出 `_night.psb`，但**层名与序号必须与基准完全一致**，方便 diff 与批量替换

天气（雨/雾/雪）：全屏 overlay + 粒子，不进 PSB。季节同理：只替换单层文件，如 `32_ground_base_snow`。

## 9. 资产边界：背景板之外的四类

| 类型 | 归属 | 命名 | 说明 |
|---|---|---|---|
| 背景板 | `Art/Locations/<loc>/` | `loc_<id>_<time>.psb` | 一地点一份，整幅层 |
| 可交互道具 | `Art/Props/` | `prop_<name>.psb` / `.png` | 单体 PSB，同光同描边，独立 prefab（要能被脚本移动/替换/高亮） |
| FX | `Art/FX/` | `fx_<name>.png` | 加法/粒子贴图，透明或黑底 |
| 标尺/标注 | PSB 内 `99_guide_*` | `99_guide_canon` | 地平线/地面线/相机边界/安全区，**不导出** |

理由：能交互的东西一旦画进背景，就再也拿不出来了；标尺层保证 11 个地点的构图不会各画各的。

## 10. 导出与 Unity 接入

### 10.1 两条路线

| 路线 | 做法 | 好处 | 代价 |
|---|---|---|---|
| **A 导出 PNG + manifest**（推荐，契合现有 builder） | PSB 母版 → 脚本导出整幅 PNG + `layers.json` → Builder 读 manifest | 沿用 `ImportArt` / `CreateLayer`；PNG 可被其他工具复用 | 多一步导出；要维护 manifest |
| **B 直接 PSB 导入** | 2D PSD Importer 15.0.0，Individual Sprites 模式 | 层偏移自动保留，省导出 | 每个地点生成 prefab 层级，ParallaxLayer 要逐个挂；母版一改整份重导 |

> 走 B 时**母版别放 `Assets/` 内**（会被当纹理再导入一次）：放 `Assets/ArtSource~/`（`~` 结尾的文件夹 Unity 会忽略）或仓库外。

### 10.2 共用导入设置

`Texture Type = Sprite`｜`Sprite Mode = Single`｜`PPU = 100`｜`Mesh Type = Full Rect`｜`sRGB ✔`｜`Alpha Is Transparency ✔`｜`Mip Maps ✘`｜`Max Size ≥ 4096`｜`Compression = BC7`（桌面）/ `ASTC 6x6`（移动）｜pivot：整幅层 `Center`、角色 `Bottom-Center`

### 10.3 manifest 示例

```json
{
  "location": "dock",
  "canvas": { "width": 3840, "height": 1080, "ppu": 100 },
  "groundY": -3.02,
  "camera": { "minX": -8.8, "maxX": 8.8, "orthoSize": 5.4 },
  "characterOrder": 50,
  "layers": [
    { "file": "sky",           "order": 0,  "depth": 0.00, "blend": "normal",   "opacity": 1.0 },
    { "file": "cloud_far",     "order": 5,  "depth": 0.15, "blend": "normal",   "opacity": 0.9 },
    { "file": "land_far",      "order": 12, "depth": 0.30, "blend": "normal",   "opacity": 1.0 },
    { "file": "sea_far",       "order": 16, "depth": 0.40, "blend": "normal",   "opacity": 1.0 },
    { "file": "sea_near",      "order": 20, "depth": 0.55, "blend": "normal",   "opacity": 1.0 },
    { "file": "struct_mid",    "order": 24, "depth": 0.75, "blend": "normal",   "opacity": 1.0 },
    { "file": "fx_lantern",    "order": 25, "depth": 0.75, "blend": "additive", "opacity": 0.35 },
    { "file": "prop_back",     "order": 28, "depth": 1.00, "blend": "normal",   "opacity": 1.0 },
    { "file": "ground_base",   "order": 32, "depth": 1.00, "blend": "normal",   "opacity": 1.0 },
    { "file": "ground_detail", "order": 36, "depth": 1.00, "blend": "normal",   "opacity": 1.0 },
```

## 11. 验收清单

**PSB 侧（美术自检）**

- [ ] 3840×1080、8 bit sRGB、所有层同尺寸
- [ ] 层名符合 §4 正则、序号不重复、无中文
- [ ] `99_guide_canon` 存在，地平线 35% / 地面线 78% / 前景带 90% 对齐
- [ ] 隐藏任意单层，画面无洞（遮挡处已补画）
- [ ] 每层按 `W(d)` 够宽，相机推到 ±8.8 不露底
- [ ] 物件边缘无绿/白溢色；alpha=0 区 RGB=0
- [ ] 无人物/文字/UI 混进背景层
- [ ] `fx_` 层是纯发光（透明或黑底），没和背景烘焙在一起

**Unity 侧（自动校验）**

- [ ] PPU 100 / Full Rect / 无 mipmap / sRGB
- [ ] `sortingOrder` 与层序号一致，角色固定 50
- [ ] `ParallaxLayer.depth` 与 manifest 一致
- [ ] 角色脚底与地面线误差 ≤ 2 px
- [ ] 任意两地点切换，地平线/地面线/角色比例不动（截图 diff）
- [ ] 单地点显存 ≤ 60 MB
