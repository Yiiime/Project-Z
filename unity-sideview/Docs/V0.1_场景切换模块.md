# V0.1 场景切换与返回入口

更新：2026-11-03。工程：Unity 6000.6.7f1。

## 本阶段交付与边界

本阶段修复场景切换、返回出生点及 E 键出口。保留当前 App 常驻场景、PlayerInteractor、GameState 和对话框架，不回退或重建已有场景。没有增加第三方依赖。

状态：代码、App 接线和地点序列化配置已完成；经过源码审查、Unity 自动导入编译及保存数据核对。**没有运行自动化测试、Play Mode 或构建，不代表运行验收通过。**

## 玩家行为与模块职责

靠近出口时复用通用提示，显示 `E 前往<地点>`；只有按 E 才请求切图，碰到或停留在出口触发盒不会自动切图。NPC 对话继续使用原来的 E 交互链。

| 模块 | 职责 |
|---|---|
| SceneExit : Interactable | 场景拥有的目标路径、目标入口及通用交互数据，不引用全局路由器，不操作玩家 |
| PlayerInteractor | 选择当前场景内、范围内且未被墙阻挡的目标；按 E 发布一次交互请求 |
| LocationRouter | 显式引用 Session、Interactor 和 CameraFollow；锁定探索输入、淡出、等待切换结果、镜头重定位、淡入，最后恢复探索 |
| GameSession | 新地点加载并校验后才提交 Location/GameState，通知出生，再卸载旧地点；加载流程不提前恢复探索 |
| SceneContext | 严格解析入口 ID，未知、重复或缺少锚点的入口拒绝，不再静默落到默认出生点 |
| PlayerController | 接收地点变化并传送；移动和物理开关统一由模式变化控制 |

成功流程：探索 → Transition → 淡出 → 加载目标 → 校验 SceneContext/入口 → 更新地点与入口 → 传送 → 卸载旧地点 → 重定位镜头 → 淡入 → 探索。

加载失败或入口校验失败时保留旧地点、游戏状态和玩家位置，清理本次加载的无效地点，再淡入恢复探索。已被其他调用加载的非当前目标场景会被拒绝，避免误卸载其他所有者的场景。同场景入口传送不重载场景。

如果目标已提交而旧地点清理失败，会记录错误并禁用残留地点对象，避免双重画面与碰撞；该异常不伪装为成功回滚。整个 App 被销毁属于会话终止，不提供跨会话的异步旅行恢复。

## 入口命名与当前路线

- 每个地点的默认入口：`start`，引用原有 initialSpawn。
- 本地点从相邻地点进入：`from_<相邻地点 locationId>`。
- 从本地点出发的出口，目标入口：`from_<本地点 locationId>`。
- 左、右入口分别使用现有侧边锚点；返回到来路一侧，不恢复任意历史坐标。

例如：码头 → 港湾木屋使用 `from_dock_dusk`；港湾木屋 → 码头使用 `from_harbor_cabin`。

| 本地点 | 左侧返回入口 | 右侧返回入口 |
|---|---|---|
| 码头 / dock_dusk | — | from_harbor_cabin |
| 港湾木屋 / harbor_cabin | from_dock_dusk | from_town_street |
| 小镇街道 / town_street | from_harbor_cabin | from_plaza_dusk |
| 中央广场 / plaza_dusk | from_town_street | from_garden_dusk |
| 花园小屋 / garden_dusk | from_plaza_dusk | from_cliff_dusk |

11 个地点共有 27 个配置入口、16 个有向出口。所有出口在 Interactable 层，分别拥有 InteractionPoint 和 PromptAnchor。交互点位于当前地面上方 0.9，提示在上方 3.4 并向画内偏移 0.5。

## 场景维护方式

`Z From Moon → Repair Location Routes` 是持久的 Editor 维护菜单：按当前保存的左右出口关系修复入口和交互字段，并连接 App 的 Router。它要求 Edit Mode 且打开的场景已保存；从当前地点数据读取左右锚点，保留原坐标、碰撞与美术。

本阶段通过该菜单迁移已有场景，**没有运行 Build World Locations**。后者是完整生成器，虽然本次已同步修复其路由规则，仍会按代码里的场景参数重建内容，不能用来替代保留手调结果的局部修复。

对照修改前基线核对：147 个原有 Transform 的位置/旋转/缩放/父级保持不变，50 个碰撞组件及 29 个 SpriteRenderer 的序列化内容保持不变；新增 32 个交互/提示锚点。港湾木屋已手调的 y=-0.2 保留。
