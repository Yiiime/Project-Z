# 街角的长椅

李庭在 AI 对话中发布委托。玩家接受后，到咖啡店与花店之间、楼梯左侧的长椅旁按一次 **E**，现场完成。

| 步骤 | 玩家操作 | 游戏反馈 |
| --- | --- | --- |
| 领取 | 进入咖啡店，与李庭交谈：「有什么我能帮忙的吗？想接下街角长椅的委托。」 | AI 发布「街角的长椅」，出现接受按钮 |
| 接受 | 点击「接受任务」，结束对话 | 右上角显示目标；Tab → 任务可查看详情 |
| 找到 | 出咖啡店向左走，到花店与咖啡店之间、楼梯左侧 | 椅子上方出现光点，靠近显示「E 查看长椅」 |
| 完成 | 按一次 E | 提示「委托完成 · 街角的长椅」，任务页更新为已完成 |

本次查看不推进时段，不要求返回交任务。咖啡店与照相馆之间的另一张椅子仍保留原有休息行为。

| 边界 | 处理 |
| --- | --- |
| 尚未接受就按 E | 只查看椅子，不完成委托 |
| 只在对话里说「做完了」 | 不完成，仍需实际交互 |
| 站得太远、站在另一张椅子旁 | 不完成目标委托 |
| 连续按 E | 每个任务步骤只记录一次 |
| 短暂断线 | 操作进入本地存档队列；连接恢复后自动同步，确认前显示正在记录 |
| 读档或重启 | 恢复已接取或已完成状态，不重复发放结果 |

## 实现与范围

复用 `MemoryLab/TaskEngine` 的发布、接受、步骤、完成和快照，复用 Unity `MemorySaveState.outbox` 的保存及重传。新增配置中的 `steps[].interaction` 描述目标场景、物件、位置、距离和输入；`WorldTaskController` 绑定对应交互并提交实际操作证据。手机任务页继续读取同一份任务目录和快照。

两端都检查接受状态及交互条件。AI 可以提出委托、回应经历，不能通过台词直接修改完成状态。完成只记为这次帮忙的经历，不新增货币或好感数值。

本轮补齐这条现场交互链路；原有物品、修理、协作、出航任务的各个世界动作仍按其已有实现范围处理。
