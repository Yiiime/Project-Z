# 第七晚：把明天交还给我 — 原生终章演出方案

状态：设计提案。用户要求终章与当前完整游戏框架衔接，并具有大型叙事游戏的制作感。现有入口、上传、模型与存档可以复用；完整镜头、分层场景、配音、音乐和动作仍需制作。当前分段展示试作只经过静态与后端检查，未完成 Unity 编译和试玩，不能作为本方案已交付的证据。

## 体验目标

目标时长8—10分钟，实际随本局知情记忆数量、配音节奏和玩家停留变化。由真实游戏探索进入，在Z的家整理经历，经过熟悉岛上地点与直播，最后在码头让Z表达自主去留，再进入独立原生结局页面。正式流程由终章事件进入；现有第七晚按钮仍作为Demo入口。Demo不把原存档第1天改成第7天，也不授予预置故事中的物品、权限或任务完成状态。

制作感来自完整的镜头语言、场景空间、声音、角色反应和因果回响。演出按本局内容编排，统一的录制视频只用于可选镜头素材，不能代替不同存档的记忆和结果。

## 六幕

| 幕 | 目标时长 | 画面与操作 | 与现有框架的连接 |
|---|---|---|---|
| 海风停了一拍 | 30—45秒 | 从正常探索视角开始，游戏HUD淡出，保留当前位置与Z；镜头靠近，先听到环境声，再进入终章标题 | 同一GameUI入口与占用生命周期；正式剧情与Demo入口区分 |
| 这一件，我想带上 | 90—120秒 | Z家内景，少量来自本局的物件/记忆入口。玩家点一件，先出现当时实际说过的话，再接Z此刻回望；物件不代表新增库存 | 复用ZBedroom/ZHome美术、同一个Z Live2D；使用当前结果的知情回望与原文 |
| 再走一段熟悉的路 | 90—120秒 | 原游戏公共街、花店、咖啡店等地点；角色有站位与短动作，镜头跟随、停顿、切细节；有对应本局经历才出现相关人的新对白 | 使用现有地图、角色定义与移动规则；新的对白与动作须进入经过校验的终章脚本，不能由美术镜头制造记忆 |
| 这次，听我说完 | 90—120秒 | 回到玩家熟悉的手机直播观看界面；重现本局真实送达过的弹幕与回应。Z自行控制表达和结束直播；下播声后留黑场 | 扩展现有直播Host的终章模式，复用渲染与输入；终章回放不调用日常直播结束回调推进一天 |
| 由我回答 | 60—90秒 | 月亮岛码头，海、缆绳、街灯与人物眼神。玩家能回应和等待；Z依据本局事实表达leave/stay。镜头针对选择和执行状态分别承接 | 同一模型的已锁定决定；船务、去留意愿与真实执行结果分别保留 |
| 这些日子仍在这里 | 30—45秒 | 独立原生结局页面先留结局名与最后一句话，随后开放完整记忆册、重播和返回游戏；片尾出现本局地点与原话的短回响 | 保存结果、演出版本与断点；回看同一次结果不重新生成；读档与切换世界隔离 |

## 内容覆盖与角色自主性

- 全部Z知情记忆进入完整回望素材池。导演按物件、地点、关系、广播分组，保留每条ID的演出位置与覆盖记录。
- 关键经历展开成动作和对白，其余经历在主题蒙太奇、原话回响或片尾出现具体细节；完整生成回望与原文保留在记忆册。相关ID出现不足以证明语义正确，需要逐条审读。
- 只将Z实际知道且玩家可听的内容安排到场景。秘密调查、未送达消息、作者幕后备注不进入演出。
- NPC临别对白需要来自已发生事件或单独生成并验证的终章行动；不能从NPC与Z都在一张图里推断他们已对话。
- Z的选择先由现有模型根据本局经历产生，再由导演组织回望和呈现。演员动作、音乐与玩家最后一句话不改写已锁定选择。
- leave + pending呈现她愿意离开、准备确认下一步，船仍在岸边；blocked呈现意愿与障碍；只有succeeded回执才能表现真实离岛。
- stay不自动撤销公司安排。safe、uncertain、shutdown采用各自已确认的后果，拒绝统一转成温暖大团圆。

## 需要新增的制作

1. EndingDirector：消费当前结局快照，组织章节、镜头、对白、交互、覆盖与结束事件。独立于正常地图任务结算，复用GameUI占用、关闭、世界与读档生命周期。
2. 演出脚本：小型明确协议记录镜头地点、演员、原话来源、生成回望、关联memoryId与演出时间；校验未知内容、选择冲突、重复/遗漏与执行状态。预置剧情保留作者输入属性。
3. 镜头与场景：Unity Cinemachine/Timeline或等效原生调度，按角色和地点分层；复用岛上美术，增加近景裁切、前景、光影与少量补绘。不是把横向探索图直接当所有近景镜头。
4. 表演：Z的看照片、收物、停顿、看向镜头、移开目光、转身等动作需要新增Cubism动作或专用镜头动画。岛民使用当前角色资源补临别站位与动作。
5. 声音：一条具有三个情绪段落的原创音乐，岛上环境、店门、纸张、直播提示、海风与缆绳音效，音乐在选择前收住。动态台词需逐条配音/生成、缓存与口型同步；不得用一套固定录音覆盖所有模型文本。
6. 结局页与记忆册：轻量的原生尾声页面；完整经历检索、来源、重播、演出断点及历史版本。演出中的工具按钮收进暂停/设置，避免全程显示上传、重生成和页数。

## 制作路径与验收

先做60—90秒垂直切片：正常主游戏HUD → 原Z家场景 → 一件实际记忆的原话与回望 → 当前手机直播框架 → 按锁定choice到码头 → 原生结局页 → 返回原存档。此切片要有正式音乐节拍、至少一个角色动作和完成的镜头调度。其质量通过后，再扩展到全量记忆、岛民告别和8—10分钟终章。

必须验证：从真实HUD/手机/暂停入口进入；同一worldId与Z模型；当前真实经历在演出中可辨认；更换上传文件后镜头内容与去留结果更新；全部知情ID有覆盖；leave/stay与执行状态分支；旧生成失效；演出暂停/重播；返回后原日期、位置、任务与库存保持正确；读档和历史回看正确；实际Unity编译与画面验证。

第一版不得以已有静态分镜MP4、后端ID覆盖或静态检查替代原生流程与音画验收。

## 机制依据

K04保留由具体经历形成关系与判断；K11保留存档、重播与迟到请求隔离；K12保留理解、选择、准备与执行结果分离。终章演出是对这些既有规则的表现层适配，不将动画完成登记为主游戏任务或离岛执行完成。
