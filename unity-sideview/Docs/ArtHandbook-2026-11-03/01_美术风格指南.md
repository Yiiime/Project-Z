# 美术风格指南：海风、日常与冷暖光

适用对象：场景概念图、其他游戏界面示意图、后续地图美术。版本：2026-11-03 / v1。

本指南的视觉依据是本次提供的 `image 5–10.png` 六张图。Unity 工程内的对话参考、UI 代码只用于补充界面设计边界。标记含义：**观察**是参考图可直接看到的共性；**建议**是便于团队统一制作的规则；**工程现状**是当前项目中的真实实现。建议值尚未经过用户美术验收。

## 一句话定义

**日系动画背景画质感的海滨日常叙事美术：以正面横版舞台构图组织生活空间，用清楚的形体、蓝紫冷影、局部金橙暖光和安静的留白，让玩家愿意停留。**

更短的内部风格名可以用“海滨日常 · 冷暖光叙事”。它描述视觉语言，不代表游戏标题。

不是仅凭“日系、治愈、唯美”三个词就能稳定复现。这组图同时依赖空间结构、角色尺度、光源逻辑、材质表现和画面密度。单独复制夕阳配色会丢掉风格。

## 视觉基因与可执行规则

| 维度 | 从六张图观察到的共性 | 给美术的执行规则（建议） |
|---|---|---|
| 情绪 | 有人生活的安静空间；晴、雨、夜、黄昏都保持平和 | 表现“此处发生过生活”，减少冲突姿态、强烈灾难感和夸张表情；雨天可以清冷，仍保留温暖的生活痕迹 |
| 画面组织 | 正面展开的横向空间，下部有连续步道，人物在同一水平活动带 | 先锁定角色脚底线、可走区域和主要交互点，再画景物；建筑正立面、地平线保持稳定，允许看见少量桌面与地面 |
| 透视 | 插画内部有体积与局部纵深，但行走方向不向消失点延伸 | 使用受控的轻透视；避免强广角、仰俯视和斜向纵深主路，不能让角色沿水平线行走时像悬浮在坡上 |
| 构图 | 室内多为床/桌/门沿横轴排列，大窗打开远景；室外用灯塔、店面与树建立识别点 | 每张一个主识别物，辅以一到两个生活焦点；给角色交谈区留下简洁背景，避免枝叶、窗框穿过头脸 |
| 形体 | 建筑、家具比例可信，线条整洁，装饰克制 | 大形先于纹理；墙、窗、柜、桌保持明确结构；不堆随机小物填空 |
| 色彩 | 蓝/靛/紫占阴影，奶白/木棕作生活基底，金黄/橙色形成焦点 | 冷暖建立层次，不要求全图高饱和；最亮、最暖的区域应服务窗光、灯或剧情焦点 |
| 光照 | 斜射日光、窗框投影、桌灯和路灯有明确来源；轮廓有柔和暖边 | 每张先写光源方向和时段；投影方向一致；暖边只出现在被光照到的边缘，不给所有物体描金边 |
| 画法 | 背景以清晰色块和柔和渐变塑形，植被与云有手绘块面，细节处有干净边缘 | 中高完成度的数字绘景；硬边与软边共存，轮廓清楚而非全局锐化；保留细小笔触但不靠厚颗粒遮掩结构 |
| 材质 | 木、布、墙体、金属可辨；水面以水平短光带表达，湿地有克制反射 | 材质通过反光、边缘和纹理密度区分；避免所有表面都像塑料或镜面 |
| 远近 | 前景深蓝稳定画面，中景家具/建筑可读，远海与山体对比变低 | 远景减少细节与对比；角色轮廓比其背后的景物更清楚；前景不抢主角 |
| 生活痕迹 | 书、纸箱、植物、衣物、杯子、行李、画片等反复出现 | 每张选与地点身份有关的三到五类物件；物件应有摆放理由，避免每张复制同一套装饰 |
| 角色 | 日常衣着、正常人体、细线轮廓，表情克制；在空间里有可信身高 | 世界小人与对话大立绘分别制作；统一人物身份、服装和头身关系，再对齐场景光色 |

## 六张参考图各自承担的校准任务

| 图 | 建议用作什么标杆 | 不应错误推广成什么 |
|---|---|---|

| image 10：雨夜卧室 | 大面积蓝灰冷色、桌灯局部暖区、窗外雨景与城市层次 | 整张简单压暗就能成为夜景；城市建筑也是其他图必须出现的设定 |
| image 7：黄昏卧室 | 紫橙冷暖、长投影、生活物件密度、两人交谈尺度 | 所有地图都用紫橙滤镜 |
| image 9：雨天海堤 | 降低色彩对比、湿地反光、阴云空气感、远灯塔 | 把雨线与人物倒影烘焙到所有晴日底图里 |
| image 6：工作间 | 工具/货架/纸箱形成的功能空间、冷灰与暖灯平衡 | 只会画温馨卧室而无法扩展到其他地点 |
| image 5：黄昏灯塔 | 户外主地标、海天留白、水平步道、远近层次 | 灯塔必须总在画面同一侧；整张都应有高饱和夕阳 |

六张图能证明的是共同的场景语言，不能单独确定游戏全部世界设定。尤其短发女性世界小人与工程里长发 Z 对话立绘存在外形差异；应以独立角色设定表锁定身份、发型和服装，不能让场景生成器替团队决定。

## 色彩与光照的统一方式

下表色号是根据参考方向整理的**建议锚点**，用于沟通色彩角色，不是要求逐像素取色，也不是锁定一张图的色彩直方图。

| 色彩角色 | 建议锚点 | 用法 |
|---|---|---|
| 深靛阴影 | `#17243F` | 地台、深处、边缘压暗，避免大面积纯黑 |
| 蓝灰中间调 | `#59667D` | 墙面、远建筑、冷色空气 |
| 海蓝 | `#358DB8` | 海与天空的中间色，随天气变化 |
| 奶白受光面 | `#E8DDC6` | 墙、纸、灯罩，不用绝对纯白铺满 |
| 金色暖光 | `#F6C675` | 窗光、灯、海面反光的焦点 |
| 黄昏橙 | `#ED9269` | 夕阳与云边的少量高暖区 |
| 灰紫 | `#8983AC` | 黄昏云影、冷暖过渡、少量服装 |
| 植物绿 | `#4B6955` | 有层次的叶片色块，避免荧光绿 |

**时段矩阵（建议）**：上午用清透海蓝和偏奶白日光；午后用更清晰的形体与略暖日照；黄昏把天空与受光区推向金橙、阴影保留蓝紫；夜间降低整体明度，重新安排桌灯、门窗和路灯；雨天降低直射光与远景对比，补湿地材质。地点的窗、门、步道与道具位置不随时段漂移。

“统一风格”应锁住画法、空间与材质，允许色温、天气和情绪变化。夜景不能以无法分辨角色和出口为代价，暖光也不能把人物照成与背景无关的贴纸。

## 给其他游戏界面的延展规则

这六张主要是场景设定图，不能直接推出字体、按钮尺寸、图标和全部界面交互。以下区分已有工程参数与延展建议。

### 当前工程中可复用的 UI 参数

来源：`Assets/Seabreeze/Resources/UI/DefaultUIStyle.asset`，并与 `Assets/Seabreeze/Scripts/UI/UIStyleConfig.cs` 核对一致。运行时优先读取该样式资产；今后若修改资产，应以资产值为准。

| Token | 当前样式值（转换为近似 sRGB 十六进制方便美术交流） |
|---|---|
| PanelFill | `#0E1B2E`，alpha .86 |
| PanelBorder | `#ABCFE0`，alpha .30 |
| TextPrimary / Secondary | `#E8F2F7` / `#A1BDD1` |
| AccentCool / Warm | `#94CCDB` / `#F0BF82` |
| HudFill | `#091426`，alpha .48 |
| Scrim | `#050B16`，alpha .47 |
| 文字 | 标题 36、正文 24、小字 18、对话正文 28；实际 HUD 有局部字号覆写 |
| 形状 | 圆角 14、描边 1；以 1920×1080 为参考分辨率 |
| 动效 | 淡入 .24 s、淡出 .18 s、悬停 .16 s、对话进入 .36 s、退出 .28 s |

颜色是代码数值的沟通换算，透明叠加、Linear 色彩空间和背景亮度会改变最终观感。正式图应在晴日、夕阳、雨夜背景上分别检查可读性。

### 新界面示意图怎么沿用

| 页面 | 构图与视觉（建议） | 必须提供的状态（建议） |
|---|---|---|
| 探索 HUD | 景物为主，信息靠边，深蓝半透明面板、细描边、小面积暖色焦点；角色脚边保持清楚 | 普通、附近可交互、通知出现；输出含 UI 合成图与独立 UI 层 |
| 全屏对话 | 人物立绘与文本区分开，留出脸、手与表情；深蓝/灰紫面板；文字后有稳定对比 | 普通对话、选项、长文本；输入/思考/语音状态只有产品确实需要时才补 |
| 地图/日志/背包 | 承接蓝灰与暖纸色，简洁线图标，按内容组织，降低背景竞争 | 常规、选中、空态、长标题或长列表 |
| 设置/暂停 | 清楚的文字层级、安静的边框和主次按钮，暖色仅强调当前行动 | 常规、焦点、不可用、需要二次确认的操作 |
| 事件/获得记忆 | 保留场景光色，可用一处暖色强调与较大留白 | 事件展示、继续；不要自动添加商城稀有度、战斗数字与无关装饰 |

首张新页面先用现有 1920×1080 截图作底，验证布局，再交独立可编辑图层。字号、透明度与交互状态不可交给生成模型随机决定。生成的中文、图标和按钮文字应由设计工具重新排版；语音、AI 状态的概念画面不能作为工程功能已实现的证明。

## 一票退回的问题与风格自检

**建议的一票退回项**：改变了侧视空间、角色身份漂移、光源矛盾、活动路径与视觉地面不符、背景中残留人影/UI/乱码、功能物件缺失或位置错误。

其余按以下六项逐项确认：空间与比例、形体与画法、冷暖与光源、远近与材质、生活物件的合理性、角色/文字可读性。可用每项 0–2 分作内部沟通工具：0 为明显偏离，1 为部分符合，2 为稳定符合；建议总分至少 10/12 且无一票退回项后交程序。这是新建议的质检方法，尚无真实生产数据证明该阈值。

评审时请同时看整张、1920×1080 实际取景、角色叠加和 UI 叠加四种视图。原画好看与进入游戏后好用是两个验收对象。
