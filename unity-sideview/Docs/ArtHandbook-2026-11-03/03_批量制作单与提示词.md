# 批量制作单、提示词与交付模板

本文件是建议生产流程。先读《美术风格指南》与《Unity地图资产规范》。提示词只帮助产出候选图，不能替代像素对齐、分层、排字和实际接入验证。

## 一张地图先填一张制作单

```text
地图 ID / 地点中文名：
任务：替换现有地点 / 现有地点时段变体 / 新地点
使用模板：Street / Cafe / Lighthouse / 新配置待程序确认
玩法用途与一处主识别物：
运行图尺寸：已有地图默认1672×941；如有变更写在这里
母版尺寸与输出缩放：
世界宽度 / 镜头 Size / Y：
地面基线：顶部83.5%（已有模板）
角色标尺：按模板叠加，禁止仅凭模型自行画人物定比例
左/右可走边界：
出生点与出口目标：
交互 ID 与锚点表：引用地图锚点.csv / 附新表
人物可活动区域、交谈站位：
静态烘焙物：
独立前景与遮挡意图：
动态道具：状态列表、pivot、锚点、去掉后补底
时段/天气及真正支持的调用方式：
主光方向 / 辅助光源：
交付版本与责任人：
美术检查记录 / Unity接入记录：分别填写
```

不要把空白制作单直接交给生成器自由决定出口、身高和地面。程序/关卡先提供功能布局，美术负责把布局转成符合风格的空间。

## 建议的文件包

```text
map_<id>_v001/
  brief.md                      制作单与变更说明
  background.png                干净运行底图，RGB，无人物/UI
  background_day.png            按需，保持相同几何布局
  foreground.png                按需，RGBA，同画布不裁边
  props/                        按需，独立状态与alpha
  layout.png                    带基线、镜头、角色标尺、锚点的标注图
  preview.png                   角色+UI+所有图层合成示意，只用于评审
  layout.json                   建议交接数据；当前Unity不自动读取
  coordinates.csv               坐标和ID，写清左上原点
  source/                       PSD/KRA等母版（建议保存，非硬性PSB）
  provenance.md                 模型/手绘/素材来源、日期、生成参数与授权情况
```

包名使用英文小写/下划线，版本明确；这是新交付约定。实际接入现有地图时，程序再映射到 `street.png` 等固定路径，不能直接把所有交付都叫 background.png 塞进同一个 Resources 目录。不要让美术复制或自行生成 Unity `.meta`；已有资源替换应保留原 GUID。

`templates/layout.template.json` 是可复制制作单模板，`templates/street.current.example.json` 是来自现有场景的真实示例。两者都只是文档交接格式，没有附带自动导入承诺。字段中的 null 必须在交付前填完；不需要的数组可留空，并在 brief 说明。

同目录三张 `*.guides.svg` 是现有地图的透明标注模板，画布1672×941，可作为layout的起点。保持与底图同画布和原点，不要缩放后再拿它校准原始锚点。

## 可复用风格前缀

```text
为海滨小镇日常叙事游戏制作场景美术。日系动画背景画质感，清楚可信的建筑和家具形体，克制细线与手绘色块，柔和渐变塑形，蓝紫冷影与局部金橙暖光，生活物件有使用理由。空间安静、清透、有人生活；材质可辨，远景低对比，角色活动区保持清楚。正面展开的横版舞台构图，允许少量桌面和地面可见的轻透视，水平行走方向不向消失点延伸。沿用给定参考的画法与光影逻辑，不复制全部物件。
```

必须搭配参考图与布局模板。不同地图允许天气、时段和主色温变化，不能只靠每次复制同一个文本种子实现一致性。

## 可复用地图生成模板

```text
[风格前缀]
地点：[地点及功能]。主识别物：[一处]；生活细节：[三到五类]。
光照：[时段/天气]，主光来自[方向]，辅助暖光来自[灯具]，所有影子一致。
使用所附布局图为严格几何约束：画布[宽×高]；水平脚底线在距顶部83.5%；底部16.5%为地台前缘；可走范围[范围]。画面与正交横版角色匹配，禁止改变布局图中的门窗和地面高度。
出口[ID]位于[u,v]；关键交互物[ID]位于[u,v]，u/v以左上原点归一化；角色站位仅供标尺，不出现在最终背景。
以[Street/Cafe/Lighthouse]的实际镜头框检查构图。重要物件与交互区不得被裁到画外。
输出一张干净无人的完整背景，地面和墙面补全，不带UI、文字、坐标线、边框、水印、光标或人物倒影。不会变化的装饰可画入底图；[动态物件列表]必须不画进底图，单独交透明PNG。
```

生成工具通常不能保证精确输出1672×941，也不能稳定遵守83.5%与锚点。因此流程应是“布局锁定→参考条件生成→美术修绘/裁切/重采样→模板复核”。不要把文字里写了坐标当作坐标已经正确。不同画幅应重新构图或合理扩画，不能非等比拉伸。

## 时段变体提示词

```text
以所附已确认底图为唯一结构底稿。保持所有建筑、门、窗、路面、栏杆、家具、植物盆位和交互锚点像素对齐，画布、透视、机位和脚底线完全不变。只把光照改为[时段/天气]：主光[方向与色温]，辅助光[开关状态]，远景空气感[要求]。不新增物件、不删物件、不改变开门方向。不要加入人物、UI或人物反射。若无法保持结构，保留原结构并交由美术分层改光。
```

提示词不是配准算法。用同画布叠图/差分检查门框、桌边和锚点；结构变化必须修回。雨线、雨粒子、湿地反射可以作为专门变体/效果层，但当前工程尚未自动调用 `_rain`。

## 新界面示意图提示词

```text
为同一海滨日常叙事游戏设计[页面名称]的1920×1080界面示意图，沿用参考场景的冷暖光和清透生活感。场景保持主要视觉，交互信息用深蓝半透明面板、细边框、柔和奶白字、克制的海蓝与暖金强调。使用工程现有UI样式表作为颜色/圆角/字号依据；内容层级为[主任务→次任务→补充信息]。
必须展示[内容清单]与[当前状态]。角色脸和关键手势保持无遮挡；当前背景为[晴日/夕阳/雨夜]。文字、图标与按钮在后期设计工具中作为独立图层排版，不把模型生成文字当作最终交付。附[默认/悬停/选中/禁用/空态等所需状态]。
```

这只是视觉示意图要求。不要在生成图里加入产品尚未确认的AI、语音、商业化、数值养成入口。需要新增功能时先在制作单注明“概念”，避免被误读为已实现。

## 统一负面约束

```text
避免：强广角、鱼眼、斜俯视主构图、等距地图、纵深主行走路、像素画、厚涂油画肌理、照片写实、塑料3D质感、重黑描边、荧光霓虹、大面积纯黑、全图过曝、所有物件发光、无来由的镜面反射、随机堆杂物、畸形门窗家具、重复花盆、人物/剪影/人物倒影、UI/文字/乱码/水印、动态物件烘焙入底图、灯光方向相互矛盾。
```

有些生成工具把负面文本当弱提示，最终仍需人工检查；布局或风格失败时优先修图/回到结构稿，不连续盲抽到“看起来差不多”。

## 建议首批试点与批量节奏

先做一张现有 Cafe 或 Street 的替换试点：保留现有ID、出生与镜头，输出底图与标注图；再加一件可变化道具、一小块真实透明前景，验证拆层/补底/排序链路。后两项需要程序接入，不能直接放图就自动工作。

试点通过后固定：参考样片、画法规则、模板尺寸、世界宽度、镜头、锚点、导入设置、文件命名、验收截图。随后按地点成组生产；同地点先通过一个时段，再做结构锁定的变体。每组以“场景＋角色标尺＋UI叠加＋实际取景”四张评审视图交付。

**职责**：关卡/程序给功能布局与技术参数；美术做视觉与可装配图层；整合者负责导入、排序、碰撞、路由和性能；最终体验/美术负责人分别签收。生成模型输出是候选资产，验收记录由实际检查产生。
