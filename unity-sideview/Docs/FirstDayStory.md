# Day0–1 · 开发草稿

2026-11-13，PR #62。以本说明替代旧版“12秒固定来信、八人固定介绍、客房片尾”的当前流程；旧版资产与历史验收记录保留，但不再作为本轮玩法。详细设计见 [方案](../Day0-Day1-开发计划与技术方案-草稿.md)。

## 运行

使用 Unity 6000.3.27f1 打开本工程和 `Assets/Seabreeze/Scenes/Street.unity`。先运行 `git lfs pull` 补齐模型，再启动已有 MemoryLab 与直播服务并配置模型；新游戏输入姓名，继续游戏沿用存档姓名。服务不可用时保留现场与进度，没有固定角色对白兜底。

## 当前流程

1. 姓名写入存档，贯通玩家身份、单聊情境与直播绑定。世界观视频1暂空。
2. 主 Agent 选择开场工具；直播主 Agent 自主主持千场直播、调用抽奖、提出七天邀请。仅虚拟观众。抽奖实际展示后才发布结果；玩家点击确认后才能调用出发。网络失败和重连不会代替玩家同意。
3. 码头自动开启 Z 的自然对话。NPC 主动开口、玩家实际回应、NPC承接且字幕完整展示后，玩家主动关闭才算完成一轮；关闭未完成窗口、换图与读档取消不计数。
4. 主 Agent 自然生成去广场的邀请，玩家确认后 Z 用已有移动执行器向右带路、距离过远时等待；玩家自主移动，经 Harbor、Street 到 Square。
5. 下午七人在场：Z、晴野、留洋、正义、李庭、阿星、周伯伯，无梨园。Z 实际展示介绍姓名的气泡后，其他角色才获知姓名。每人完整交谈一次；七人未完成时，地图和场景出口都不能离开。关系与自主交谈仍使用既有人设/决策系统。
6. 主 Agent 调用烟花剧情占位，返回广场迎新任务阶段。没有配置烟花视频，不写视频播放成功回执。
7. AI 从现场交谈／拍照能力生成一项1–3步委托，走既有任务卡的接受／拒绝。每局独立保存定义，实际发言或新照片才完成步骤；只需完成一项。旧照片、错误对象、未接受、重复回执与读档隔离有接口测试。
8. 主 Agent 开启首夜直播前，手机弹出，直播按钮持续高亮并震动1秒。主播自然介绍新朋友、回忆实际公开经历、按意愿调用现有唱歌工具；六位居民可参与，梨园不参与。首日两场直播没有固定节目节拍。
9. 首夜结束真实回执将首日标为完成并进入第2天。此后休息／喝咖啡计数0→4，第四次等待直播；普通行走、阅读、聊天不消耗。直播结束才增加日期并清零计数，重复回执不重复切天。

## 状态与恢复

首日枚举保留旧值，新阶段追加，旧完成档不会重开引导。旧客房／就寝档迁移到迎新任务阶段。生成请求带运行和阶段版本，读档、重开或会话替换后拒绝迟到结果。任务定义和实际回执保存在原有 checkpoint。开场／首夜／日常直播使用不同的存档、日期、模式绑定。

`FirstDayDirector`持有阶段事实和可用工具，不写角色台词；MemoryLab 的`FirstDayAgent`使用现有人设及模型提供方选择工具并生成任务；`LiveScene`校验抽奖、邀请、实际确认和转场顺序。主 Agent 不能直接伪造任务完成。

## 验证

- `npm test`（Tools/MemoryLab）：105项通过。
- `npm test`（Tools/live-service）：143项通过。
- Unity `Seabreeze.Editor.FirstDayRuntimeVerification.Run`：17项状态/存档检查通过，独立临时存档。
- Unity `Seabreeze.Editor.FirstDayPlayVerification.Run`：17项 Play Mode 检查通过（最终回归使用无图形批处理，之前已检查可视截图）；覆盖窗口、走图、NPC移动、区域限制、姓名气泡、任务卡、手机提示和日循环；模型台词及直播完成为测试注入，不能称为真实模型全通关。需设置独立 `/private/tmp/` 下的 `Z_MEMORY_SAVE_ROOT`，并用 `-memoryService` 选择隔离服务地址。
- 经用户授权实测既有 DeepSeek：四种主 Agent 场景决策、实时迎新任务生成和自然开场主持／虚拟弹幕成功；连续真实主持与审阅完成抽奖→邀请→确认后出发，展示/确认回执为测试注入。结果保存在本机临时目录，凭据与真实存档未提交。

编辑器另有 UnityEditor.Search 索引启动异常，单列为编辑器告警；最终回归没有游戏运行时异常。批处理不会产生帧末渲染回调，手机毛玻璃在该模式保留底色以免阻塞交互，正常运行仍使用场景截图。

尚需用户本地检查不中断的完整 AI＋语音＋歌曲体验、中文输入法候选提交和手感；本轮未声称这些全部通过。草稿待用户确认，未合入 main。
